# Google Analytics 4 — 속성 만들기·방침에 맞춘 설정·켜고 끄기·삭제 요청 (스펙 075, 사람용)

랜딩(`/`)과 대시보드(`/app/`)의 방문 통계를 GA4 로 본다. Clarity 와 **같은 동의**다 — 동의 창이나 처리방침의 동의 관리(`/privacy#consent`)에서 세 칸에 모두 동의해 저장한 방문자만 Google 태그를 받고, 동의 전에는 Google 요청이 하나도 없다. 레포 쪽 설정은 `web/public/clarity.js` 머리의 GA 측정 ID 하나이고, 나머지는 GA 관리 화면에서 사람이 한다. **아래 2절의 값은 처리방침 v9 가 사실로 적는 값이다 — 바꾸면 방침도 고친다.**

## 1. 켜는 순서
1. 처리방침 v9(075 — Google Analytics 를 알리는 판)가 게시돼 있다(2026-10-17 머지).
2. 아래 2절로 속성을 만들고 측정 ID(`G-…`)를 받는다 — 지금 속성의 ID 는 `G-RJ732XDRKM`.
3. ID 를 `clarity.js` 의 `GA_ID` 에 넣는 PR 을 머지·배포한다 — **이 머지가 곧 켜기다.** 판은 올리지 않는다(방침 글이 그대로라 동의 창이 다시 뜨지 않는다). 2절 설정을 먼저 끝낸다 — 방침이 그 값을 사실로 적는다.
4. 배포 뒤 3절로 확인한다.

## 2. 속성 만들기와 설정 (analytics.google.com → 관리)
- **만들기 → 속성**: 속성 이름 KimpTrack, 시간대 대한민국, 통화 KRW. 업종·규모는 아무거나, 목표는 '트래픽 이해'.
- **데이터 스트림 → 웹**: URL `https://kimptrack.com`, 스트림 이름 KimpTrack. 여기 나오는 **측정 ID** 가 레포에 넣을 값이다(공개 값 — 페이지 소스에 보인다). '태그 설치 안내' 의 코드는 붙이지 않는다 — 레포의 `clarity.js` 가 동의한 방문자에게만 부른다.
- **향상된 측정**(스트림 안 톱니): 페이지 조회·스크롤·이탈 클릭만 켠다. 페이지 조회의 고급 설정에서 **'브라우저 기록 이벤트 기반 페이지 변경' 은 끈다** — 켜 두면 대시보드 주소의 쿼리가 그대로 Google 로 간다. **양식 상호작용·사이트 검색·동영상 참여·파일 다운로드는 끈다.**
- **데이터 수집 및 수정 → 데이터 수집**: Google 신호 데이터 **끔**. '광고 개인화를 위한 데이터 수집' → 모든 지역 **끔**. 세분화된 위치·기기 데이터 수집은 기본(켬).
- **데이터 수집 및 수정 → 데이터 보관**: 이벤트 데이터 보관 **2개월**, '새 활동 시 사용자 데이터 재설정' 켬.
- **계정 설정 → 계정 세부정보 → 데이터 공유 설정**: Google 제품 및 서비스, 모델링 기여 및 비즈니스 통계, 기술 지원, 비즈니스 추천(전문가 상담) — **모두 끔**.
- **데이터 스트림 → 태그 설정 → 내부 트래픽 정의**(선택): 운영자 집·사무실 IP 를 `internal` 로 정하고, 데이터 필터의 '내부 트래픽' 을 '활성' 으로 바꾼다.
- Google Ads 연결은 하지 않는다(075 범위 밖 — 광고 신호를 거부로 보내므로 연결해도 전환이 거의 안 잡힌다).

## 3. 켠 뒤 확인
1. 새 크롬 프로필로 `https://kimptrack.com` — 동의 창이 뜨고, 개발자 도구 네트워크에 `googletagmanager.com`·`google-analytics.com` 요청이 0건이다.
2. 세 칸 모두 체크하고 [선택한 대로 저장] — `www.googletagmanager.com/gtag/js?id=G-…` 와 `…google-analytics.com/g/collect` 요청이 생기고, 쿠키 `_ga`·`_ga_<기호>`(도메인 `.kimptrack.com`, 만료 약 2개월 뒤)가 생긴다. `g/collect` 요청의 `dl`(페이지 주소)에 `?`·`#` 뒤가 없고, `gcs` 값이 `G101`(광고 거부·분석 허용) 꼴이다.
   - 이어서 `https://kimptrack.com/?q=test` 로 들어가면 Google 요청이 0건이다(검색어 꼴 쿼리가 있는 주소에서는 `clarity.js` 가 GA 를 부르지 않는다 — Clarity 요청은 있다).
3. GA → 보고서 → 실시간에 1명이 보인다.
4. `/privacy#consent` 에서 [동의 철회] → `_ga` 쿠키가 지워지고, 다음 페이지부터 Google 요청이 0건이다.
5. GPC 를 보내는 브라우저(Brave)·[모두 거부]·`www.kimptrack.com` 에서는 Google 요청이 0건이다.

## 4. 끄기
`clarity.js` 의 GA 측정 ID 를 빈 문자열로 바꾸는 PR 을 머지·배포한다(`test_clarity.py` 의 `test_the_repo_file_loads_its_ga_id_for_agreed_visitors` 도 '빈 ID' 단언으로 바꾼다). 다음 페이지 로드부터 아무도 태그를 받지 않는다(파일은 no-cache). 오래 끌 생각이면 방침에서 Google Analytics 를 빼는 PR 도 따로 낸다.

## 5. 삭제 요청이 왔을 때 (방침 8절)
- GA 기록은 이름·연락처가 없어 한 사람분을 찾기 어렵다. 요청자가 `_ga` 쿠키 값을 알려 주면 GA → 탐색 → 사용자 탐색기에서 그 클라이언트 ID 를 찾아 **사용자 삭제** 를 누른다.
- 찾을 수 없으면 관리 → 데이터 수집 및 수정 → **데이터 삭제 요청** 으로 그 기간의 기록을 지운다(모든 방문자의 그 기간 기록이 함께 지워진다). 지우는 시점은 Google 기준이다 — 요청을 만든 뒤 바로 취소할 수 있는 기간이 지나야 시작된다.
- 처리한 날과 방법을 답장에 적는다.
