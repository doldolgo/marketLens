# execute-spec.md — 실행 세션 프롬프트

새 Claude Code 세션을 `<repo>` 에서 열고 아래를 붙여넣는다. `NNN` 만 바꾼다.

```
다음 순서로만 읽어라:
1. CLAUDE.md
2. docs/context/product.md, architecture.md, dev-setup.md, conventions.md, status.md
3. docs/specs/NNN-*.md  (이 스펙 하나만)

그 다음 스펙을 구현하라. 규칙:
- 스펙 §2(범위) 밖의 기능·파일은 건드리지 않는다. 범위 안의 구조(파일·클래스)는 CLAUDE.md §2 규약 안에서 자유.
- 스스로 정해도 되는 것과 멈추고 물어야 하는 것의 기준은 CLAUDE.md §3 "스펙 크기 규칙" 을 따른다. 묻는 것(공유 모듈·저장 모양·응답 키·라이브러리·트레이드오프·스펙에 없는 동작)은 선택지 2~3개 + 장단 + 추천 1개로 묻고, 답을 받으면 코드보다 먼저 스펙의 해당 절에 합의한 문구로 적은 뒤 이어간다. 기능 폴더 안에만 영향 있는 구조는 묻지 않고 정하되 §7(실행 보고)에 적는다.
- 이 레포 밖의 코드는 읽지 않는다. 막히면 추측하고 §7(실행 보고)에 적는다.
- 테스트는 스펙 §4(검증)의 목록을 보고 직접 쓴다.
- 스펙 §5(완료 기준) 명령을 실제로 실행해 통과를 확인한 뒤에만 완료라고 말한다. 출력을 보고서에 붙인다.
- 완료 조건: docs/context/conventions.md §스펙 완료 조건 5개 전부.
- 커밋은 하되 push 는 하지 않는다.
끝나면 §7(실행 보고) 내용을 그대로 출력하라.
```

## 실행 후 설계 세션에서 할 일
1. §7(실행 보고)의 "추측한 지점" 을 읽는다. 실행 중 함께 고친 스펙 문구가 코드와 맞는지 확인하고, 같은 종류의 빈틈이 다음 스펙에도 있으면 미리 채운다.
2. 결함이 구현을 틀리게 만들었다면 → 새 스펙(fix)으로 처리.
3. `docs/context/status.md` 가 실제와 맞는지 한 번 본다.
