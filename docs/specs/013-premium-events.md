## 1. 목적
"어느 코인이 언제부터 언제까지 김프(역프)였나"를 **저장 시점에 사건 단위로 감지해 1건 1행으로 남기고**, 기록 탭은 그 표를 읽기만 한다. 지금은 `/history/streaks` 가 요청마다 초 단위 원본을 전부 읽어 구간을 다시 계산하므로 전 코인 조회(`bulk`)는 6시간 창에서도 Influx 를 죽인다(2026-09-07 실측). 끝나면 기록 탭에 심볼을 치지 않아도 김프/역프 서브탭별로 전 코인 1주·1달·3달 사건 표가 즉시 뜨고(진행 중인 코인이 표시된다), 행을 고르면 그 코인의 사건 로그·타임라인이 보인다.

## 2. 범위
- 만드는 것: 사건 감지기(core — 틱 루프가 매초 부른다), Influx measurement `premium_event` 쓰기·60초 갱신·기동 시 복원, `GET /history/events`(`server/app/features/history/`), 기록 탭 화면(`web/src/features/history/` — 티커별 표·요약·타임라인·사건 로그를 이 API 로).
- 하지 않는 것: 지난 기록의 사건 일괄 생성(배포 시점부터 쌓인다 — 과거분은 `premium` 원본을 코인별로 나눠 도는 별도 스펙). 기준값 조정 UI(기준은 고정, §3.2). `/history/streaks`·`bulk`·`/premium` 변경(그대로 남고 화면은 안 쓴다). 사건 클릭 → 그 구간 차트(후속 014 — 코인 1개 × 사건 구간의 `premium` 조회는 가벼워 임의 구간 조회 엔드포인트 하나면 된다, 롤업 불필요). 알림.
- 바꾸는 기존 것:

  2. 005 §3.6 기록 탭 — `/history/streaks` 사건 로그를 이 스펙의 화면으로 교체. 005 §2 의 "후속 스펙" 문구와 §7 남은 빚을 이 스펙으로 돌린다. 005 의 `features/history/api.ts`·`types.ts` 는 이 API 용으로 다시 쓴다.

## 3. 동작

### 3.1 읽는 계약 (복사)
- 001·009: 틱은 1초 주기. 틱 `rows` 의 행 = `(dom, fx, base, fwd, rev)`, `dom ∈ {upbit, bithumb}`, `fx ∈ {binance, bybit, bitget}`(020), `fwd`·`rev` 는 **슬리피지 차감 전 원값 %**(005 §3.3). 국내 거래소의 USDT 시세가 없거나 호가가 없으면 그 조합은 그 틱에 **없다**. 틱 시각 `ts` 는 epoch 초.
- 005: `fwd`(kimp) 는 해외 매수→국내 매도 방향, `rev`(reverse) 는 국내 매수→해외 매도 방향. 둘 다 양수일 때 그 방향의 프리미엄이 있다. `/history/*` 오류 계약 — 503 `storage_unavailable`(Influx 불달·`INFLUX_TOKEN` 없음), 400 `invalid_request`(`end ≤ start`), 422(파라미터 검증). `start`·`end` 는 0 ≤ 값 ≤ 4,102,444,800, `start` 없으면 `end − 7일`, `end` 없으면 지금+1초. HTTP JSON 키는 camelCase.
- 011: 구간을 메모리에서 열고 닫으며 Influx 에 **열림·닫힘 시 1점**(같은 tag·time 으로 덮어써 field 를 합친다 — Influx 2.x 는 같은 key 재쓰기 시 field 합집합·새 값 우선). 기동 시 복원은 틱 루프 시작 **전**, 3초 상한, 실패하면 빈 상태로 시작하고 경고 1줄. 쓰기 실패는 로그 후 무시하되 순서를 보장한다.
- 002/003: 셸의 1.5초 `now`, 탭은 숨김만, 스프레드 행 클릭 → 선택 심볼 + 기록 탭 전환(초기 `'BTC'`). 거래소 표시명 `upbit→업비트` `bithumb→빗썸`.

### 3.2 사건 규칙 — 틱이 판정한다
사건은 조합 `(dom, fx, base, dir)` 마다 따로 본다. `dir ∈ {kimp, reverse}`, 값 = `dir` 가 `kimp` 면 `fwd`, `reverse` 면 `rev`. 기준은 고정이다:

| 이름 | 값 |
|---|---|
| 진입 | 1.0 |
| 종료 | 0.5 |
| 최소지속 | 60 |
| 결측허용 | 600 |

- **열기**: 열린 사건이 없는 조합의 값이 진입(1.0%) **이상**이면 그 틱 `ts` 에 연다. `max_percent`·`max_ts` 는 그 값·시각, `samples`=1.
- **유지**: 열린 사건의 값이 종료(0.5%) **초과**이면 이어진다 — 0.5 와 1.0 사이도 이어진다(히스테리시스: 기준선 근처 들락날락을 한 사건으로). `max_percent`·`max_ts` 갱신, `samples`+1, `last_ts`=틱 `ts`.
- **닫기**: 값이 종료(0.5%) **이하**가 된 첫 틱 `ts` 가 `end_ts`. `duration = end_ts − start_ts`.
- **버리기**: `duration ≤ 60` 이면 없던 것으로 한다(Influx 에 쓰지 않고, 열 때 쓴 점이 있으면 지운다 — §3.3). 1분을 못 넘긴 스파이크는 사건이 아니다.
- **결측**: 틱에 그 조합 행이 없으면 값이 없는 것이다(0 이 아니다). 마지막 관측 `last_ts` 로부터 600초 안에 행이 돌아오면 이어지고, 600초를 넘기면 `end_ts = last_ts` 로 닫는다(관측 못 한 시간은 사건에 넣지 않는다). 닫힌 뒤 돌아온 값이 1.0 이상이면 새 사건이다.
- 두 방향은 독립이다(같은 조합에 kimp·reverse 사건이 동시에 열릴 수는 없지만 — 둘 다 양수일 수 없다 — 규칙은 각각 적용한다).
- 메모리에 드는 것은 **열린 사건**뿐(조합 수(≈1,458) × 2 이하). 닫힌 사건은 Influx 가 진실이다.
- **판정 경로 규칙(2026-09-28).** 행의 두 값(fwd·rev)이 모두 진입 미만이고 그 조합에 열린 사건이 없으면 키를 만들지 않고 넘어간다 — 그런 행은 열 것도, 이어 가거나 닫을 것도 없어 어떤 상태도 바꾸지 않는다(값이 NaN 이면 비교가 거짓이라 판정으로 간다). 결측 닫힘은 "마지막 관측 뒤 600초 초과" 하나로 가른다 — 이번 틱에 행이 있던 사건은 `last_ts` 가 그 틱이 되거나 닫혀 빠지므로 "이번 틱에 본 조합" 을 따로 모으지 않는다. 틱에는 조합당 행이 하나다(001 §3.6). 운영 표에서 할 일이 있는 조합은 약 8% 라 틱마다 2,916개 키를 만들 이유가 없다.

### 3.3 Influx `premium_event` — 쓰기·갱신·복원
- measurement `premium_event`. tag `dom`·`fx`·`base`·`dir`, time = `start_ts`(초). field `end_ts`(int 초, **진행 중이면 0**)·`duration_seconds`(int, 진행 중 0)·`max_percent`(float)·`max_ts`(int 초)·`last_ts`(int 초)·`samples`(int)·`enter_percent`(float 1.0)·`exit_percent`(float 0.5)·`net_dom`·`net_fx`(string, `-` = 없음 — 024). 한 사건 = 점 1개, 유일키 = (dom, fx, base, dir, start_ts). 망 이름 2개는 **사건이 열리는 틱 행**의 값이고, 60초 갱신·닫힘 때마다 **그 시점 틱 행의 값으로 덮어쓴다**(진행 중이면 "지금 옮길 망", 닫히면 "닫힐 때 망" — 이력은 남기지 않는다). 복원도 두 필드를 그대로 읽는다. 배포 전 점(필드 없음)과 옛 점의 빈 문자열은 읽을 때 `null`. 기준값을 점에 같이 남기는 것은 나중에 기준이 바뀌어도 과거 사건의 의미가 남게 하기 위해서다.
- 쓰는 시점 세 가지 — 매초 쓰지 않는다:
  1. **열린 지 60초를 넘긴 순간** 1점(그 전엔 메모리에만 — 1분 못 넘기고 닫히는 사건은 Influx 를 건드리지 않는다).
  2. 열린 채로 있는 동안 **60초마다** 같은 키로 덮어써 `max_percent`·`max_ts`·`last_ts`·`samples` 를 갱신한다(재기동 복원의 정확도를 위해 — §복원).
  3. **닫힐 때** 같은 키로 `end_ts`·`duration_seconds`·최종값을 쓴다.
- 버리기(§3.2)는 열린 지 60초 전에만 일어나므로 지울 점이 없다 — `duration ≤ 60` 인 사건은 60초 갱신 시점(1)에도 도달하지 못한다. 단 결측으로 닫혀 `end_ts = last_ts` 가 되면 `duration` 이 60 이하로 줄 수 있다(예: 열리고 30초 관측 뒤 끊김). 그 경우 이미 쓴 점을 `end_ts`·`duration_seconds` 를 채워 닫되 응답에서는 `duration ≤ 60` 을 빼지 않는다 — 관측한 만큼은 사실이므로 남긴다. **버리기는 관측 중 닫힌 사건에만 적용한다.**
- 쓰기 실패는 로그 1줄 후 **다음 60초 회차에 재시도**한다(열림·갱신·닫힘 모두 같은 키 덮어쓰기라 재시도가 안전하다). 닫힌 사건의 미전송분은 메모리 재시도 목록에 두고 회차마다 보낸다(상한 1,000건, 넘치면 오래된 것부터 버리고 쓰기를 시도하는 회차가 버린 수를 1줄로 알린다). **실패한 뒤 60초가 지나기 전에는 새 사건이 열리거나 닫혀도 다시 쓰지 않는다** — Influx 쓰기 1회는 동기이고 타임아웃이 60초라, 불통 중에 사건마다 즉시 재시도하면 실패 호출이 쓰기 스레드를 연달아 막아 복구 뒤에도 밀린 쓰기가 한참 이어진다. 60초 안의 지연은 화면(60초 재조회)이 어차피 못 본다.
- **기동 시 복원**(틱 루프 시작 전): 열린 사건을 **Redis 사본(아래)에서 먼저** 읽고, 키가 없거나 읽기·해석이 실패하면 Influx 에서 `start_ts` 가 최근 7일이고 `end_ts == 0` 인 점을 읽는다(2026-09-28 사람 결정). 사본이 있으면 Influx 는 읽지 않는다 — 7일 사건 전부를 pivot 하는 조회는 운영에서 3초 상한을 넘겨(2026-09-28 재기동 13번 모두), 배포마다 진행 중 사건 ≈144건이 끊겨 새로 열린다. 상한은 원천마다 3초이고 둘 다 못 읽으면 빈 상태로 시작하고 경고 1줄. 어느 원천이든 규칙은 같다: `지금 − last_ts > 600` 이면 `end_ts = last_ts` 로 닫아 쓰고(재기동마다 다시 열리지 않게 — 복원 안에서 동기로 쓰지 않는 것은 쓰기 1회가 최대 60초라 3초 상한이 무의미해지기 때문이고, 쓰기 태스크가 복원 직후 시작하므로 실제 지연은 수 초다), 아니면 진행 중으로 메모리에 올려 첫 틱부터 이어 본다. 600초를 재기동에도 쓰는 이유: 서버가 죽어 있던 시간은 감지기에게 "행을 못 본 시간" 과 같다 — 결측과 다른 숫자를 두면 같은 사건이 죽었다 켜졌는지 스트림이 끊겼는지에 따라 다르게 판정된다. 같은 조합에 진행 중이 둘 이상이면 `start_ts` 가 가장 늦은 것만 살리고 나머지는 `end_ts = last_ts` 로 닫아 쓴다. 사본도 Influx 도 못 읽으면(`INFLUX_TOKEN` 없음·불달) 빈 상태로 시작하고 경고 1줄 — 감지는 계속하되 쓰기만 실패로 남는다.
- **복원이 닫은 점**은 미전송 맵이 아닌 따로 모은 목록에 두고, 첫 쓰기 회차가 미전송 점보다 먼저 **상한 없이 전부** 한 번에 쓴다(실패하면 다음 회차에 그대로). 미전송 맵에 넣으면 쌓인 고아 점 수천 건이 상한 1,000 에 걸려 버려지고 건마다 경고가 찍힌다.
- **Influx 복원 조회는 두 단계다(2026-09-28 사람 결정).** 1단계는 `end_ts` 필드만 읽어 값이 0 인 (dom, fx, base, dir, 시각) 을 찾고, 2단계는 그 코인만 정규식으로 좁혀(메타문자와 정규식 끝 `/` 는 이스케이프) pivot 한 뒤 1단계 키에 든 행만 남긴다. **두 단계 모두 7일 창**이다 — 2단계 창을 좁히면 옛 점의 빈 문자열 망 이름이 창에 따라 다른 점으로 밀려 읽혀(024 §3.4) 결과가 달라진다. 결과는 헤더 있는 CSV 로 읽는다. core 공개 함수 `InfluxClient.query_ongoing_events(*, start: int, stop: int, timeout_sec: float | None = None) -> list[PremiumEventRow]` 이고, 복원은 요청마다 HTTP 타임아웃을 상한과 같은 3초로 걸어 상한을 넘기면 스레드와 Influx 조회가 함께 끝난다.
- **열린 사건 사본(2026-09-28 사람 결정).** 닫힌 사건은 Influx 가 진실이고 이것은 복원용 사본이다. Redis 키 `premium_events:open`, 값은 열린 사건 전체를 담은 JSON 배열 하나(사건마다 `dom fx base dir start_ts max_percent max_ts last_ts samples net_dom net_fx written` — 열린 지 60초 전인 사건도 든다), TTL 600초(다음 저장이 덮는다). TTL 은 결측 허용과 같은 값이다 — 60초마다·종료 때 저장하므로 보통의 재기동은 늘 사본을 찾고, 수집이 10분 넘게 멈췄거나 옛 코드로 되돌렸다 온 기동은 옛 코드가 그동안 Influx 에 쓴 사건을 낡은 사본이 덮지 않게 Influx 로 복원한다(되돌림이 10분 안이면 사본을 쓴다 — 되돌렸다 다시 배포할 때는 배포 전에 키를 지운다). 60초 갱신(쓰는 시점 2)과 같은 틱에 틱 루프는 직렬화만 하고 저장은 쓰기 태스크가 한다 — 가장 최근 사본 하나만, 저장은 한 번에 하나(옛 사본이 새 사본을 덮지 않게), 실패는 경고 1줄 후 버린다(다음 갱신이나 닫힘 회차가 새 사본을 만든다). 열린 사건 ≈255건이면 ≈55KB, 직렬화 0.2ms·되살리기 0.3ms(로컬).
- **닫힘 회차 사본(2026-09-28 사람 결정).** 사건이 닫히면(1분을 못 넘겨 버린 스파이크 포함) 60초 갱신을 기다리지 않고, 그 닫힘 점을 Influx 에 다 쓴 쓰기 회차(쓸 점이 없는 스파이크는 다음 쓰기 회차)가 지금 열린 사건으로 사본을 다시 만들어 저장한다 — 닫힌 사건이 사본에 남은 채 비정상 종료되면 600초 안의 재기동 복원이 그 사건을 다시 열어 Influx 의 올바른 닫힘 점을 덮고, 버린 스파이크는 되살아나 사건으로 남는다. 닫힘 쓰기가 먼저, 사본이 다음이다 — 닫힘 점 쓰기가 실패한 회차는 사본을 다시 만들지 않는다(사본이 먼저면 그 사이 종료에 Influx 의 진행 중 점이 고아로 남는다). 직렬화는 쓰기 태스크가 루프 안에서 한다(틱과 겹치지 않는다). 사본 저장 실패는 60초 갱신과 같이 경고 1줄이다. 60초 갱신 사본은 닫힘 쓰기를 기다리지 않는다 — Influx 쓰기가 실패하는 동안 닫힌 사건은 그 사본에서 빠지고, 그 사이 비정상 종료되면 진행 중 점이 고아로 남아 §3.4 고아 점 규칙이 받는다(status.md 알려진 빚).
- **종료**: 쓰기 태스크를 멈추기 전에 지금 열린 사건의 사본 저장 1회와 미전송 점 쓰기 1회(60초 실패 대기 무시)를 한다. 사본이 먼저다 — 다음 기동이 읽는 것이 사본이라서다. 둘 합쳐 3초 상한, 넘기면 경고 1줄(Influx 불통이 종료를 붙들지 않게) — 못 쓴 점은 다음 기동 복원의 600초 규칙과 §3.4 고아 점 규칙이 메운다. 비정상 종료면 사본은 마지막 60초 갱신이나 닫힘 회차 때 것이다 — 닫힌 사건이 사본으로 다시 열리는 틈은 닫힘 쓰기와 사본 저장 사이(수십 ms)와 사본 저장 실패뿐이다(status.md 알려진 빚).

### 3.4 `GET /history/events`
Influx 의 닫힌 사건 + 메모리의 진행 중 사건. 거래소 호출 0회. 같은 키가 양쪽에 있으면 메모리가 이긴다(60초 갱신 사이의 최신값). Influx 에 `end_ts == 0` 인데 메모리에 없는 **고아 점**(기동 시 Influx 불통으로 복원을 못 했거나, 죽어 있는 동안 아무도 안 닫은 사건)은 `endTs = last_ts`·`durationSeconds = last_ts − start_ts` 로 **닫힌 사건처럼** 싣는다 — 복원 규칙(§3.3)과 같은 판정이라 복원 전·후의 화면이 같고, 응답에서 빼면 실제 있었던 사건이 사라져 횟수·점유율이 틀리며, 진행 중으로 내면 끝난 사건이 영원히 `진행 중` 으로 남는다.
`?start&end&dom&dir&base` — 전부 선택. `start`/`end` 규칙은 §3.1 복사값(`end − 7일` / 지금+1초, `end ≤ start` 400). `dom` 없으면 두 국내 거래소 다, `dir` 없으면 두 방향 다, `base` 는 `^[A-Za-z0-9]{1,20}$`(대문자 정규화). 구간 판정은 **`start_ts` 기준** — `start ≤ start_ts < end` 인 사건만(구간 전에 시작해 구간 안에서 끝난 사건은 빠진다 — 단순함을 택했다). 진행 중 사건은 `start_ts` 가 구간 안이고 **열린 지 60초를 넘긴 것만** 싣는다.
```json
{
  "startTs": 1788160000, "endTs": 1788764800, "count": 2, "fetchedAt": 1788764800123,
  "events": [
    {"base": "SOPH", "dom": "upbit", "fx": "binance", "dir": "kimp",
     "startTs": 1788760000, "endTs": null, "durationSeconds": 4800, "ongoing": true,
     "maxPercent": 2.31, "maxTs": 1788761200, "samples": 4790, "netDom": "Ethereum", "netFx": "ERC20"},
    {"base": "BONK", "dom": "bithumb", "fx": "binance", "dir": "reverse",
     "startTs": 1788700000, "endTs": 1788700900, "durationSeconds": 900, "ongoing": false,
     "maxPercent": 1.42, "maxTs": 1788700300, "samples": 899, "netDom": null, "netFx": null}
  ]
}
```
- 진행 중은 `endTs null`·`ongoing true`·`durationSeconds = 지금 − startTs`. 닫힌 사건은 저장값 그대로. `netDom`·`netFx` 는 진행 중이면 메모리 값, 닫힌 사건은 저장값, 배포 전 점은 `null`(024).
- 정렬 `startTs` 내림차순, 같으면 `base`·`dom`·`fx`·`dir` 오름차순 — 저장소가 주는 순서에 기대지 않는다. 기록 없으면 404 가 아니라 빈 `events`(bulk 와 같다 — 전 코인 조회는 "없음" 이 정상 상태다).
- 오류: 503 `storage_unavailable`(Influx 불달·토큰 없음 — 진행 중 사건만으로 200 을 만들지 않는다, 반쪽 답을 주지 않기 위해), 400·422 는 §3.1.
- 응답 크기 감: 운영 7일 창 김프 약 0.9MB(gzip 0.13MB)·역프 약 12.7MB(gzip 1.8MB), 1건 ≈ 230B.
- **사건 목록 조회(2026-09-28 사람 결정)**: 응답에 싣는 필드(`end_ts`·`last_ts`·`max_percent`·`max_ts`·`samples`·`net_dom`·`net_fx`)만 pivot 하고 group·sort 없이 헤더 CSV 로 읽는다 — core `InfluxClient.query_premium_events(*, start: int, stop: int, dom: str | None = None, dir: str | None = None, base: str | None = None) -> list[EventListRow]`, 순서 없음. `durationSeconds` 는 저장값을 읽지 않고 `endTs − startTs` 로 센다(닫힌 점의 저장값과 같다). 이 조회는 `/history/events` 전용이다 — 기동 복원은 §3.3 의 두 단계 조회, 랜딩은 022 의 요약 조회를 쓴다. 이유: 11필드 전체를 pivot·group·sort 하고 레코드 객체로 파싱하면 7일 전 코인 조회·빌드 시간의 절반가량이 거기에 든다(§7).
- **인코딩(2026-09-28)**: 005 §3.4 대로 조회부터 JSON 바이트까지 스레드에서 한다. 사건마다 모델을 만들지 않고 camelCase dict 로 만들어 **2,000건씩** 인코딩해 이어 붙인다 — 모델로 만든 응답과 같은 바이트다. 진행 중 사건은 틱 루프가 제자리에서 고치므로 루프에서 사본을 떠 스레드에 넘긴다.
- **공유 캐시(2026-09-28 사람 결정)**: 조회 키 `(dir, dom, base, start, end)`(요청 인자 그대로, `base` 는 대문자)마다 원본 바이트와 gzip(레벨 6) 바이트를 **60초** 들고 준다 — 목록은 최대 60초 늦고, 진행 중 사건의 `durationSeconds`·`maxPercent` 는 캐시를 만든 시각 기준이다. 비었거나 만료된 키에 요청이 몰리면 조회 하나를 같이 기다리고, 오류는 담지 않는다. 만료된 키는 새 키를 채울 때 버리고, 담은 응답의 합(원본 + gzip)이 **64MB** 를 넘으면 가장 오래 안 쓴 키부터 버린다 — 혼자 64MB 를 넘는 응답(역프 1달 이상 전 코인)은 담지 않는다(수집 박스 메모리 2GB 를 캐시가 잠식하지 않게 둔 보수값). `Accept-Encoding` 에 `gzip` 이 있으면 미리 압축한 바이트를 `Content-Encoding: gzip`·`Vary: Accept-Encoding` 과 함께, 없으면 원본 바이트를 준다. 웹이 같은 분에 같은 URL 을 부르므로(§3.5) 대시보드 접속자 N명이 조건 조합마다 분당 한 번의 조회·빌드·압축을 나눠 쓴다 — 역프 7일은 한 번에 수집 박스 CPU 약 1초라, 접속자 수에 비례하면 코어가 찼다.

### 3.5 web — 기록 탭
화면 순서는 위에서부터 **표 설정(방향 서브탭·필터바) → 티커별 표 + 선택 심볼 요약·로그 → 차트 툴바 → 차트**. 표 설정과 차트 설정은 서로 독립이다 — 한쪽을 바꿔도 다른 쪽은 그대로(방향 서브탭만 둘 다에 걸린다). 표·요약·로그의 데이터는 `GET /history/events` 전 코인 조회. **방향 서브탭·기간·거래소**가 바뀔 때 1회 조회(디바운스 400ms·진행 중 요청 취소, 005 §3.6 방식), 그리고 **기록 탭이 보이는 동안**(기록 탭이 활성이고 브라우저 탭이 보일 때) **60초마다** 같은 조건으로 다시 불러 진행 중 사건의 지속·최대값을 갱신한다. 심볼 선택은 클라이언트에서 거른다. 항상 `start`·`end`·`dir` 를 붙인다 — `end` 는 지금을 60초 경계로 올린 값(`ceil(지금 / 60) × 60`), `start` 는 `end − 기간`(차트 음영은 청크 시작). 같은 분에 같은 조건을 보는 접속자는 같은 URL 을 불러 서버의 60초 공유 캐시(§3.4)가 맞는다. 다른 탭을 보거나 브라우저 탭이 가려지면 60초 재조회를 멈추고 받은 결과는 그대로 둔다 — 7일 사건이 김프 약 0.9MB·역프 약 12.7MB 라, 보지 않는 접속자까지 매분 부르면 collect 박스 CPU 와 전송이 대시보드 접속자 수에 비례한다. 다시 보이게 되면 마지막 조회가 60초보다 오래됐을 때만 곧바로 1회 부르고, 아니면 마지막 조회로부터 60초가 될 때 부른다(그동안은 직전 표가 보인다). 조건이 바뀔 때의 1회 조회는 보이는지와 무관하다.
- 방향 서브탭: 탭 맨 위에 `김프 | 역프`(기본 김프) → `dir=kimp|reverse`. 한 화면은 한 방향만 보여준다 — 한 코인에 김프·역프를 나란히 적지 않는다. 서브탭 색은 김프 = POS 색, 역프 = NEG 색(스프레드 탭 관례).
- 필터바: 기간 `1시간/4시간/8시간/12시간/24시간/3일/1주/1달/3달`(기본 1주, 차트의 봉 종류와는 별개), 국내 거래소 `전체/업비트/빗썸`(전체 = `dom` 생략), 해외 거래소 `전체/Binance/Bybit/Bitget`(API 에 `fx` 파라미터가 없으므로 응답을 클라이언트에서 사건의 `fx` 로 거른다 — 표·요약·로그에 걸린다). 세그먼트 앞에 `기간`·`국내`·`해외` 소제목(차트 툴바와 같은 모양). 차트 음영은 이 필터를 따르지 않는다 — 선택 심볼만 `base` 로, 차트가 보여주는 범위(가장 오래된 청크 시작 ~ 지금을 60초 경계로 올린 시각)를 `start`·`end` 로 따로 조회하고(보이는 동안 60초 재조회 같음) 차트 툴바의 국내·해외 선택으로 거른다. 음영은 사건 구간 [startTs, endTs)(진행 중은 끝없음)이 봉 구간 [ts, ts + 봉 길이) 와 **겹치는** 봉을 칠한다 — startTs < ts + 봉 길이 이고 (endTs 없음 또는 endTs > ts). 봉 길이는 화면의 봉 종류(접은 봉이면 접은 길이, 1분~1일)다. 봉 시작 시각이 사건 안인지만 보면 1시간봉 이상에서 봉 안에서 시작·끝난 사건이 빠진다. 길이가 0 이하인 사건은 어떤 봉과도 겹치지 않는다. 계산은 사건 구간을 시작순으로 정렬해 겹침을 합친 뒤 오름차순 봉과 한 번에 훑는다(봉 + 사건 규모) — 봉마다 사건 전체를 보면 과거를 끌어 붙일수록 봉·사건이 같이 늘어 제곱으로 느려진다. 기준 입력은 없다 — 우측 설명 `사건 = 원값 {김프|역프} 1.0% 진입 → 0.5% 이탈, 1분 이하 제외 · 기간 내 N건`.
- 좌 카드 "티커별 {김프|역프} 사건 · {기간} — 열 클릭으로 정렬": 열 `티커|상태|횟수|최대 지속|평균 지속|최대 스프레드|평균 스프레드|네트워크|최신`, 응답을 심볼별로 집계(거래소 전체면 두 거래소 사건을 합쳐 센다), 상위 30행, 헤더 클릭 정렬(재클릭 반전, 기본 횟수 내림차순). **`상태`** = 그 심볼에 진행 중 사건이 있으면 accent pill `진행 중 · {경과}`(경과 = 지금 − 그 사건 시작, 거래소 전체면 어느 한 거래소라도), 없으면 `끝남`(neutral 색). 상태 열 정렬은 진행 중이 먼저. `최신` = 가장 최근 사건 시작 시각의 경과 표기. **`망`** = 그 심볼의 가장 최근 사건의 `netDom`(거래소 전체면 두 거래소 사건을 합친 뒤 최근 것), 없으면 `–` — 정렬은 문자열 오름차순(재클릭 반전)(024). 평균 지속은 끝난 사건만으로 낸다(진행 중 사건은 길이가 미정이라 뺀다 — 최대 지속·점유율에는 지금까지로 넣는다). 행 클릭 → 선택 심볼. 선택 행 accent 배경. 비면 `기간 내 사건 없음`. 집계는 두 단계다 — 사건 목록이 바뀔 때만(60초 재조회·필터 변경) 심볼별 횟수·합·최대·가장 최근 사건과 진행 중 사건의 시작 시각을 한 번 훑어 모아 두고, 렌더마다(1.5초)는 진행 중 사건의 지속만 더해 최대 지속·상태를 채운다. 역프 7일 5만여 건을 렌더마다 다시 묶지 않기 위해서다. 합은 사건 순서대로 더해 한 번에 모으는 방식과 같은 값이 나온다. 가장 최근 사건은 시작이 가장 늦은 것, 같으면 먼저 온 것. 지속 표기(최대 지속·평균 지속·상태 pill·로그·툴팁)는 1시간 미만 `N분`(정수), 하루 미만 `N.N시간`, 그 이상 `N.N일` 이다. 먼저 표시 단위로 반올림하고, 반올림한 값이 다음 단위 경계(60분·24.0시간)에 닿으면 다음 단위로 올린다 — 3,599초는 `60분` 이 아니라 `1.0시간`, 86,399초는 `24.0시간` 이 아니라 `1.0일`. `최신` 열은 002 §3.3 의 경과 표기(같은 올림 규칙)다.
- 우 column: 요약 카드(선택 심볼 + 상태 pill(`진행 중 · {경과}` / `끝남`), 총 사건·평균 지속(끝난 사건만)·최장 지속·기간 점유율 = 기간(지금 − 기간 ~ 지금) 안에서 사건 구간 [시작, 시작 + 지속]을 **합친(겹침 제거) 길이 / 기간**(0~1, 소수 1자리 %) — 진행 중 사건의 지속은 지금까지로 센다. 거래소 전체면 같은 코인의 두 거래소 사건이 같은 시각에 겹치므로 지속을 그냥 더하지 않는다(더하면 100% 를 넘는다). 구간은 기간 안으로 자르고 시작순으로 정렬해 한 번 훑으며 합친다). 타임라인 **1줄**(현재 방향 색, 위치·폭 = 기간 대비, 최소폭 보장, 진행 중은 지금까지, 축 라벨 5등분 — 기간이 하루 이하면 `HH:mm`, 1주 미만이면 `M/D HH:mm`, 그 이상 `M/D`). "사건 로그 · {심볼} 최근 20건"(거래소|시작|종료|지속|최대 스프레드|망 — 현재 방향 색. `망` = 김프면 `{netFx} → {netDom}`, 역프면 반대, 한쪽만 있으면 있는 쪽만, 둘 다 없으면 `–` — 024). 진행 중 행은 종료 칸이 accent 색 `진행 중`, 지속은 지금까지, 행 배경을 옅은 accent 로 — 끝난 행과 한눈에 구분되게. 타임라인 막대의 key·툴팁은 사건 목록이 바뀔 때 사건마다 한 번 만든다(끝난 사건은 완성된 문자열, 진행 중은 지속 앞뒤 조각). 막대는 memo 된 컴포넌트로 툴팁·위치·폭 문자열과 색만 받는다 — 글자·위치가 그대로인 막대는 렌더마다 다시 그리지 않는다. 진행 중 사건의 툴팁·폭은 렌더마다 계산한다.
- 선택 심볼: 초기 `'BTC'`, 스프레드 행 클릭 피벗 그대로. 서브탭을 바꿔도 선택 심볼은 유지한다. 선택 심볼에 사건이 없으면 요약은 `–`, 로그는 `기간 내 사건 없음`.
- 상태: 조회 중 `조회 중…`(직전 유지), 오류 `기록을 불러오지 못했습니다 (HTTP n)`. 표 구조·색·간격은 `docs/design/reference/tabs/HistoryTab.tsx`·`theme.css`(김프/역프 열 분리 대신 서브탭 — 이 스펙이 참조 디자인을 개정한다).
- 필터바 아래 차트 카드는 014 §3.7 — 이 스펙의 API 와 무관하다.

## 4. 검증
- 열기: 값 1.0 정확히 → 연다, 0.99 → 안 연다
- 유지·닫기: `1.2 0.8 0.6 0.51 0.5` → 0.5 에서 닫힌다(0.51 까지 이어짐); `1.2 0.4 1.2` → 두 사건
- 버리기: 열린 뒤 60초에 닫힘 → 기록 없음, 61초 → 기록 1건
- 결측: 행이 599초 비었다 돌아오면 이어진다, 601초면 `end_ts = last_ts` 로 닫힌다; 그 뒤 값 1.0 이상이면 새 사건
- 결측으로 닫혀 `duration ≤ 60` 이 된 사건은 (이미 쓴 점이 있으면) 남는다
- `max_percent`·`max_ts` 는 사건 안 최댓값·그 시각, `samples` 는 관측 틱 수
- 조합·방향 독립: 업비트 SOPH kimp 와 빗썸 SOPH kimp 는 별개 사건
- Influx 쓰기: 열린 지 60초 전엔 0점, 넘기면 1점(`end_ts 0`), 열린 채 60초마다 갱신, 닫힐 때 `end_ts`·`duration_seconds` 채움; 같은 키 덮어쓰기
- 쓰기 실패 → 다음 회차 재시도, 재시도 목록 상한 1,000
- 복원: `end_ts 0` 이고 `last_ts` 가 601초 전 → 닫아서 쓴다; 300초 전 → 진행 중으로 올라온다; 같은 조합 둘 → 늦은 것만
- 복원 원천: 사본이 있으면 Influx 를 읽지 않고 같은 열린 사건(열린 지 60초 전 사건·망 이름 포함)이 되살아난다; 키 없음·깨진 JSON·읽기 실패면 Influx(HTTP 타임아웃 3초)로; 빈 사본 `[]` 은 열린 사건 없음; 사본에서 온 사건도 600초 규칙으로 닫혀 쓰인다 (`tests/test_premium_events_snapshot.py`)
- 사본 저장: 60초 갱신 틱에 직렬화되고 쓰기 태스크가 저장한다(틱에서는 저장 없음, 60초 안엔 새 사본 없음); 종료 1회는 실패 대기 안에서도 미전송 점을 쓰고 사본은 지금 상태이며 3초를 넘기면 경고 1줄로 끝난다; 앱 종료가 이 1회를 쓰기 태스크 취소 전에 부른다 (`tests/test_boot_order.py`)
- 닫힘 회차 사본: 60초 갱신 사이에 닫힌 사건과 버린 스파이크는 닫힘 점을 쓴 회차의 사본에서 빠지고, 쓰기 태스크만 취소한 비정상 종료 뒤 600초 안의 재기동에서 다시 열리지 않으며 Influx 의 닫힘 점도 그대로다; 닫힘 점 쓰기가 실패한 회차는 사본을 다시 만들지 않고 쓰기가 되는 회차에 뺀다 (`tests/test_premium_events_snapshot.py`)
- 복원이 닫은 고아 1,500건(상한 초과)이 첫 회차 쓰기 1번에 모두 쓰이고 버림 경고가 없다; 실행 중 상한 초과는 쓰기를 시도하는 회차에 1줄(`… 5건 버림`)
- 두 단계 조회: 두 요청 모두 같은 7일 창, 코인 정규식 이스케이프(`A\.B`·`X\/Y`), 1단계 키에 없는 행·반쪽 점은 버림, `-`·빈 문자열 망은 `null`, 열린 사건이 없으면 2단계 없음, CSV 오류 표는 저장소 실패 (`tests/test_influx_lines.py`)
- 판정 경로: 모든 행·방향의 키를 만들고 이번 틱에 본 조합으로 결측을 가르는 기준과, 결측·700초 공백·문턱을 오가는 값(NaN 포함) 3,000틱 열에서 열린 사건과 쓴 점이 같다
- Influx 없이 기동 → 감지는 돌고 `/history/events` 503
- `/history/events`: `start` 없으면 `startTs == endTs − 604800`; `dom`·`dir`·`base` 필터; 진행 중은 `endTs null`·`ongoing true`·60초 미만 사건은 안 실림; 구간 전에 시작한 사건은 빠짐; 정렬; 빈 `events` 200; `end ≤ start` 400; `base=btc` → `BTC`
- `/history/events` 정렬: 같은 시작·같은 코인은 저장소가 준 순서와 무관하게 dom·fx·dir 오름차순 (`test_events_api.py`) / 사건 목록 조회는 응답 필드 7개만 pivot·group·sort 없음, 따옴표 속 쉼표·반쪽 점·망 표식 `-`, 조각 경계 (`tests/test_influx_stream.py`)
- `/history/events` 인코딩: 모델로 만든 응답과 같은 바이트다(`fetchedAt` 제외 — 0·1,999·2,000·4,321건 × 필터 4종, 고아 점·진행 중 포함), 오류 400·503 도 같다 (`features/history/tests/test_encoding.py`)
- `/history/events` 공유 캐시: 같은 키 두 번 → 조회 1번·같은 바이트(그 사이 바뀐 저장소는 60초 안엔 안 보임), 61초 뒤 새로 조회 / `base` 대소문자는 같은 키 / gzip 이면 미리 압축한 바이트, 아니면 원본(풀면 같다) / 오류는 담지 않는다 / 동시 8건에 조회 1번 / 만료 키는 채울 때 버리고 담은 합은 64MB 이하, 혼자 넘는 응답은 안 담는다 (`test_cache.py`)
- web 집계 규칙(수동 또는 순수 함수 테스트): 횟수 = 기간 안 시작한 사건 수(거래소 전체면 합산), 평균 지속은 끝난 사건만, 최대 지속·점유율은 진행 중을 지금까지로 포함, 상태 열은 진행 중 사건이 하나라도 있으면 `진행 중 · 경과`
- web 폴링: 스프레드 탭만 연 5초 동안 `/history/*` 0건(기록 탭 미마운트), 기록 탭을 보는 동안 60초마다 사건 2건(표·차트 음영)·최신 청크, 다른 탭·가려진 브라우저 탭 62초 동안 0건, 62초 만에 돌아오면 곧바로 1회, 5초 만에 돌아오면 0건(헤드리스 크롬 요청 기록)
- web 조회 창: `end` 가 60의 배수이고 지금 이상 60초 미만 뒤, 표 조회는 `end − start = 604800`, 같은 분의 두 시각은 같은 `(start, end)`, 차트 음영의 `start` 는 청크 시작 그대로 (node)
