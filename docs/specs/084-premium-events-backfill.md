# 084 — premium-events-backfill

상태: DONE | 의존: 013(사건 규칙·`premium_event` 점·감지기), 005(`premium` 점·백필의 변동분 기록), 024(망 이름 없음 `-`), 021(data 박스)

> 이 문서는 이 기능이 **지금 어떻게 동작해야 하는지**를 적는다. 동작이 바뀌면 이 문서를 직접 고치고, 같은 PR 에서 코드·테스트도 맞춘다(CLAUDE.md §4·§6). 사람이 끝까지 읽는 문서다 — 코드를 산문으로 옮기지 않는다.
> 구현 구조(클래스·함수·파일 내부)는 실행 세션의 몫이다. 여기엔 **무엇이 어떻게 동작해야 하는가**만 쓴다.

## 1. 목적
`premium_event` 는 운영 감지기가 돈 2026-09-07 부터만 쌓여, 기록 탭의 1달·3달 표·요약·사건 로그는 그 전이 비어 있다. Influx `premium` 에는 그 전 기록(2026-05-15~09-07)이 남아 있으므로, 같은 감지기로 그 기록을 한 번 재생해 배포 전 사건을 만들어 넣는다. 끝나면 기록 탭이 운영 감지기와 같은 규칙으로 만든 사건을 배포 전까지 이어서 보여 준다. 일회성이다 — 그 뒤는 운영 감지기가 맡는다.

## 2. 범위
- 만드는 것: 일회성 스크립트 `server/scripts/premium_events_backfill.py`(기본은 쓰지 않는 dry-run, `--write` 로 쓴다, `--verify` 는 운영 사건과 맞춰 보기만 한다). core 공개 함수 둘(추가만) — `InfluxClient.stream_premium_base(*, base: str, start: int, stop: int) -> Iterator[tuple[str, str, str, int, float]]`(코인 하나의 `premium` 을 모든 거래소 쌍에 걸쳐 `(dom, fx, field, ts, value)` 로 흘려 읽는다 — pivot·group·sort 없음)와 `InfluxClient.premium_day_counts(*, start: int, stop: int, base: str | None = None) -> list[tuple[str, int, int]]`(코인·UTC 날별 fwd 점 수 — Influx 가 1일 창 count 로 접어 준다, 조각 나누기용).
- 하지 않는 것: 사건 규칙·`premium_event` 점 모양·`/history/events`·기록 탭 변경. 배포 뒤 사건 다시 쓰기. 옛 점의 망 이름·입출금 상태 복원(원천에 없다). 배포 전 봉(014) 만들기 — 그래서 차트 음영은 늘지 않는다(§3.8). 정기 실행. `premium` 원값 수정.
- 바꾸는 기존 것: 013 §2 "하지 않는 것" 의 "과거분은 … 별도 스펙" 을 이 스펙으로. status.md 알려진 빚 "(013) 과거 `premium` 의 사건 일괄 생성 미완" 을 지운다.

## 3. 동작

### 3.1 읽는 계약 (복사)
- 013 §3.2: 사건은 조합 `(dom, fx, base, dir)` 마다, 값 = `kimp` 면 `fwd`·`reverse` 면 `rev`. 1.0% 이상이면 열고, 0.5% 초과면 이어 가고, 0.5% 이하가 된 첫 틱에서 닫고, 관측 중 닫힌 사건의 길이가 60초 이하면 버린다. 틱에 그 조합 행이 없으면 결측 — 마지막 관측 `last_ts` 뒤 600초를 넘기면 `end_ts = last_ts` 로 닫고(길이 60초 이하도 남긴다), 그 안에 돌아오면 이어 간다. 판정은 core 감지기(`core/premium_events.py`)가 매 틱 한다.
- 013 §3.3: `premium_event` — tag `dom`·`fx`·`base`·`dir`, time = `start_ts`(초), field `end_ts`·`duration_seconds`·`max_percent`·`max_ts`·`last_ts`·`samples`·`enter_percent` 1.0·`exit_percent` 0.5·`net_dom`·`net_fx`. 유일키 (dom, fx, base, dir, start_ts) — 같은 키 재쓰기는 덮어쓴다. `end_ts 0` 은 진행 중. 기동 복원은 7일 안 `end_ts 0` 만 읽는다.
- 013 §3.4: `/history/events` 는 `start ≤ start_ts < end` 인 사건을 싣고, `end_ts 0` 인데 메모리에 없는 점은 `last_ts` 에 닫힌 것처럼 싣는다.
- 005·009: `premium` — tag `dom`·`fx`·`base`, field `fwd`·`rev`(원값 %, 두 필드는 늘 같이 쓴다), time = 초. 버킷 `marketlens`.
- 024: 망 이름 "없음" 은 `-` 로 쓰고, 읽을 때 null.

### 3.2 경계와 원천
- **경계 C = 2026-09-07T09:20:08Z (1788772808).** 운영 감지기의 첫 틱이다 — `premium_event` 의 가장 이른 점이고(2026-10-23 확인: 그 전 점 0건, 그 시각에 연 사건이 여럿), 그 뒤 운영 점은 전부 `start_ts ≥ C` 다. 백필은 C 전의 틱만 재생하고, 백필 사건은 전부 C 전에 시작해 C 전에 끝난다(§3.4) — 운영 사건과 유일키도 시간 구간도 겹치지 않는다. C 는 고정값이다 — 백필 뒤에는 가장 이른 점이 백필 점이라 다시 셀 수 없다.
- **원천**은 Influx `premium` 의 C 전 점이다 — 6,561만 점(fwd 기준), 코인 298종, 쌍 497개(업비트×바이낸스 200·빗썸×바이낸스 297 — 그때 해외는 바이낸스뿐). 밀도가 시대마다 다르다(2026-10-23 실측):

| 시대 | 점 |
|---|---|
| 초단위변동분 | 05-15~08-15 |
| 분당1점 | 08-16~09-05 |
| 원본없음 | 09-05~09-06 |
| 초단위틱 | 09-06~C |

  초 단위 변동분은 업비트 상위 14종(BTC·ETH·XRP·SOL·WLD·SUI·XLM·KAITO·ONDO·EUL·LA·HOME·ONG·RED, BTC 는 08-28 까지)만이고 값이 바뀐 초만 적었다(005 §3.5 합치기 — 구 스택 백필 포함). 분당 1점은 전 코인(구 스택 분 단위 기록 이관과 당시 라이브). 원본 없음은 2026-09-05T14:32Z~09-06T17:04Z 26시간(이관 기록의 남은 유실). 초 단위 틱은 09-06T17:04Z~C, 지금 저장 방식 그대로(틱 행 = 점).
- **시대를 가르지 않는다.** 저장된 점 하나를 그 초에 관측한 행 하나로 보고 같은 규칙을 돌린다 — 005 streaks 가 같은 점을 `maxGap` 600초로 끊어 세던 것과 같다. 그래서 백필 사건의 `samples` 는 감지기가 본 틱 행 수가 아니라 **저장된 점 수**다(분당 1점 시대는 분 수, 변동분 시대는 값이 바뀐 초 수). 변동분 시대에 값이 600초 넘게 그대로였던 곳(덜 거래된 코인의 한산한 시간 — C 전 기준 ONG 1,281곳·RED 1,007곳·LA 325곳)은 결측으로 보고 사건을 끊는다. 이유: 그 공백이 "값이 그대로" 인지 "원천이 끊김"(07-05 BTC 5시간처럼)인지 점만으로는 가를 수 없고, 채워 넣으면 끊긴 수집을 이어 붙인다(005 와 같은 이유).

### 3.3 틱 다시 만들기
- **코인 하나씩** 돈다(감지기 상태가 조합마다 따로라 코인끼리 섞이지 않는다 — 전 코인을 한 틱 열로 돈 것과 같은 결과). 그 코인의 점을 읽어 같은 초의 (국내, 해외) 점마다 행 하나 `(dom, fx, base, fwd, rev)` 로 묶은 것이 그 초의 틱이고, 틱은 시각 오름차순으로 감지기에 넣는다. 두 필드 중 하나만 있는 점은 건너뛴다(005 — 정상 데이터가 아니다). 망 이름·가격·입출금은 비운다.
- **틱 열은 끊기지 않는다고 본다.** 앞 틱과 1초보다 벌어지면 다음 틱의 1초 전에 행 없는 틱을 하나 넣는다. 운영은 매초 틱이 돌고 그 조합 행만 빠지므로, 결측 판정이 운영과 같은 결과를 낸다 — 마지막 관측 L 뒤 행이 L + 601 에 돌아오면 이어지고, L + 602 이후면 그 전에 L 로 닫혀 돌아온 값은 새 사건이 된다(L + 601 의 틱이 행 없이 지나간 운영과 같다). 이 빈 틱이 없으면 600초 넘게 비었다 돌아온 행이 닫혔어야 할 사건을 이어 간다. 수집이 통째로 멈춘 시간(점이 하나도 없는 초)도 같은 결측이다 — 013 §3.3 이 "서버가 죽어 있던 시간은 행을 못 본 시간과 같다" 고 둔 것과 같다.
- **판정은 운영 감지기를 그대로 쓴다** — 기준값·판정 경로를 이 스크립트가 따로 갖지 않는다. 감지기가 쓰려는 점 가운데 **닫힌 사건(`end_ts > 0`)만** 받는다. 열린 지 60초·60초 갱신 점(`end_ts 0`)은 버린다 — 재생이 도중에 끊겨도 진행 중 점이 고아로 남지 않게(013 §3.4 가 `last_ts` 에 닫힌 것처럼 실어 버린다).
- 감지기의 미전송 상한(1,000)에 걸리지 않게 **재생 시각 600초마다** 감지기의 점을 받아 간다 — 600초 동안 한 조합에서 닫힐 수 있는 사건은 10건 안팎이라 코인 하나(조합 ≤ 8, 방향 2)는 상한에 닿지 않는다.

### 3.4 경계 C 에서 열려 있는 사건
- 그 코인의 마지막 틱이 C − 1 보다 이르면 C − 1 에 행 없는 틱을 하나 넣는다 — C 전에 600초 넘게 끊긴 조합은 운영처럼 마지막 관측에서 닫히고, 열린 지 60초가 지났는지가 C − 1 기준으로 정해진다.
- 그래도 열려 있는 사건은 **`end_ts = last_ts`**(C 전 마지막 관측)로 닫아 쓴다 — 013 §3.3 복원이 600초 넘게 못 본 사건을 닫는 규칙과 같다. 운영은 C 에 빈 상태로 시작해 그 조합의 값이 1.0% 이상이면 C 에 새 사건을 열었으므로, 한 사건이 C 에서 둘로 나뉜다(2026-09-28 전 재기동이 사건을 쪼갠 것과 같은 모양 — 겹치지 않는 쪽을 택했다).
- 단 C − 1 에 **열린 지 60초를 넘기지 못한 사건은 버린다** — 운영이었다면 Influx 에 점이 생기기 전이다(013 §3.3 쓰는 시점 1).

### 3.5 쓰기
- 점 모양은 013 §3.3 그대로(core `premium_event_point`) — `enter_percent` 1.0·`exit_percent` 0.5, **`net_dom`·`net_fx` 는 `-`**(024 — 원천 `premium` 에 망 이름이 없다. 읽을 때 null 이라 기록 탭 `망` 칸은 `–`). `duration_seconds = end_ts − start_ts`.
- 같은 키 덮어쓰기라 **다시 돌려도 같은 점이 같은 값으로 덮인다**(감지기는 같은 입력에 같은 결과를 낸다). 도중에 끊겨도 이미 쓴 점은 닫힌 사건이라 최종값이고, 다시 돌리면 나머지를 채운다. 진행 중 점(`end_ts 0`)은 쓰지 않으므로 기동 복원·랜딩 진행 중 수·고아 점 규칙에 걸릴 것이 없다.
- 쓰기 1회 5,000점(009 와 같은 단위).

### 3.6 운영 보호
- **실행 위치**: data 박스의 일회용 컨테이너. collect 박스의 `marketlens-server` 이미지(운영 코드와 같은 의존성)를 옮겨 와 `--rm` 으로 띄우고, compose 망 `marketlens_default` 로 `http://marketlens-influxdb:8086` 에 붙는다. CPU 0.5개·메모리 512MB(스왑 없음), 프로세스는 `nice 19`. 운영 컨테이너는 건드리지 않는다. 토큰은 Influx 컨테이너 환경에서 env 파일로 넘겨 화면·셸 기록에 남지 않게 한다. 이유: Influx 와 같은 박스라 원값(약 1.3억 줄)이 망을 건너지 않고, collect(1 vCPU)는 틱 루프가 CPU 를 쓴다. data 박스는 평소 CPU 5~10%·크레딧 잔량 576(t4g.small 최대, 2026-10-23).
- **조회는 한 번에 하나**(Influx 동시 조회 2개 중 하나만 — 운영 조회 몫을 남긴다). 한 조회는 fwd **20만 점 이하**다 — 코인의 날별 점 수(Influx 가 접어 주는 창 집계 1회)로 날을 묶고, 하루가 넘치면 그날을 같은 길이로 쪼갠다. 조회 하나는 다 받은 뒤 재생한다(받다 끊기면 그 조회만 다시 — 감지기에 반쪽 조각이 들어가지 않게).
- **쉬기**: 조회가 걸린 만큼 쉬고(최소 0.2초), 쓰기 1회마다 0.5초 쉰다 — Influx 가 쓰는 CPU 가 절반을 넘지 않게.
- 조회·쓰기 실패는 10초 간격으로 3번 다시 하고, 그래도 실패면 멈춘다(exit 1) — 다시 돌리면 된다(§3.5).
- **순서**: dry-run(쓰지 않고 사건 수·걸린 시간·박스 CPU 를 잰다) → 검증(§3.7) → 쓰기. 끝나면 옮겨 온 이미지·env 파일·스크립트 사본을 지운다.

### 3.7 검증 — 배포 뒤 겹치는 구간
- 운영 감지기와 같은 결과인지 보려고 **배포가 없던 하루 2026-10-20T00:00Z~10-21T00:00Z**(앞뒤 배포 10-19T10:48Z·10-23T11:10Z)를 재생해 운영 `premium_event` 와 맞춘다. 대상 코인: 그날 운영 사건이 많은 상위 30종 + BTC·ETH(해외 4곳 모두). 쓰지 않는다.
- **맞출 사건**: 조합마다 비교 시작 = 창 시작, 단 창 시작 전에 열린 운영 사건이 있으면 그 사건의 끝(진행 중·고아 점은 `last_ts`) + 601초 — 재생은 창 시작에서 빈 상태로 시작하므로 그 전부터 이어진 사건은 같을 수 없고, 끝난 뒤 601초 안에 돌아온 행은 운영에선 그 사건을 잇지만 재생에선 새 사건을 연다. 비교 시작이 창 끝을 넘는 조합(창 내내 이어진 사건)은 통째로 빠진다. 양쪽 모두 시작이 비교 시작 이상이고, 닫혔고, 끝이 창 끝 − 610초 이하인 사건만 센다(결측 닫힘은 마지막 관측 601초 뒤에 정해진다).
- **맞추는 값**: 유일키 집합과 `end_ts`·`max_percent`·`max_ts`·`last_ts`·`samples`. 운영 `samples` 는 감지기가 본 틱 행 수이고 재생은 저장된 점 수라, 틱이 저장되지 않은 초(인계·flusher 유실 — 009)에서만 다를 수 있다. 다른 사건은 하나하나 원인을 §7 에 적는다.

### 3.8 화면에 미치는 것
- `/history/events` 의 1달·3달 창이 배포 전 사건까지 싣는다 — 응답 크기는 §7 실측(상한은 새로 두지 않는다 — 수치만 기록). 7일 창(기본)·랜딩 7일 요약·`/kimp-history`·기동 복원(7일)은 C 뒤라 그대로다.
- 기록 탭 표·요약·타임라인·사건 로그는 배포 전 사건을 다른 사건과 같게 보인다(`망` 칸 `–`). **차트 음영은 늘지 않는다** — 봉 계층(014)이 2026-09-07 부터라 배포 전에는 칠할 봉이 없다.

### 3.9 되돌리기
- 백필 점은 전부 time(= `start_ts`) < C, 운영 점은 전부 ≥ C 이므로 **시간 범위 삭제 하나로 백필만 지운다** — data 박스 Influx 컨테이너 안에서(토큰은 컨테이너 환경):
  `influx delete --org marketlens --bucket marketlens --start 1970-01-01T00:00:00Z --stop 2026-09-07T09:20:08Z --predicate '_measurement="premium_event"'`
- Influx 삭제는 표시만 하고 디스크는 다음 압축 때 돌아온다. 지운 뒤 다시 돌리면 같은 점이 다시 생긴다(§3.5).

## 4. 검증
- 틱 다시 만들기: 같은 초의 (국내, 해외) 점이 한 틱의 행들, 시각 오름차순, 반쪽 점은 건너뜀, 망 이름 없음
- 빈 틱: 마지막 관측 L 뒤 행이 L + 601 에 돌아오면 이어지고 L + 602 면 L 로 닫혀 새 사건 — 같은 행을 매초 틱 열(빠진 초는 행 없는 틱)에 넣은 운영 기준과 같은 점(무작위 열: 결측·문턱 오가는 값·분당 점·변동분 점·NaN 없는 값, 수천 틱)
- 쓰는 점: 닫힌 사건만(진행 중 점 0), `net_dom`·`net_fx` `-`, 기준값 1.0·0.5, `duration_seconds = end_ts − start_ts`
- 경계: C − 1 에 열린 지 60초 넘은 사건은 `last_ts` 로 닫혀 쓰이고, 못 넘은 사건은 버려지며, C 전 600초 넘게 끊긴 조합은 결측으로 닫힌다. 쓴 점은 전부 `start_ts < C`·`end_ts < C`
- 다시 돌리기: 같은 입력 두 번 → 같은 점 집합·같은 값(덮어쓰기 저장소의 점 수 그대로)
- 600초마다 받아 가기: 한 시간에 닫힘 수백 건인 코인도 버림 없음
- 조각: 날별 점 수로 나눈 조각(넘치는 날은 쪼갬)이 20만 점 이하이고, 조각 경계에서 틱·사건이 이어져 조각 하나로 돈 결과와 같다
- dry-run(`--write` 없음)·`--verify` 는 쓰기 0
- 검증 비교: 창 시작 전에 열린 운영 사건의 조합은 그 끝(진행 중·고아 점은 `last_ts`) + 601초부터 세고, 그것이 창 끝을 넘으면 조합째 뺀다(오래된 고아 점은 창과 무관); 끝이 창 끝 − 610초보다 늦은 사건·진행 중 사건은 양쪽 다 뺀다; 다른 값은 필드별로 센다
- `stream_premium_base`: pivot·group·sort 없음, 다섯 칸(`dom`·`fx`·`_field`·`_time`·`_value`), 1바이트 조각에서도 같은 점, 도중 오류 표·줄 중간에서 끝난 응답은 저장소 실패
- 실패: 조회가 3번 다시 해도 실패하면 exit 1, 그 전까지 쓴 점은 닫힌 사건뿐
- 수동(EC2): dry-run 의 사건 수·걸린 시간·박스 CPU, 검증 일치율, 운영 쓰기 뒤 `premium_event` 의 C 전 점 수 = dry-run 사건 수, 기록 탭 1달·3달 표·로그에 배포 전 사건, `/history/events` 응답 크기

  - `server/tests/test_premium_events_backfill.py`, `server/tests/test_influx_stream.py`(두 조회).
- 추측한 지점 (묻지 않고 정한 사소한 것) / 실행 중 함께 고친 스펙 절:
  - 변동분 시대를 채워 넣지 않았다(§3.2) — 005 streaks 의 `maxGap` 600초가 같은 점에 같은 규칙을 썼고, 공백이 "값이 그대로" 인지 "원천 끊김" 인지 가를 수 없어서다. 그래서 `samples` 는 저장된 점 수다.
  - 경계는 운영 첫 점 시각으로 고정했다(§3.2). 경계에서 열린 사건은 복원 규칙(`last_ts`)으로 닫고, 60초를 못 넘긴 것은 버렸다(§3.4 — 88건 닫음·2건 버림).
  - 검증 창 비교 시작을 "창 전 운영 사건의 끝 + 601초" 로 잡았다(§3.7 고침) — 끝난 뒤 601초 안에 돌아온 행은 운영에선 그 사건을 잇는다.
  - 조각 상한 fwd 20만 점에서 백필 컨테이너 최대 RSS 385MB(상한 512MB).
  - 감지기의 테스트용 `flush()` 를 받아 가기에 썼다(공개 함수 — 미전송 점을 지금 쓴다).
- 남은 빚:
  - 배포 전 사건의 `samples` 는 저장된 점 수(분당 1점 시대 = 분 수, 변동분 시대 = 값이 바뀐 초 수)이고, 변동분 시대의 600초 넘는 한산한 구간에서 사건이 끊긴다(§3.2). 망 이름은 `-`.
  - 배포 전 봉(014)이 없어 차트 음영에는 배포 전 사건이 보이지 않는다(§3.8).
  - 90일 역프 전 코인 응답이 원본 59.5MB + gzip 7.9MB = 67.4MB 로 013 공유 캐시 상한(64MB, 원본 + gzip)을 넘어 이제 담기지 않는다(쓰기 전 61MB 는 담겼다) — 그 조건은 요청마다 조회한다(15.9초). 상한은 바꾸지 않았다(사람 결정 — 수치만 기록).
  - 정리: data 박스의 옮겨 온 이미지(`evbf-server:tmp`)·`/tmp/evbf`(env 파일 포함)·샘플러를 지웠다. 운영 컨테이너는 건드리지 않았다.
