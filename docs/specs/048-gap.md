## 1. 목적
해외 현물과 해외 perp(무기한 선물) 사이의 **현선갭**(베이시스)을 실데이터로 본다. 끝나면 선물–현물 갭 탭이 mock 대신 매초 오는 표로 돌고, 트레이더가 "어느 코인을 어느 현물 거래소에서 사서 어느 perp 거래소에서 숏하면 몇 % 가 벌어져 있고, 펀딩은 얼마를 언제 받는가"를 한 표에서 본다.
갭은 **체결 가능한 최우선 호가**로 계산한다(2026-10-08 사람 결정) — 현물은 ask 에 사고 perp 는 bid 에 숏하는 값이라 체결가·mark 기준보다 보수적이고, 양수면 그 순간 실제로 벌어져 있는 것이다.

## 2. 범위
- 만드는 것: server — 틱마다 현선갭 표 1장(접속자와 무관하게 매초), Redis 게시(채널 `gap`·키 `gap:latest`), api 허브와 `GET /ws/gap`. 017 의 게시기·허브를 **표 id 로 일반화**(spreads 의 동작은 그대로). web — `features/gap` 의 mock 피드를 `/ws/gap` 구독으로 교체(화면·조작은 002 §3.7 그대로). nginx 공개 허용 목록에 `/api/ws/gap`.
- 하지 않는 것: 갭 이력 저장·사건·봉(Influx 에 아무것도 쓰지 않는다 — 후속 스펙), 슬리피지 차감(최우선 1단계만 — 체결 규모 선택지 없음), HTTP 조회 `GET /gap`(curl 진단은 Redis `gap:latest` 를 본다), 선선갭(049), 국내 거래소가 낀 조합, 입출금 상태(perp 에는 없고 현물 쪽 값도 싣지 않는다), 004 분석 API 의 perp 확장, 관리자 화면의 gap 접속 수(§3.4).
- 바꾸는 기존 것: 017 게시기·허브의 표 id 매개변수화(§3.4), 028 허용 목록 +1(§3.5), 003 §3.4 표시명 사전에 perp 원천 4개(§3.6), 002 §3.6·§3.7 의 gap mock 규칙 삭제(§6).

## 3. 동작

### 3.1 읽는 계약 (복사)
- 046 §3.1 perp 행 = `(source, base)` 당 `native_symbol`·`multiplier`·`bid`·`ask`·`bid_size`·`ask_size`(가격·잔량은 **1코인 단위** — 배수 심볼은 046 이 이미 나눠 둔 값)·`mark`·`funding_rate`(한 주기의 비율, 예 `0.0001` = 0.01%, 모르면 null)·`next_funding_ms`(null 가능)·`funding_interval_h`(정수 시간, null 가능)·`quote_ts`·`updated_at`. 원천 id 와 고정 순서 `binance_perp`·`bybit_perp`·`bitget_perp`·`hyperliquid_perp`, 표시명 `Binance`·`Bybit`·`Bitget`·`Hyperliquid`. 원천별 스트림 상태 `{connected, last_message_at, …}` 는 001 과 같은 모양.
- 001 §3.3 해외 현물 행 = `(exchange, base)` 당 `price`(마지막 체결가, 없으면 mid)·`asks`·`bids`(`[price, size]`, 1단계가 최우선)·`updated_at`. 해외 현물 거래소 = 001 §3.2 의 해외 원천 전부(`binance`·`bybit`·`bitget`, 045 가 끝났으면 `okx`), 그 순서. 거래소별 스트림 상태의 `last_message_at`.
- 003 §3.2 `age`·`status`: `age` = 양쪽 스트림 `last_message_at` 중 오래된 쪽의 경과 초(0 미만이면 0), 단 두 행 중 어느 쪽이든 `updated_at` 이 300초 이상 오래됐으면 그 행의 실제 경과 초(둘 중 오래된 쪽). `status` = 최우선 호가 4개 중 하나라도 없거나 가격·잔량이 0 이하면 `fail`(숫자 필드 0), `age ≥ 5.0` 이면 `stale`, 아니면 `ok`. `core/premium.py` 의 `premium_percent(buy, sell) = (sell / buy − 1) × 100`.
- 017 §3.1~3.4: 게시(PUBLISH + SET … EX 10, 큐 2장, Redis 불달 60초 1줄, 300ms 경고), 허브(접속자 0명이면 구독 없음·30초 유예, 직전 표 1장, diff 1회·gzip 레벨 6 1회, snapshot 칸, heartbeat 1초, waiting, 느린 접속 대기열 5개 → 1008, `--ws-per-message-deflate false`), 프레임 네 종류 `snapshot`·`delta`·`heartbeat`·`waiting`, web 구독 규칙(`DecompressionStream`·직렬 처리·10초 무응답·백오프 1→30초 × 0.5~1.5 지터·첫 snapshot 전 상한 3초·폴링 fallback 없음).

### 3.2 표 계산 (틱 루프 안, 동기 — `await` 없음)
- 조합 = (해외 현물 거래소 `spot`, perp 원천 `perp`, **양쪽에 행이 있는** base). 국내 거래소는 끼지 않는다. 같은 회사의 현물·perp(`binance` × `binance_perp`)도 한 행이다 — 한 거래소 안의 베이시스 거래가 가장 흔하다. 현물 행은 김프 우주(국내 상장 코인)에만 있으므로 **현선갭의 코인 범위 = 김프 우주 ∩ perp 우주**다(해외 현물 우주 확장은 빚 — §6 status.md).
- 행 값(반올림하지 않는다):
  ```
  entry = premium_percent(buy=spot_ask, sell=perp_bid)   # 진입: 현물 ask 에 사고 perp bid 에 숏 — 클수록 좋다
  exit  = premium_percent(buy=spot_bid, sell=perp_ask)   # 정리: 현물 bid 에 팔고 perp ask 에 숏 청산 — 작을수록 좋다
  ```
  `spot_ask`=현물 `asks[0].price`·`spot_bid`=`bids[0].price`, `perp_bid`·`perp_ask`=perp 행의 `bid`·`ask`. `spotPrice` = 현물 행 `price`. `funding` = `funding_rate × 100`(한 주기의 퍼센트, null 이면 null), `intervalH` = `funding_interval_h`, `nextFundingTs` = `next_funding_ms // 1000`(epoch 초 — product.md 시각 규칙, null 이면 null). `mark` 는 싣지 않는다(화면이 쓰지 않는다).
- `status`·`age` 는 003 §3.2 그대로 — 호가 4개 = 현물 bid/ask(가격·잔량)·perp bid/ask(`bid_size`·`ask_size`). `fail` 이면 `entry`·`exit`·`spotPrice` 는 0 이고 펀딩 세 값은 그대로 싣는다.
- 행 정렬 `(sym, spot, perp)` 오름차순 — `spot` 은 해외 현물 거래소 순서, `perp` 는 046 원천 순서(사전순이 아니다).
- 표 JSON(camelCase): `{"rows":[…], "warnings":[], "dataReceivedAt":<틱 ts, 초>, "fetchedAt":<만든 시각 ms>}`. 행 키 **11개** 고정: `sym spot perp spotPrice entry exit funding intervalH nextFundingTs status age`. 예:
  ```json
  {"sym":"BTC","spot":"binance","perp":"bybit_perp","spotPrice":82430.1,"entry":0.0412,"exit":-0.0188,
   "funding":0.0065,"intervalH":8,"nextFundingTs":1791475200,"status":"ok","age":0.8}
  ```
  `warnings` 는 지금 항상 빈 목록이다(키는 017 과 모양을 맞추기 위해 둔다). `rate`·`notional` 은 없다.
- 규모: 김프 우주 ∩ perp 우주 약 300코인 × (현물 3~4 × perp 4) = **최대 약 4,800행**, spreads 표(약 1,500행)의 3배다. 틱 생성 경로 규칙(001 §3.6-2)대로 조합을 한 번 훑고 행은 불변 튜플형 레코드로 만든다. 표 생성(JSON 포함) 300ms 경고는 017 과 같고 실측은 §5 에 적는다. 단계별 소요 로그(001 §3.6)에 `갭표` 단계가 는다.

### 3.3 게시 (017 §3.1 을 표 id `gap` 으로)
틱 루프가 spreads 표를 게시한 다음 같은 회차에서 이 표를 만들어 `PUBLISH gap <JSON>` + `SET gap:latest <JSON> EX 10`. 큐 2장·오래된 것부터 버림·Redis 불달 경고 60초 1줄·게시 실패가 틱을 막지 않는 것은 017 과 같다. spark 조각이 없으므로 보통 인코더(NaN 거부)로 한 번 인코딩한다.

### 3.4 허브 일반화 · `GET /ws/gap`
- 017 §3.2~3.3 의 허브를 **표 id 하나로 매개변수화**한다 — 채널 `<id>`, 시작 키 `<id>:latest`, 경로 `/ws/<id>`, 그리고 행 키 함수. spreads 는 `sym|dom|fx`, gap 은 `sym|spot|perp`. 그 밖의 규칙(접속자 0명 구독 없음·30초 유예, 직전 표 1장, diff·gzip 1회, snapshot 칸, heartbeat, waiting, 느린 접속 1008, 종료 1001, Redis 구독 백오프)은 전부 같다. 허브 인스턴스와 Redis 구독 연결은 **표마다 하나**(한 연결이 한 채널만 구독하는 지금 구조를 유지한다). `spreads:want` 갱신(018)은 spreads 허브만 한다. spreads 의 바이트·프레임·테스트는 바뀌지 않아야 한다(§4).
- 프레임: `{"type":"snapshot","rows":[…11키 행 전부…],"warnings":[],"dataReceivedAt":…,"fetchedAt":…}` / `{"type":"delta","rows":[바뀐 행],"removed":["BTC|binance|bybit_perp",…],"warnings":[],"dataReceivedAt":…,"fetchedAt":…}` / `{"type":"heartbeat"}` / `{"type":"waiting"}`. 바뀜 = `age` 를 뺀 어느 필드라도 다름(017 과 같다). 바이너리 프레임 1개 = gzip JSON 1개, 클라이언트 → 서버 메시지는 무시.
- 027 의 WebSocket 접속 수 게이지 `marketlens.ws_clients` 는 **spreads 허브만** 센다 — gap 접속은 CloudWatch·관리자 화면에 나오지 않는다(빚, §6).

### 3.5 프록시 (028)
공개 허용 목록에 **정확 일치** `/api/ws/gap` → api `/ws/gap` 을 더한다(일곱 번째; 045·049 와 번호가 어긋나도 "spreads 바로 다음"). 모양은 `/api/ws/spreads` 와 같다 — 접두 제거 rewrite + URI 없는 `proxy_pass` + 업그레이드 헤더(`Upgrade`·`Connection "upgrade"`, HTTP/1.1). 접두 location 은 만들지 않는다. 028 의 배포 계약 테스트(웹이 부르는 경로 ↔ 허용 목록 대조)가 이 경로를 함께 본다. vite dev 프록시는 `/api` 에 이미 `ws: true` 다.

### 3.6 web — 선물–현물 갭 탭
- 화면·조작·정렬·강조·펀딩 셀·빈 상태는 002 §3.7 그대로다. 바뀌는 것은 **데이터 원천**과 **코인별 집계**뿐이다.
- 구독: 017 §3.4 의 연결 규칙(주소 만들기·gzip 해제·직렬 처리·10초 무응답·백오프·지터·첫 snapshot 전 3초 상한·폴링 fallback 없음)으로 `/ws/gap` 을 **탭이 보이는 동안만** 연다 — 숨으면 닫고 표는 메모리에 둔 채 셸의 1.5초 tick 으로 `age` 만 키우고(5초 뒤 전 행 stale), 다시 보이면 새로 연결해 snapshot 으로 통째 교체한다(architecture.md "숨은 화면은 조회하지 않는다"). 행의 `spot`·`perp` 는 표시명으로 바꾼다 — 현물은 003 §3.4 사전, perp 는 `binance_perp→Binance` `bybit_perp→Bybit` `bitget_perp→Bitget` `hyperliquid_perp→Hyperliquid`(모르는 id 는 그대로). 키(`sym|spot|perp`)는 서버 id 기준으로 행마다 한 번만 만든다. 안 실린 행의 `age` 는 서버가 마지막에 준 값으로 되돌린다(017 과 같다).
- 집계(렌더마다 행을 **한 번** 훑어 코인별 누산): `fail` 아닌 행 중 **`entry` 최대 행**(진입 기준)과 **`exit` 최소 행**(정리 기준)을 고른다. 보기 기준의 채택 행 하나에서 현물가·현물 칩·선물 칩·갭·펀딩·`age` 를 전부 가져온다 — 다른 행의 값을 섞지 않는다(003 §3.5 와 같은 이유). `fail` 행뿐인 코인은 fail 행(값 `–`, 항상 뒤). stale = 채택 행 `age ≥ 5`.
- 갭 셀 = 채택 행의 `entry`(진입 기준) 또는 `exit`(정리 기준) — 헤더 문구·정렬 방향(진입 내림차순·정리 오름차순)·임계 판정(진입 `entry ≥ 임계`, 정리 `exit ≤ −임계`)은 002 §3.7 그대로. `현물가 USDT` = 채택 행 `spotPrice`(USDT 표시 형식, 0 은 `–`).
- 펀딩 셀 2줄: `funding` 을 소수 3자리 퍼센트(퍼센트 색 규칙, null 은 `–`) / 남은 시간 = `nextFundingTs − now`(`펀딩 N분 후`·`N시간 M분 후`, null 이거나 지났으면 `–`). **거래소별 펀딩 주기 상수표(1h·4h·8h)는 없앤다** — 주기는 심볼마다 다르고 행의 `intervalH` 가 말한다(이 탭은 `intervalH` 를 표시하지 않는다 — 049 가 시간당 정규화에 쓴다).
- 빈 상태: 행 0 개(`waiting` 포함) → `백엔드에서 갭 표를 받는 중입니다…`. URL 키 `g.*` 는 그대로(검색어 제외).

### 3.7 엣지
- perp 원천 하나가 끊기면 그 원천의 행들이 `age` 로 stale → 흐리게. 현물 거래소 끊김도 같다. 스트림이 돌아오면 다음 표에서 `ok`.
- 한쪽만 있는 코인(현물만·perp 만)은 행이 없다. 우주에서 빠지면 그 초의 표에서 사라지고 다음 delta 의 `removed` 에 실린다.
- 046 이 아직 펀딩을 못 받은 행은 `funding`·`nextFundingTs`·`intervalH` 가 null 이고 `status` 는 호가만 본다.
- 표가 2장 같은 초에 오면 나중 것 기준 diff, 수집 재시작·api 재시작은 017 §3.6 과 같다.

## 4. 검증
네트워크 없음 — 가짜 저장소·가짜 Redis(017 의 fakes 재사용).
- `entry`·`exit` 식: 현물 ask 100·bid 99, perp bid 100.5·ask 100.6 → `entry = 0.5`, `exit = (100.6/99 − 1)×100`. 배수 심볼은 1코인 단위 값끼리 비교된다(현물 PEPE 0.00001 vs perp 행 0.0000101 → 1%).
- 조합: 현물·perp 양쪽에 행이 있는 base 만, `binance × binance_perp` 도 한 행, 국내 거래소 행은 없다. 정렬 `(sym, spot, perp)` — perp 는 원천 순서.
- `status`: 호가 4개 중 하나라도 없거나 가격·잔량 0 → `fail`(`entry`·`exit`·`spotPrice` 0, 펀딩은 실림). `age ≥ 5` → `stale`. 행 `updated_at` 300초 예외. 펀딩 null 행은 `ok` 일 수 있다.
- 표 JSON: 행 키 정확히 11개, 최상위 `rows warnings dataReceivedAt fetchedAt` 4개, `warnings` 는 빈 목록, NaN 이 끼면 인코딩 거부. 4,800행 표 생성 시간을 재서 300ms 경고 문턱과 비교(§5 에 기록).
- 게시: 매 틱 `PUBLISH gap` + `SET gap:latest … EX 10`, Redis 불달이면 경고 1줄·틱은 계속, spreads 게시와 같은 회차에 둘 다 나간다.
- 허브 일반화: spreads 허브의 기존 테스트가 **그대로** 통과하고 바이트가 같다. gap 허브는 채널 `gap`·키 `gap:latest`·경로 `/ws/gap`, 행 키 `sym|spot|perp`, `removed` 원소 형식, 첫 접속 snapshot·`waiting`·heartbeat 1초·느린 접속 1008, 접속자 0명이면 30초 뒤 구독 해지. 두 허브가 서로의 채널을 받지 않는다. `spreads:want` 는 gap 접속으로 갱신되지 않는다.
- nginx 계약 테스트: 허용 목록에 `/api/ws/gap` 정확 일치·업그레이드 헤더, `/api/ws/gap/`·`/api/ws/gapx` 404, 웹이 부르는 경로 대조 통과.
- web: `npm run lint && npm run build`. 집계 — 코인별 `entry` 최대·`exit` 최소 행 채택, 보기 전환 시 모든 셀이 채택 행에서 온다, fail 뿐인 코인은 뒤, stale 반투명, 임계 필터·정렬 방향은 002 §4-5 와 같다, 펀딩 null → `–`, 남은 시간 표기. 탭을 숨기면 연결이 닫히고 다시 보이면 snapshot 으로 교체된다(mock 데이터 코드가 gap 에서 사라진다).
- 수동(실서버): 기동 뒤 `redis-cli GET gap:latest | head -c 400` 에 11키 행, `wscat`(또는 브라우저)로 `/api/ws/gap` 에서 snapshot → 매초 delta, 갭 탭이 실데이터로 돌고 BTC 의 `binance × binance_perp` 갭이 바이낸스 화면의 현물·선물 호가 차이와 맞는다. 실측해 §5 에: 행 수, 표 생성 ms(틱 로그 `갭표`), snapshot 바이트, delta 평균 바이트·행 수, collect 박스 CPU 증가분.
