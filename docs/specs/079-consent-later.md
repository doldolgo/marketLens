# 079 — consent-later

상태: DONE | 의존: 033(동의 창)·032(동의 관리·저장값)·078(처리방침 v8 — 지금 판)·052·073(동의 판정 — attention.js·replay.js)

> 이 문서는 이 기능이 **지금 어떻게 동작해야 하는지**를 적는다. 동작이 바뀌면 이 문서를 직접 고치고, 같은 PR 에서 코드·테스트도 맞춘다(CLAUDE.md §4·§6). 사람이 끝까지 읽는 문서다 — 코드를 산문으로 옮기지 않는다.
> 구현 구조(클래스·함수·파일 내부)는 실행 세션의 몫이다. 여기엔 **무엇이 어떻게 동작해야 하는가**만 쓴다.

## 1. 목적
사람 결정(2026-10-17): 처음 뜨는 동의 창에서 **완전히 거부하는 버튼을 빼고 [하루 동안 안 보기]로** 바꾸고, **[모두 동의]** 버튼을 더한다. 거부는 스스로 찾아오는 처리방침의 '화면 분석 동의 관리' 에만 남긴다(동의 철회는 법 제37조 — 늘 남긴다).

## 2. 범위
- 바꾸는 것: 동의 창 버튼·저장 규칙(`public/clarity.js`), 동의 관리 칸의 저장 규칙·상태 줄(`public/privacy.html` 스크립트), 저장값 하나 더(`kt.analytics.until`), 처리방침 v9(버튼·저장값 문장), 안내 판 올림, 테스트.
- 그대로: 세 칸·알릴 사항(받는 자·항목·목적·보유 기간), 동의 판정(attention.js·replay.js·clarity.js 모두 '지금 판의 granted·GPC 아님' 일 때만 켬), 처리방침 칸의 [모두 거부]·[동의 철회](사람 결정).

## 3. 동작

### 3.1 저장값 (032 §3.3 을 바꾼다)
- `kt.analytics` 값: `granted`(세 칸 모두 동의 — `kt.analytics.v` = 동의한 판) · `later`(하루 동안 안 보기 — `kt.analytics.until` = 다시 물을 시각, epoch ms 글자) · `denied`(처리방침 칸의 [모두 거부]·[동의 철회] — `kt.analytics.v` = 그때의 판).
- '정하지 않음'(동의 창이 뜬다): 값 없음·그 밖의 값·판이 다르거나 없는 `granted`·**`until` 이 지난(또는 없거나 숫자가 아닌) `later`**·**판이 없는 `denied`**(예전 동의 창의 [모두 거부] — 사람 결정: 다시 묻는다).
- 켜는 값은 그대로 `granted`+지금 판뿐 — `later`·`denied` 는 끔. GPC 는 늘 끔·동의 창 없음.

### 3.2 동의 창 (033 §3.3 을 바꾼다)
- 버튼 셋, 이 차례: **[모두 동의]**(채운 강조색 — 사람 결정) · [선택한 대로 저장] · [하루 동안 안 보기](둘은 지금처럼 외곽선). 넓은 화면은 한 줄 세 칸, 좁은 화면(≤599px)은 [모두 동의]가 한 줄을 다 쓰고 아래 두 칸.
- [모두 동의]: 세 칸을 체크로 보이고 [선택한 대로 저장]과 같은 일(판 먼저, `granted`, 창 지우고 곧바로 켬).
- [선택한 대로 저장]: 세 칸 모두면 `granted`. **하나라도 빠지면 `later`(지금 + 24시간)** — 사람 결정, 완전 거부가 남지 않게.
- [하루 동안 안 보기]: 칸과 상관없이 `later`(지금 + 24시간), `kt.analytics.v` 는 지운다. 아무것도 부르지 않는다.
- 쓰기 예외면 창만 지운다(값이 그대로면 다음 페이지에서 다시 묻는다 — 지금과 같음). 닫기(×)·Esc 는 여전히 없다 — 셋 가운데 하나를 고른다.
- 다른 탭·뒤로 가기 캐시(033 §3.5): 창이 떠 있는데 값이 `later`(아직 안 지남)·`denied`(판 있음)가 되면 창만 지운다. 페이지가 열린 채 24시간이 지나도 다시 띄우지 않는다 — 다음에 여는 페이지에서 묻는다.

### 3.3 처리방침 '화면 분석 동의 관리' (032 §3.3 을 바꾼다)
- 버튼은 그대로 [선택한 대로 저장]·[모두 거부]·[동의 철회](사람 결정). [선택한 대로 저장]에서 하나라도 빠지면 동의 창과 같이 `later`(24시간). [모두 거부]·[동의 철회]는 `denied` 와 **그때의 판**을 쓴다(쿠키 지움은 그대로) — 판이 있는 `denied` 는 다시 묻지 않는다.
- 상태 줄: 동의함 · 거부함(판 있는 `denied`) · **'하루 동안 묻지 않음 — <다시 물을 날짜·시각 KST> 뒤 다시 물음'**(아직 안 지난 `later`) · 정하지 않음(그 밖) · GPC로 거부 · 저장할 수 없음.

### 3.4 처리방침 v9
- 시행일 = PR 올린 날 KST `2026-10-17`(다른 날 머지하면 그날로). 상수 `PRIVACY_V9_EFFECTIVE`(test_privacy 가 시행일과 묶는다 — 서버 게이트는 없다). 안내 판 `2026-10-16-2` → `2026-10-17`(clarity.js·attention.js·replay.js·privacy.html 네 곳 — 동의 상자 글이 바뀌어 다시 묻는다), 이전 판 사본 `public/privacy-20261016-2.html`(v8).
- 바꾸는 글: 동의 상자·동의 창 같은 글의 '저장 규칙'(하나라도 빠지면 하루 동안 묻지 않고 다시 묻는다)과 국외 이전 칸 '거부 방법'(이 칸에 체크하지 않으면 이전되지 않는다 — 버튼 이름 없이), '화면 분석 동의 관리' 의 저장 설명(세 값·`until`·판 있는 거부는 다시 묻지 않음·예전 판 없는 거부는 다시 묻는다), 7절 저장 항목에 `kt.analytics.until`·값 `later`, 머리 변경 안내·12절 이력·대조표. 받는 자·항목·목적·보유 기간은 그대로.
- 머지 = 게시. **법률 확인(사람) 뒤 머지** — 볼 것: [모두 동의] 강조(한쪽으로 끄는 화면으로 읽힐 수 있음), 하루 뒤 다시 묻기(거부한 사람을 다시 조르는 꼴), 예전 거부(판 없음)를 다시 묻는 것 — 예전 [동의 철회]도 같은 값이라 가려낼 수 없다.

### 3.5 엣지
- `until` 이 미래로 너무 먼 값(시계를 바꿈·손댐)이면: 지금 + 24시간보다 뒤면 '정하지 않음'(다시 묻는다).
- 저장소 쓰기가 안 되는 브라우저: 지금처럼 동의 창이 뜨지 않는다('저장할 수 없음').

## 4. 검증
- node(clarity.js 가짜 window — test_clarity 꼴): [모두 동의] → 세 칸 체크·granted·지금 판·태그 1 / [선택한 대로 저장] 두 칸 → later·until = 지금+24h·판 없음·태그 0·창 없음 / [하루 동안 안 보기] → later / later 안 지남 → 창 없음, 지남 → 창 / until 없음·숫자 아님·너무 먼 미래 → 창 / 판 없는 denied → 창 / 판 있는 denied → 창 없음 / 다른 탭에서 later → 창만 지움 / 버튼 셋 차례·[모두 동의]만 채운 모양.
- node(privacy.html 스크립트): 두 칸 저장 → later·상태 줄 '하루 동안 묻지 않음 — …', [모두 거부]·[동의 철회] → denied + 지금 판, 판 있는 denied → '거부함'.
- attention.js·replay.js: later 에서 보내지 않음(판정 그대로).
- test_privacy: 판 해시·시행일·이전 판 사본·대조표, 동의 창 글 = 방침 동의 상자 글.
- 브라우저: 랜딩에서 창 → [하루 동안 안 보기] → 새로고침에 창 없음 → until 을 지난 값으로 바꾸면 창.
