## 1. 목적
관리자 화면이 접속 요약을 최근 30일까지 보이고, IP 앞부분으로 나라와 망 종류(국내 통신사·데이터센터 등)를 추정하고, 방문자를 하루 한 번씩 세려면(038·039) 서버 접속 기록을 쓰는 방식이 바뀐다. 지금 방침 2절은 '24시간 요약' 만 적는다. 이 스펙은 처리방침을 고쳐 시행일 7일 전에 게시하고, 그 시행일을 서버 상수 한 곳에 둔다. 서버는 시행일 전까지 지금처럼 24시간 줄 단위 집계로만 돌고, (가린 IP, 브라우저 정보) 짝을 쓰는 처리(방문 세기·나라·망 종류)는 하나도 하지 않는다(038·039 의 날짜 게이트) — 그래서 개정 전 기록에 새 목적을 붙이지 않는다. 이 PR 은 서버 동작을 바꾸지 않는다.

## 3. 동작

### 3.1 시행일 D — 한 곳과 정하는 규칙
- **한 곳**: `server/app/core/config.py` 의 상수 `PRIVACY_V2_EFFECTIVE = "YYYY-MM-DD"`(KST 날짜 — 아래 D). 뜻은 '처리방침 v2 가 시행되는 날 = 접속 요약의 30일 창과 나라·망 종류가 열리는 날' 이다.
  - 이 PR 에서는 앱 코드가 읽지 않고 test_privacy 만 읽는다. 038·039 는 D 00:00 Asia/Seoul(= 전날 15:00Z)을 게이트로 쓰고 응답 `gateAt`(epoch ms)에 싣는다.
  - 다음 개정 때도 이 상수는 그대로 둔다 — v2 기능이 열린 날이라서다. 다음 판의 시행일은 test_privacy 의 `EFFECTIVE` 와 HTML·sitemap 만 바꾼다.
  - 상수 옆 주석은 왜 여기 있는지(038·039 의 게이트, 테스트가 방침 HTML 과 묶는다)를 적는다.
- D 와 같은 값을 갖는 곳: 페이지의 `<time datetime>` 넷(머리·변경 안내·12절 시행 문장·이력 첫 항목), sitemap 의 `/privacy` lastmod, test_privacy 의 `EFFECTIVE`. 테스트가 모두 묶어 한 곳만 고치면 CI 가 멈춘다(§4).
- **정하는 규칙**: D = 037 PR 을 올리는 날(KST) + 9일. 머지 마감 = D − 8 의 18:00 KST 다. PR 제목 끝에 `(머지 마감 MM-DD 18:00 KST)` 를, 본문 첫 줄('무엇을') 끝에 "머지 마감 YYYY-MM-DD 18:00 KST — 넘기면 머지하지 말고 시행일을 미룬다" 를 적는다(본문 3줄 규칙은 그대로). 예: 10-02 에 올리면 D = 10-11, 마감 10-03 18:00.
  - 이 스펙에는 규칙만 둔다. 실행 세션은 실행한 날(KST) + 9일을 임시 D 로 상수·`<time>` 넷·sitemap·`EFFECTIVE` 에 쓴다(push·PR 은 하지 않는다). PR 을 올리는 세션(설계 세션)은 올리는 날 + 9일이 그 값과 다르면 네 곳을 고치는 커밋을 먼저 넣고, PR 제목·본문의 마감과 §7 을 그 값으로 적는다.
  - 머지가 곧 게시는 아니다. 배포가 data → collect → serve 로 이어지고 앞 박스가 실패하면 serve 가 올라가지 않는다. 마감 시각 안에 머지하면 배포를 마친 게시가 D − 7 00:00 KST 보다 앞서, D 00:00 까지 7×24시간 넘게 미리 알린 셈이다.
  - 마감을 넘기면 머지하지 않는다. 실행 세션이 D 를 미루는 커밋(상수·`<time>` 넷·sitemap·`EFFECTIVE`)과 PR 제목 고침을 먼저 넣는다.
  - 배포가 늦거나 실패해 `/privacy` 머리에 D 가 보인 때가 D − 7 00:00 KST 를 넘으면, 곧바로 D 를 미루는 PR 을 올린다. CI 는 머지·게시 시각을 볼 수 없어 이 두 확인만 사람에게 남는다(§4).
- 038·039 는 D 전후 언제 머지해도 된다 — 게이트가 날짜로 연다. 개정 전 기록에는 새 목적을 붙이지 않는다 — 추가적 이용(개인정보 보호법 제15조 제3항) 판단을 피하려는 것이고, 확인한 공식 해석은 없다. 대가로 30일 창은 D+30 부터 꽉 찬다.
- **게이트 전에 하는 것과 안 하는 것**(038·039 가 지킨다):
  - 하지 않는다: (가린 IP, 브라우저 정보) 짝을 쓰는 모든 처리 — 짝을 되돌릴 수 없는 값으로 바꾸기, 확인·브라우저 모양 방문자, 다시 온 방문, WebSocket 짝 수, 나라·망 종류. 모두 D 부터의 KST 날 기록에만 한다. 그 전에는 응답의 짝 값이 비고 상태가 `before_gate` 다.
  - 한다: 035 와 같은 꼴(줄마다 세는)의 집계 — 038 이 넓힌 종류 여덟(사람 브라우저·검색·AI·미리보기·도구·스캐너·운영자·모름 — 운영자 흔적은 출처로 정한다), 탐색 경로, 사람 모양 페이지·스크립트가 돈 페이지 수, 경로·출처·utm·탭, 상태 코드, 시간 막대, 5xx 의 WebSocket·나머지 나눔. 모두 줄마다 세고 짝을 쓰지 않는다.
  - 브라우저 정보로 봇 종류를 나누는 것은 지금 판의 '보안·이용 통계'(2절 처리 근거) 안이라 D 전에도 한다. 새 판 1절의 '자동 요청(봇)의 규모 파악' 은 그 일을 풀어 적은 것이고, 대조표의 '바뀐 점' 칸이 그렇게 밝힌다(§3.2-6).
  - 그래서 변경 안내 상자와 2절 (라)의 '시행일 전 기록에는 쓰지 않는다' 가 서버 동작과 맞는다.

### 3.2 privacy.html — 바뀌는 곳
말투·모양·외부 자원 0·CSP 는 지금 판(032 §3.1·§3.4) 그대로. 날짜가 지나도 맞는 글로 쓴다 — 시행 전후 언제 읽어도 거짓이 아니게.
1. 머리: `시행일 <time datetime="D">YYYY년 M월 D일</time>`(앞 0 없음 — 지금 판과 같은 꼴).
2. 변경 안내 상자 — 머리 시행일 줄 바로 아래, 소개 문단 앞. 제목 '변경 안내'(번호 없는 h2, 앵커 `#changes`), 동의 상자와 같은 바탕. 내용:
   - "이 판은 D부터 시행합니다 — 그 전날까지는 이전 판(2026년 10월 1일 시행)을 따릅니다."
   - 서버 접속 기록을 쓰는 방식에서 바뀌는 것 셋(목록): ① 관리자 화면의 접속 요약 24시간 → 최근 30일까지(서버 메모리에서만, 따로 저장하지 않음) ② IP 앞부분으로 나라·망 종류(국내 통신사·데이터센터 등) 추정 — 공개 자료 DB-IP Lite, 방문자 정보는 밖으로 보내지 않음 ③ 같은 방문을 하루 한 번만 세려고 되돌릴 수 없는 값으로 바꿔 메모리에서만 씀(그날의 시간대·들어온 길·기기·운영체제·브라우저 종류·스크립트를 받았는지·다시 온 방문인지 등을 붙여 최근 30일까지).
   - 목록 바로 뒤: "위 세 가지는 시행일 전의 기록에는 쓰지 않습니다." — 다음 문단도 셋을 늘어놓으므로 가리키는 것이 목록임을 자리와 낱말로 밝힌다.
   - "그 밖에 문장이 바뀐 곳은 1절 목적의 '자동 요청(봇)의 규모 파악'(이전 판의 보안·이용 통계 안에서 하던 일을 풀어 적은 것), 로그 저장소의 90일을 보낸 때부터 세는 것, 한눈에 보기의 지우는 때입니다. 바뀐 문장은 모두 12절 대조표에 전후를 나란히 적었습니다. 화면 분석(Clarity) 동의 내용은 바뀌지 않아 다시 묻지 않습니다."
   - 링크 둘: 이전 판 보기(`/privacy-20261001.html`), 바뀐 문장 전후 대조(`#s12`).
3. 1절 서버 접속 기록 줄: "서비스 제공과 장애·오류 확인, 어떤 경로·나라·망(국내 통신사·데이터센터 등)에서 들어와 얼마나 머무는지와 자동 요청(봇)의 규모 파악(서버 접속 기록)".
4. 2절 '서버 접속 기록' 문단:
   - 저장 위치 문장: 서버 파일과 로그 저장소(Amazon CloudWatch Logs)에 둔다 — 로그 저장소에는 보낸 때부터 90일. 에이전트가 줄의 시각이 아니라 보낸 때로 찍기 때문이다(2026-10-02 처음 켤 때 09-29 부터의 줄이 보낸 시각으로 찍혔다 — 027 §7).
   - '24시간 요약' 문장 하나를 다음 넷으로 바꾼다. 글은 실행 세션이 쓰고 사실은 이대로다.

### 3.5 엣지

- D 전 sitemap: lastmod 가 미래 날짜다. 검색엔진이 무시할 수는 있어도 해는 없다.
- D 까지 038·039 가 머지되지 않으면 방침이 실제보다 앞선다(032 가 033·035 를 미리 적은 것과 같다). 039 를 접으면 처리를 줄이는 변경이라 접는 PR 에서 방침 문장을 함께 고치고 그날 시행한다(12절·032 §3.6).
- 다음 개정: 상수는 그대로 둔다. 새 시행일은 `EFFECTIVE`·HTML·sitemap 에 쓰고, 이 판은 `privacy-<D 의 YYYYMMDD>.html` 로 남기며, 변경 안내 상자는 새 판의 것으로 바꾼다.
- CloudWatch 의 09-29~10-02 줄은 지금 판의 '90일' 과 최대 ≈3일 어긋난다(027 §7). 그 줄이 줄 시각으로 90일을 넘는 ≈12-28 에는 D 가 지나 '보낸 때부터 90일' 판이 시행 중이다. 어긋남은 12절 이력에 사실대로 적고 줄은 지우지 않는다 — 로그 스트림은 줄 단위로 지울 수 없다(§3.2-6).
