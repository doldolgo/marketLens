- 호버 규칙은 전역 클래스로 둔다. 인라인 style 을 이겨야 하기 때문이다.
- 숫자는 전부 `tabular-nums`.

셸·표·KPI·카드·배지의 **구조와 인라인 스타일**(크기·간격·어느 토큰을 쓰는지)은 `docs/design/reference/`(App.tsx·ui.tsx·tabs/ 6개)가 진실이다. 컴파일 대상이 아닌 참조 원본이며 import 대응표는 그 폴더의 README 에 있다. 참조와 이 스펙 문구가 어긋나면 참조 파일이 우선이다. 참조에 없는 동작(003 입출금 배지·망 열, 005 실데이터 등)은 이 레포의 스펙대로 유지하고 겉모습만 참조를 따른다.
- 표는 `<table>` 이 아니라 CSS grid. 탭마다 컬럼 폭 문자열 1개. 행 높이 40px. 헤더는 sticky·10.5px·uppercase·`letter-spacing 0.07em`, 정렬 활성 열은 `accent-300`.
- hot 행 = accent 8% 배경 + 심볼 `accent-300`. stale 행 = `opacity 0.45`. 실패값 `–`.
- 흐린 글자는 `--color-neutral-500`(보조)·`-600`(캡션·kicker) 램프를 쓴다. `color-mix` 로 재해석하지 않는다. 이 규칙은 **글자색**에만 적용된다 — 배경·구분선 강조(hot 행 배경, 토글·칩 배경, 표 행 밑선, 타임라인 트랙)는 참조 원본과 `theme.css` 그대로 `color-mix` 를 쓴다.
- 카드 = surface + `radius-md` + `shadow-sm`. KPI 스트립은 카드가 아닌 flex 스트립이고 블록 사이는 세로 그라디언트 선.
- kicker·card·세로선·grid 표·거래소/상태 배지는 shared 에 한 번만 두고 탭에서 다시 정의하지 않는다. 참조 원본은 탭마다 중복돼 있으니 추출해서 쓴다.

### 3.3 색 규약·stale·숫자 포맷
- **한국식 색 규약**: 빨강=상승, 파랑=하락. 퍼센트 값의 색 = `>0` 빨강, `<0` 파랑, `0` 은 중립. 판정은 **표시 자릿수로 반올림한 값**으로 한다(퍼센트 2자리, 갭 탭 펀딩 3자리, 선선갭 펀딩 4자리) — 글자가 `0.00%` 인데 색만 파랗게 나오지 않게. 공유 색 함수는 `pctColor(v, digits = 2)` 하나다. 반올림 문자열을 숫자로 되읽는 판정은 |v| < 10^−자릿수 인 값에만 한다 — 그 이상은 반올림해도 0 이 아니라 부호가 곧 답이다(표 한 번에 수백 셀이라 모든 값을 되읽지 않는다). 모든 김프·갭·펀딩 수치에 적용한다(퍼센트 색 규칙).
- **stale**: 행의 `age`(마지막 수신 후 초) `>= 5` 면 행 전체를 흐리게 그리고 하이라이트 대상에서 제외. `fail` 상태는 표 맨 뒤로 보내고 값은 `–`.
- 포맷 규칙은 전부 순수 함수이며 아래 예시와 정확히 일치해야 한다.
  1. KRW: `≥100` 반올림 정수 ko-KR 콤마. `≥1` 소수 2자리. 그 외 최대 4자리. 예 `12345678`→`12,345,678`, `2.5`→`2.50`, `0.12345`→`0.1235`.
  2. USDT: `≥1000` 콤마+소수 2. `≥1` 소수 3. `≥0.001` 소수 4. 그 외 소수 8. 예 `118420`→`118,420.00`, `2.91`→`2.910`, `0.0000162`→`0.00001620`.
  3. 퍼센트: 양수는 `+` 접두, 소수 2자리, `%`. 소수 2자리로 반올림한 값이 0 이면 부호 없이 `0.00%`(중립색)이다 — `-0.00%`·`+0.00%` 를 내지 않는다. 기록 탭 차트의 축·십자선 라벨(부호 접두 없음)도 같다. 예 `1.234`→`+1.23%`, `-0.5`→`-0.50%`, `0`→`0.00%`, `-0.004`→`0.00%`, `0.003`→`0.00%`.
  4. 경과: `<60s` `N초 전`, `<60m` `N분 전`, 그 이상 `N시간 전`(반올림). 먼저 표시 단위로 반올림하고, 반올림한 값이 다음 단위 경계(60)에 닿으면 다음 단위로 올린다 — `60초 전`·`60분 전` 은 나오지 않는다. 예 `3.2`→`3초 전`, `400`→`7분 전`, `7200`→`2시간 전`, `59.6`→`1분 전`, `3599`→`1시간 전`.
  5. 수량: `≥1000` 정수 콤마. `≥1` 소수 2. 그 외 소수 4. 예 `1234.5`→`1,235`, `0.5`→`0.5000`.
  6. USD: `null`→`–`. 아니면 `$` + 반올림 정수 콤마. 예 `1234567`→`$1,234,567`.
  7. 펀딩: 갭 탭은 소수 3자리 `%`(예 `+0.012%`). 선선갭은 소수 4자리 `%/h`(예 `+0.0015%/h`). 그 자릿수로 반올림한 값이 0 이면 부호 없이 `0.000%`·`0.0000%/h`(중립색) — 퍼센트와 같은 규칙.
  8. 시각: `M/D HH:mm`(로컬, 월 1-base). 예 `8/23 14:05`.
- 포맷 함수는 로캘·옵션 조합마다 `Intl.NumberFormat` 을 모듈에서 한 번만 만들어 재사용한다 — `toLocaleString(로캘, 옵션)` 은 부를 때마다 포맷 객체를 새로 만들고, 스프레드 표 한 번 그리는 데 수백 번 불린다. 셸의 시계(`HH:MM:SS KST`)와 환율 표기도 모듈에 둔 `Intl.DateTimeFormat`·`Intl.NumberFormat` 하나씩을 쓴다. 출력 문자열은 위 예시와 같다.

### 3.4 피드 계약 (003·005 가 의존하는 유일한 인터페이스)
셸은 **공유 피드 객체 하나**를 모든 탭에 내려준다. 피드가 들고 있는 것:
1. `spreads` — 아래 `SpreadRow[]`. 이 스펙에서는 항상 빈 배열.
2. `rate` — USDT/KRW 암묵환율. `0` = 아직 없음.
3. mock 탭용 데이터(§3.6~3.10)와 mock 사건 목록 `events(per, now)`(아래).

피드는 **"spreads 행 + rate 를 통째로 교체하는 방법"** 을 하나 제공한다. 교체는 받은 행 배열을 그대로 건다 — 행을 복사하거나 파생 조회표를 만들지 않는다(매초 불리는 자리라서, 읽는 곳 없는 파생 맵은 두지 않는다). 이 스펙에서는 교체를 호출하는 곳이 없다(017 구독이 snapshot·delta 마다 호출).
1.5초 tick 마다 모든 행의 `age` 를 1.5 증가시킨다. 폴링이 멈추면 stale 로 드러나게 하기 위해서다.
값의 모양:
- 피드 상태 `FeedStatus` — `ok`·`stale`·`fail` 셋 중 하나.
- 입출금 상태 `IoState` — 열림 / 막힘 / 확인 불가(null) 셋 중 하나. 확인 불가는 초록으로 칠하지 않는다.
- `SpreadRow` — 국내×해외 페어 1개. 003 의 `GET /spreads` 응답 행과 같은 키다. 값:
  - `sym` 코인, `dom` 국내 거래소 표시명, `fx` 해외 거래소 표시명
  - `fwd` 순방향 김프 %, `rev` 역방향 김프 % — 둘 다 **슬리피지 차감 후 순값**이다(003 §3.2). `usd` 해외 USD 가격, `spark` 스파크라인용 최근 값 배열
  - `status` 피드 상태, `age` 마지막 수신 후 초
  - `slipFwd`·`slipRev` 각 방향에서 차감된 폭(%p, 양수 — 원값이 필요하면 `fwd + slipFwd`), `krw` 국내 거래소 최우선 매수호가(KRW)
  - `netDom` 국내 입출금 망 이름(없으면 null)
  - `depDom`·`wdDom`·`depFx`·`wdFx` 국내·해외 입금/출금 상태(`IoState`)

`events(per, now)` — 005(기록/통계)가 실 DB 전에 화면을 채우는 mock 사건 목록. 인자: 조회 기간 문자열 `"<N>h"|"<N>d"|"<N>w"`(해석 불가면 24h — 기록 탭은 `7d`·`30d`·`90d` 를 쓴다)·현재 시각 epoch ms. 반환: 사건 배열. 사건 하나는 `{sym, type, dom, start, durMin, peak}` — `type` 은 김프(`kimp`)·역프(`rev`), `dom` 은 국내 거래소 표시명, `start` 는 시작 시각 epoch ms, `durMin` 은 지속 분, `peak` 는 최고 %.
mock 데이터는 전부 문자열 시드 기반 결정론적 난수로 만든다. 리로드해도 같은 모양이어야 하기 때문이다. tick 의 흔들림만 비결정적이어도 된다.

### 3.5 셸 레이아웃 (세로로 순서대로, 탭 본문만 스크롤)
1. **헤더**.
   - 좌측 로고 `KimpTrack`(Kimp + 보라색 Track, 랜딩 로고와 같은 두 톤) + 깜빡이는 초록 점 + `실시간 수집 중`.
   - 가운데 탭 버튼 6개. id/라벨/순서 고정: `spread` 실시간 스프레드, `history` 기록/통계, `gap` 선물–현물 갭, `pp` 선선갭, `health` 수집 상태, `flow` 입출금 레이더. 활성 탭 = 본문 글자색 + accent 밑줄. 비활성 = 흐린 글자.
   - 우측 현재 시각 `HH:MM:SS KST`(ko-KR 24h). 1.5초 tick 마다 갱신.
2. **KPI 스트립**(가로 스크롤 허용, 라벨은 kicker). 블록 5개:
   - `USDT/KRW 암묵환율` — `rate>0` 이면 `₩1,380.5`(소수 1자리), 아니면 `–`. 출처 feed.rate(이 스펙: 항상 `–`).
   - `BTC 김프 · 순방향` — 퍼센트 색 규칙. spreads 중 `sym==='BTC' && status!=='fail'` 행들의 `fwd` 최대값(김프 최대 행), 없으면 `0`.
   - `BTC 김프 · 역방향` — 같은 방식으로 `rev` 최대값(역프 최대 행).
   - `수집 상태` — 011 §3.7.
   - `추적 페어`(우측 끝) — `{코인 수}개 코인 · {행 수} 페어`. spreads 의 고유 sym 수와 행 수(이 스펙: `0개 코인 · 0 페어`).
   - 블록 사이 세로 구분선은 1번 뒤와 3번 뒤.
3. **탭 본문**. 탭은 한 번 마운트되면 **언마운트하지 않고 숨긴다**. 각 탭의 검색어·필터·드릴다운 상태가 전환 후에도 유지되어야 하기 때문이다. **기록 탭만 처음 볼 때 마운트한다**(`?tab=history` 로 들어오면 곧바로) — 기록 탭 코드(차트 라이브러리 포함)는 첫 화면 번들에서 빠진 별도 청크라서 처음 볼 때 받는다. 받는 동안 그 자리는 비어 있고(대기 문구 없음), 받지 못하거나 기록 탭을 그리다 오류가 나면 그 자리에만 `기록 탭을 불러오지 못했습니다 — 새로고침해 주세요` 를 띄우고 셸·다른 탭은 그대로 둔다. 다시 시도하지 않는다.
   - 숨김 탭은 레이아웃에 참여하지 않는다. 보이는 탭은 컨트롤 바(고정) + 본문(가변, 자체 스크롤).
   - 계속 숨어 있는 탭은 셸의 리렌더(1.5초 tick·매초 표 수신)에서 다시 그리지 않는다 — 보이게 되는 순간 한 번 그려 최신이 되고, 숨은 동안에도 탭 자기 상태(폴링 결과 등)가 바뀌면 그 탭만 스스로 다시 그린다. 보이는 탭 하나만 매초 그리기 위해서다.
   - `spread` 탭은 003 이 채운다. `history` 탭은 005 의 mock 탭이다(실데이터 연결은 후속 스펙) — 셸이 넘긴 선택 심볼을 선택 티커로 보인다.
   - **화면 상태는 URL 쿼리에 실린다** — 새로고침·링크 공유 시 같은 화면. 셸 `tab`·`sym`, 탭별 필터·정렬·토글은 탭 접두어 키(`h.` history, `s.` spread, `g.` gap, `p.` pp, `f.` flow). **URL 은 보이는 화면만 담는다** — 활성 탭의 키만 남고 다른 탭 키는 빠진다(`sym` 은 기록 탭). 숨은 탭의 상태는 메모리에 남아 탭을 오가면 유지되고, 새로고침하면 보이던 탭만 복원된다. 기본값이면 키를 지운다(첫 진입 URL 은 깨끗). `replaceState` 라 뒤로가기 히스토리는 쌓이지 않는다. 허용 밖 값은 기본값으로. 제외 = Enter 로 확정하는 검색 입력(history·flow)·드릴다운 스택·hover. 첫 화면이 기록 탭이 아니면 URL 의 `h.*` 키는 셸이 지운다 — 기록 탭이 마운트돼 있었다면 비활성이라 스스로 지웠을 키다. 지운 값은 메모리에 남겨 기록 탭을 처음 열 때 초기값으로 쓴다(마운트돼 있던 비활성 탭이 값을 들고 있는 것과 같게).
4. **푸터**. `flow` 탭에서는 탭 자체 푸터로 대체.
   - 문구: `암묵환율 = 국내 거래소 USDT/KRW 최우선 매도호가(ask) 기준`, `순방향 = 해외 매수 → 국내 매도 · 역방향 = 국내 매수 → 해외 매도`. 우측 `수집 실패 값은 보간 없이 –로 표시`.

### 3.7 선물–현물 갭 탭
- 행 = 코인 1개. `fail` 아닌 현물×선물 모든 조합의 갭 `((1+prem/100)/(1+off/100) − 1)×100` 중 최대(진입)와 최소(정리)를 채택. 조합이 없으면 fail 행. age = 채택 조합의 현물·선물 age 중 큰 값.
- 컨트롤 바:
  - 심볼 검색(부분 일치, 대소문자 무시). `기준 보기` 분절 `진입 기준`/`정리 기준`. 전환 시 정렬 키도 따라간다. 방향은 진입=내림차순, 정리=오름차순.
  - 숫자 입력 `하이라이트 임계값`(기본 0.5, step 0.1). 토글 `임계 초과만`(진입: 갭 ≥ 임계, 정리: 갭 ≤ −임계).
  - 안내 `양의 갭 = perp > 현물 → 현물 매수 + 선물 숏 · 음의 갭 = 반대 방향`. 우측 `{표시} / {전체} 코인 표시`.
- 표(헤더 sticky). 열 순서: `심볼`, `현물가 USDT`(기준가×(1+off/100)), `진입 갭 · 현물 → 선물`(정리 기준이면 `정리 갭 · …`), `펀딩비`. 갭 열이 가변, 나머지 고정.
- 헤더 클릭 정렬: 같은 열 재클릭 = 방향 반전. 활성 열은 accent + `▾`/`▴`. fail 행·값 없는 행은 항상 뒤.
- 행: 심볼 앞 점, 현물가, `{현물 ex} 현물` 칩 `→` `{선물 ex} 선물` 칩(accent 테두리), 갭은 굵게 + 퍼센트 색. hot 행(fail·stale 아니고 임계 충족) = accent 배경 + 심볼 accent.
- 펀딩 셀 2줄: `+0.0xx%`(퍼센트 색) / `펀딩 N분 후` 또는 `N시간 M분 후`. 주기는 Hyperliquid 1h, Bitget 4h(§3.8 과 동일한 거래소별 주기), 그 외 8h. 현재 시각 기준 남은 시간.

### 3.8 선선갭 탭
- 행 = 코인 1개. `fail` 아닌 선물 거래소 모든 쌍에 대해 두 값을 구한다.
  - 가격갭 `((1+high/100)/(1+low/100) − 1)×100`. high/low 는 prem 높은 쪽/낮은 쪽.
  - 시간당 정규화 펀딩갭 `|fundingA/cycA − fundingB/cycB|`. cyc 는 Hyperliquid 1, Bitget 4, 그 외 8. 거래소마다 펀딩 주기가 달라 시간당으로 맞춰야 비교가 되기 때문이다.
  - 최대 가격갭 쌍과 최대 펀딩갭 쌍을 각각 채택. 최대 펀딩갭 쌍은 `임계 초과만` 토글의 연환산 비교에만 쓰고, 펀딩갭 열의 표시·정렬은 **채택 가격갭 쌍의 펀딩 차**다(§표 참고).
- 컨트롤 바:
  - 검색. 숫자 입력 `가격갭 임계값`(기본 0.3, step 0.1). 숫자 입력 `펀딩갭 임계값 · 연`(기본 20, step 5). 비교는 시간당 펀딩갭×24×365.
  - 토글 `임계 초과만`(가격갭 ≥ 임계 **또는** 연환산 펀딩갭 ≥ 임계).
  - 안내 `perp ↔ perp · 싼 쪽 롱 + 비싼 쪽 숏 · 펀딩비갭은 시간당 정규화`. 우측 표시 건수.
- 표 열 순서: `심볼`, `가격갭`(기본 정렬, 내림차순, 가변 폭), `펀딩갭`.
- 행: 심볼. 가격갭 셀 2줄 = `{low ex}` 칩 `↔` `{high ex}` 칩 + 가격갭(굵게) / `{low ex} 롱 / {high ex} 숏`(보조). 펀딩갭 셀 2줄 = 채택 가격갭 쌍의 펀딩 차 `%/h` / `해당 조합 펀딩갭`.
- hot = 가격갭 ≥ 임계.

## 4. 검증
테스트 러너 없음. 완료 = build 에러 0 + lint error 0(warn 허용) + dev 서버의 index 에 문서 제목 `KimpTrack` 이 있음 + 아래 육안 체크(`localhost:5173`):
1. 헤더: `KimpTrack` + 깜빡이는 초록 점 `실시간 수집 중`, 탭 6개가 §3.5 순서·라벨, 우측 `HH:MM:SS KST` 가 1.5초마다 바뀐다.
2. KPI: `USDT/KRW 암묵환율 –`, `BTC 김프 · 순방향 0.00%`(중립색), `역방향 0.00%`, `수집 상태 3곳 중 N곳 정상`(011 §3.7) + 보조문, 우측 `0개 코인 · 0 페어`.
3. 활성 탭 밑줄이 accent 색, 비활성은 흐린 글자.
4. 갭 탭에 검색어 입력 → 다른 탭 갔다 와도 검색어·정렬이 유지된다.
5. 갭 탭: 24행, 헤더 `진입 갭 · 현물 → 선물 ▾`, 임계 0.5 이상 행 accent 배경, stale 행 반투명, 펀딩 `+0.0xx%` + `펀딩 N분 후`. `정리 기준` 전환 시 헤더 문구·`▴` 로 바뀐다.

7. 선선갭: `가격갭 ▾` 기본 정렬, `A ↔ B` 칩 + `A 롱 / B 숏`, 펀딩갭 `%/h`. `임계 초과만` 토글 후 임계를 올리면(예 0.8) 건수가 준다 — 기본 임계에선 전 행 통과일 수 있다.
8. 수집 상태: 011 §4.
9. 레이더: 코인 칩 9개 → 클릭 시 브레드크럼 `전체 → BTC`, 코인 카드 + 표에서 코인 열 사라짐. 주소 클릭 → 주소 카드. `← 뒤로` 동작. 푸터가 ⚠️ 안내로 바뀐다.
