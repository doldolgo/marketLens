# 060 — privacy-v4

상태: DONE | 의존: main(051·052·053 머지 — 처리방침 v3 시행 2026-10-09). 061 attention-v2 가 이 스펙의 상수 `PRIVACY_V4_EFFECTIVE` 와 동의 안내 판을 쓴다. 고치는 스펙은 032·033·037·038·039·042·051·053(이 레포 주인 담당).

> 이 문서는 이 기능이 **지금 어떻게 동작해야 하는지**를 적는다. 동작이 바뀌면 이 문서를 직접 고치고, 같은 PR 에서 코드·테스트도 맞춘다(CLAUDE.md §4·§6). 사람이 끝까지 읽는 문서다 — 코드를 산문으로 옮기지 않는다.
> 구현 구조(클래스·함수·파일 내부)는 실행 세션의 몫이다. 여기엔 **무엇이 어떻게 동작해야 하는가**만 쓴다.

## 1. 목적
사람 결정(2026-10-09): 서버 접속 기록 쓰임새의 게이트를 없앤다 — 관리자 접속 요약의 30일 요약·날마다 센 방문자·나라와 망 종류(038·039)에 남아 있는 접속 기록 전체(기록을 남기기 시작한 2026-09-29 부터, 로그 보관 기간 안)를 쓰고, 7일·30일 창을 시작 날짜로 자르지 않는다. 화면 요소별 통계(061)를 받을 수 있게 처리방침과 동의 안내를 고친다. 처리방침 12절의 '7일 전 게시' 약속은 이 결정과 맞지 않아 고친다.

## 2. 범위
- 만드는 것: `web/public/privacy.html` v4(같은 날 두 번째 판), 이전 판 사본 `web/public/privacy-20261009.html`(v3), `server/app/core/config.py` 상수 둘(값 바꿈 하나·새로 하나), 동의 안내 판 올림(clarity.js·privacy.html 스크립트·attention.js·보이는 판 글자 — 띠·동의 창 글은 방침 동의 상자와 같은 글), 관리자 화면의 정책·게이트 낱말 정리(§3.5), 테스트.
- 하지 않는 것: 요소별 통계 수집(061) — 방침이 수집보다 하루 이틀 앞설 수 있다(051 과 같다). 038·039 의 게이트 코드 자체를 지우는 것 — 상수를 남은 기록보다 앞선 날로 두어 게이트가 걸리지 않게만 한다(§3.1).

## 3. 동작

### 3.1 게이트 — 없음
- `PRIVACY_V2_EFFECTIVE = "2026-09-01"` — 첫 접속 기록(2026-09-29)보다 앞선 날이라 게이트가 없는 것과 같다(사람 결정 2026-10-09): 남아 있는 기록 전체(로그 보관 기간 안 — 하루 회전 파일 100개·90일, 032)를 30일 요약·날마다 센 방문자·나라와 망 종류에 쓴다. 038·039 가 읽으므로 상수는 두고, 옆 주석에 '게이트 없음 — 남은 기록 전체를 쓴다(사람 결정 2026-10-09)' 를 적는다.
- 새 상수 `PRIVACY_V4_EFFECTIVE = "2026-10-09"` — 화면 요소별 통계(061)를 받기 시작하는 날. 052 의 `PRIVACY_V3_EFFECTIVE`(영역 통계)는 그대로.
- 결과: 배포 뒤 관리자 접속 절의 세 창(24시간·7일·30일)·짝(날마다 센 방문자)·나라와 망 종류가 곧바로 열리고, 7일·30일 시작은 잘리지 않는다(038 의 '게이트로 자름' 은 실제로 일어나지 않는다). 남은 기록이 창보다 짧으면 036 의 '기록 시작 MM-DD HH:mm' 이 보인다 — 30일 창은 10-29 부터 꽉 찬다.

### 3.2 동의 안내 판
- 판 값은 `2026-10-09-2`(같은 날 두 번째 판 — 판 값은 날짜 꼴이 아니어도 된다, 같은지만 본다). clarity.js `NOTICE_VERSION`·privacy.html `VERSION`·attention.js `NOTICE_VERSION`·방침의 보이는 판 글자를 함께 바꾸고 `NOTICE_DIGESTS` 에 새 판을 더한다(예전 판 해시는 둔다). 예전 판(`2026-10-09`) 동의자에게는 동의 창이 다시 묻는다.
- 판 값과 날짜를 맞대던 테스트(`NOTICE ≤ EFFECTIVE` 등)는 '판은 `NOTICE_DIGESTS` 의 마지막 키' 로 고친다.

### 3.5 관리자 화면 글 — 정책·게이트 낱말 없음
- 지금 관리자 화면(`web/admin/` — 064 가 바꾸기 전까지)에서 운영자가 보는 정책·게이트 낱말을 모두 뺀다: 접속 절(042)의 닫힌 버튼 안내('7일·30일은 처리방침 개정 시행 MM-DD 부터')·창 줄 meta('MM-DD 00:00 시행부터 센 n일')·답의 '처리방침 개정 시행 … 부터 센다'·'개정 시행 뒤 센 n일'·'시행 … 부터 센 값이다'·짝 단위 빈 칸('처리방침 개정 시행(MM-DD 00:00) 뒤부터 센다'·'그 전에는 DB-IP 자료를 받지도 않는다')·타일 부제와 나라·망 배지('시행 뒤부터')·날 막대 이름표('개정 전 n일'), 화면 이용 절(053)의 before_gate 글('D 부터 모읍니다(처리방침 v3 시행일)')·머리('시행 전')·요약, 두 절의 '이 절 읽는 법'·'이 칸 뜻' 정적 설명.
