# 026 — day-change

상태: DONE | 의존: 001(collect — 행 `price`), 003(spreads — 행·화면), 009(tick-store — 틱 행), 017(spreads-push — Redis)

> 이 문서는 이 기능이 **지금 어떻게 동작해야 하는지**를 적는다. 동작이 바뀌면 이 문서를 직접 고치고, 같은 PR 에서 코드·테스트도 맞춘다(CLAUDE.md §4·§6). 사람이 끝까지 읽는 문서다 — 코드를 산문으로 옮기지 않는다.

## 1. 목적
스프레드 표에서 코인이 **오늘 얼마나 움직였는지**를 김프와 나란히 보게 한다. 기준은 거래소 앱의 "전일대비"(업비트·빗썸은 UTC 0시 = KST 09시)가 아니라 **KST 00:00** 이다 — 국내 트레이더의 하루 경계에 맞춘다.

## 2. 범위
- 만드는 것: 수집기의 **일중 기준가 장부**(국내 거래소·코인별 KST 00:00 이후 첫 체결가, Redis 에 날짜별 보존) + `/spreads` 행 키 `dayChg` + 스프레드 탭 열 개편(변동율·해외가격·거래소 열 2개).
- 바꾸는 기존 것: 003 행 18→19키(`dayChg` 맨 뒤)와 §3.5 열 순서, 017 snapshot·delta 행도 19키, db.md Redis 키 1개.
- 하지 않는 것: 해외 가격 변동율, 24시간 변동율, 거래소 ticker 의 전일대비 필드 사용, 배포 첫날 Influx 백필(아래 §3.1 한계).

## 3. 동작

### 3.1 기준가 장부 (수집 프로세스)
- 대상 = 국내 거래소(`upbit`·`bithumb`) × 코인. 값 = 틱 행의 국내 `price`(001 — 마지막 체결가, 없으면 호가 중간값).
- 하루 = **KST(UTC+9) 달력일**. 매 틱: 틱 시각의 KST 날짜가 장부 날짜와 다르면 장부를 비우고 새 날짜로 바꾼다. 그 뒤 장부에 없는 (거래소, 코인)은 **그 틱의 `price`(> 0)** 로 못 박는다. 한 번 잡힌 값은 그날 안에 바뀌지 않는다.
- 보존: Redis 해시 **`dayopen:<YYYY-MM-DD>`** — field `<거래소>:<코인>`, value 가격(문자열), TTL 48시간. 새로 못 박힌 항목은 그 틱 뒤 별도 태스크가 한 번에 HSET + EXPIRE 한다. 실패하면 경고 1줄(10분 억제)을 남기고 항목을 남겨 뒀다가 다음 틱에 다시 보낸다.
- 기동 직후와 날짜가 바뀐 직후엔 그 날짜의 해시를 **먼저 읽는다(HGETALL)**. 읽기가 끝나기 전엔 새 항목을 못 박지 않는다 — 재기동 직후 가격이 자정 가격을 덮어쓰면 안 되기 때문이다. Redis 를 못 읽으면 경고 1줄 뒤 메모리만으로 진행한다(그 경우 기준 = 첫 관측 시각 가격).
- 결과: 수집기가 낮에 재기동해도 자정 기준가가 유지된다. 한계: **최초 배포일·Redis 소실 시**엔 기준이 첫 관측 시각 가격이라 그날 변동율은 자정 대비가 아니다 — 다음 자정부터 정상.

### 3.2 `/spreads` 행 `dayChg`
- 행 국내 거래소·코인의 기준가를 R, 그 행 국내 `price` 를 P 라 할 때 `dayChg = (P / R − 1) × 100`(%, 소수 그대로). R 없음·R ≤ 0·P ≤ 0 이면 **null**. `status=fail` 이어도 계산한다(입출금처럼 호가와 무관).
- 행 키 **19개**: 003 의 18키 + `dayChg`(맨 뒤). 017 의 snapshot·delta 행도 같다. **null 은 0% 가 아니다** — 화면은 `–`.

### 3.3 화면 — 스프레드 탭 열 (003 §3.5 의 열 문단 대체)
열 순서: **심볼 | 변동율 | 국내가격 | 해외가격 | 해외거래소 | 국내거래소 | 김프(또는 역프) | 입출금 | 네트워크**. 국내가격 열만 가변 폭.
열 값은 전부 **그 보기의 최대 행** 하나에서 온다 — 김프 보기 = 김프 최대 행, 역프 보기 = 역프 최대 행. 국내가격도 예외가 아니다(역프 보기에서 김프 최대 행의 가격을 쓰면 국내거래소 태그와 다른 거래소의 가격이 보인다).
- 변동율 = 보기 기준(김프/역프) 최대 행의 `dayChg`. `+1.23%` 꼴, 퍼센트 색 규칙(양수 빨강·음수 파랑·0 중립). null 이면 `–`.
- 국내가격 = 보기 기준 최대 행의 `krw` 를 `₩` + KRW 표시 형식으로(003 §3.5). 해외가격 = 보기 기준 최대 행의 `usd` 를 `$` + USDT 표시 형식으로. fail 이거나 0 이면 `–`.
- 해외거래소·국내거래소 = 최대 행의 거래소 태그(김프 셀에 있던 `출발 → 도착` 태그가 이 두 열로 나온다). 김프 셀은 `슬 −N.NN%p` 배지 + 값만.
- 정렬: 새 열 전부 헤더 클릭. 변동율·해외가격은 숫자(새 키 클릭 시 내림차순, null 은 뒤), 해외거래소·국내거래소는 이름 오름차순(심볼·네트워크와 같은 규칙).

## 4. 검증
기준가 장부 (Redis 는 fakeredis):
- 읽기가 끝난 뒤 첫 틱의 국내 `price` 가 못 박힌다 / 같은 날 다음 틱의 다른 가격은 덮지 않는다
- KST 자정을 넘는 틱(예 2026-09-26 23:59:59 KST → 00:00:00 KST)은 장부를 비우고 새 가격으로 잡는다
- 기동 시 Redis 해시 `dayopen:<오늘>` 에 값이 있으면 그 값이 기준이고 현재가로 덮지 않는다
- 읽기가 끝나기 전 틱은 아무것도 못 박지 않는다 / Redis 가 없으면 경고 뒤 메모리만으로 진행한다
- 못 박힌 항목이 `dayopen:<날짜>` 해시에 `<거래소>:<코인>` → 가격으로 쓰이고 TTL 이 48시간이다
- 해시 필드는 국내 거래소만 (`binance:` 같은 필드 없음)
`/spreads` 행:
- 기준가가 있으면 `dayChg` 가 수식대로, 없으면 null / 키 19개(§3.2) / `status=fail` 행도 값이 있다
web: `npm run lint && npm run build`, 스텁으로 열 9개·정렬·`–` 육안.
web 열 값 출처: 운영 표 3장 × 보기 2 × 국내 3 × 해외 3 에서 국내가격이 거래소 태그가 가리키는 행의 `krw` 와 같다 — 역프 보기 포함(node). 헤드리스 스텁 역프 보기 399코인 어긋남 0.
