## 1. 목적
운영자가 관리자 접속 절에서 서버 기록을 24시간·7일·30일로 골라 '몇 명 → 사람인가 봇인가 → 어디서 → 언제 → 무엇을 → 문제는 없나' 를 위에서 아래로 읽는다. 덩어리마다 첫 줄에 데이터로 만든 답 문장이 있고, 숫자·그림은 그 근거다. 사람 수는 늘 확인(하한)과 브라우저 모양(상한)을 함께 보이고, 처리방침 개정 시행 전에 세지 않는 값은 '시행 뒤부터' 로 비워 둔다.

## 3. 동작

### 3.1 읽는 값 (038·039 복사)
- 요청: `/svc/api/admin/access?window=24h|7d|30d`(관리자 nginx 가 쿼리를 넘긴다). 인자 없음·목록 밖·지금 고를 수 없는 창이면 서버가 24시간으로 답한다(오류 없음). 부분 하나 `{state, code, fetchedAt, refreshSec(60), …}` — 036 §3.2 공통 규칙.
- 늘 실림(상태 무관): `window`(실제로 답한 창), `windows`(지금 고를 수 있는 창 — 시행 전 `["24h"]`, 뒤 `["24h","7d","30d"]`), `gateAt`(ms — `PRIVACY_V2_EFFECTIVE` 00:00 KST).
- 줄 단위 값(시행 전에도 있다): `startTs`(7d·30d 는 max(창 시작, 게이트))·`endTs`·`firstTs`(초), `totals{requests, pages, humanPages, jsViews, probes, ws, skipped}`, `hourly[{ts, requests, pages, humanPages, jsViews, errors, wsErrors}]`(시마다 ≤720, `errors` 는 `/api/ws/spreads` 밖 5xx), `status{"2xx","3xx","4xx","5xx","ws5xx"}`, `recent5xx[{ts, path, status}]`(WS 뺌), `ws{count, errors, durations{lt10s, lt1m, lt10m, lt1h, ge1h}}`, `classes`(여덟 `{requests, pages}`), 상위 목록 `paths`·`tabs`·`referrers`·`utmSources`·`devices`·`browsers`(`[[이름, 수]]` — 사람 브라우저 모양 페이지 줄만).
- 짝 단위 값(시행일 KST 날의 줄부터만 — 짝 게이트): `visitors` 하위 부분 `{state, code, sinceTs, confirmed, shaped, returning, capped, days[{ts, confirmed, shaped, returning}], channels, devices, os, browsers, inApp}`(목록은 `[[이름, confirmed, shaped]]`, shaped 내림차순, 0 행 없음)와 `ws.pairs`. 시행 전에는 `visitors` 가 `unconfigured`·`before_gate`(값 null)이고 `ws.pairs` null. 뒤에는 `sinceTs` = max(`startTs`, 게이트 초) — 24시간 창이 시행 전 시간을 품어도 짝 값은 그때부터 센 것이다.
- `geo` 하위 부분(039) `{state, code, month, loadedAt, sinceTs, countries, networks, ipv6}` — `countries` `[[ISO 두 글자, c, s]]` 20행 + `["(기타)", c, s]`(작은 수는 서버가 합친다), `networks` `telecom_kr`·`telecom`·`cloud`·`other`·`unknown`(KR 이 `(기타)` 에 합쳐진 창에서는 `telecom_kr` 이 `telecom` 에 든다). 시행 전 `unconfigured`·`before_gate`, 받는 중 `pending`, 판 없음 `error`(`http_<n>`·`timeout`·`bad_data`). 접속 부분이 ok 가 아니면 `visitors`·`geo` 는 null.
- 낱말: 방문자 수는 KST 하루마다 따로 센 (가린 IP, 브라우저 정보) 짝의 합이다. 화면은 이것을 **'날마다 센 방문자'**(줄여 '방문자(날마다 셈)')라 부르고 '방문자-일' 은 쓰지 않는다. 응답 키 이름은 그대로다.

### 3.2 창 고르기·부르기
- 창 줄: 버튼 셋 `24시간`·`7일`·`30일`(HTML 고정 — 첫 응답 전에는 7일·30일 `disabled`)과 meta. 기본 24시간. 고른 창은 JS 변수에만 둔다(주소·브라우저 저장소 없음 — 새로고침하면 24시간). 고른 버튼은 `aria-pressed`.
- 버튼은 응답 `windows` 에 든 창만 연다. 닫힌 버튼 옆에 '7일·30일은 처리방침 개정 시행 MM-DD 부터'. 화면의 시행일 글자(MM-DD)는 늘 `gateAt` 의 KST 날짜다.
- 느린 묶음(60초)은 접속 경로를 늘 `?window=<고른 창>` 으로 부른다. 버튼을 누르면 접속 경로 하나만 곧바로 부른다 — 같은 요청 함수(헤더·만료 판정·여덟 경로 셈 그대로), 다른 일곱 경로와 느린 묶음의 다음 시각은 그대로다.
- 접속 호출이 떠 있으면 겹쳐 부르지 않고 끝난 뒤 한 번 부른다(그 사이 여러 번 누르면 마지막 창만).
- 바꾸는 순간 덩어리 여섯을 '… 7일 불러오는 중' 상태 글로 비운다 — 다른 창의 값을 새 창 이름 아래 두지 않는다. 고른 창으로 요청한 응답만 그린다.
- 응답 `window` 가 요청한 창과 다르면(서버가 24시간으로 답함) 변수와 버튼을 응답 창으로 되돌린다. 화면을 연 채 시행일이 지나면 다음 응답의 `windows` 로 버튼이 열리고, 창은 그대로다.
- meta: 'MM-DD HH:mm ~ 지금 · 60초마다 · n초 전 값 · 읽지 못한 줄 n'(시작 = `startTs`). 7일·30일 시작이 시행일로 잘렸으면 시작 대신 'MM-DD 00:00 시행부터 센 n일'. `firstTs` > `startTs` 면 '기록 시작 MM-DD HH:mm'(036 규칙).

### 3.4 덩어리별 칸
- **① 몇 명**: 큰 범위 숫자 'a ~ b'(7일·30일은 하루 평균 소수 1자리 '명/일', 24시간은 합 '방문자(날마다 셈)'). 그 아래 하한–상한 띠 한 줄(회색 전체 = 브라우저 모양, 보라 = 확인 비율)과 양 끝 글 '적어도 이만큼은 사람 — 확인 a'·'많아야 이만큼 — 브라우저 모양 b'. 타일 셋: 다시 온(`returning`, '확인의 n%'), 스크립트가 돈 페이지(`jsViews`, '사람 모양 페이지 n 중'), 사람 모양 페이지(`humanPages`, '위장 봇 섞임'). `capped` 면 답 아래 ▲ 줄(§3.8). '지금 열린 대시보드' 타일은 두지 않는다(실시간 카드와 겹친다).
- **② 누가**: 걸러 내기 줄 다섯(HTML) — 모든 요청 → 페이지 → 사람 모양 페이지 → 스크립트가 돈 페이지 → 확인 방문자(날마다 셈). 둘째~넷째 칸에 앞 칸 대비 %, 마지막 칸은 '1명이 평균 n쪽'(jsViews ÷ confirmed, 소수 1자리). 종류 여덟 표(고정 순서 browser·search·ai·preview·tool·scanner·operator·unknown — 이름·요청 비율 막대·'요청 · 페이지', 0 행 흐림)와 그 아래 '탐색 경로 n줄(요청의 x%)'. 위장 봇 단서 셋: 스크립트가 한 번도 돌지 않은 브라우저 모양(shaped − confirmed), 데이터센터·클라우드 망의 브라우저 모양(`geo.networks` cloud 의 s, '그중 확인 c' — §3.8 geo 글이 있으면 그 뒤에 함께), 운영자 흔적 요청(`classes.operator.requests`, '방문자에서 뺐다').
- **③ 어디서**: 첫 줄 셋 — 나라(`geo.countries`, `Intl.DisplayNames(['ko'], {type:'region'})` 한국어 이름 + ISO 두 글자 작게), 망 종류(`geo.networks`, 다섯 고정 순서), 들어온 길(`visitors.channels` 아홉). 셋 다 겹친 두 막대. 둘째 줄 — 앱 안 브라우저(`visitors.inApp`, 겹친 두 막대), 외부 출처(`referrers`)·utm(`utmSources`)은 한 막대 + %(분모 `totals.humanPages`, '페이지 줄 기준'). 바닥 — geo 상태 배지(ok 면 '자료 YYYY-MM 판 · n시간 전 올림 · MM-DD HH:mm 부터 셈 · IPv6 n')와 `index.html` 고정 링크 `IP Geolocation by DB-IP` → `https://db-ip.com`(`rel="noreferrer"` — 039 의 CC BY 표시, 상태와 무관하게 늘 보인다).
- **④ 언제** — 24시간: 시간 막대 24(회색 = 사람 모양 페이지, 그 안 진한 막대 = 스크립트가 돈 페이지, 빨강 = `errors` 겹침·최소 높이). `wsErrors` 는 막대 title 에만. 눈금은 정시 0·6·12·18시(브라우저 시간대)와 '지금'. 아래 한 줄 '요일×시간 열지도와 날 막대는 7일·30일 창에서'.
- **④ 언제** — 7일·30일: (가) 날 막대 — KST 날마다 확인 막대, 다시 온은 그 아랫부분을 진한 색으로 겹친다. 칸은 시행일로 자르기 전 창(`endTs` 가 든 시 시작 − (N−1)시간, N = 168·720)이 덮는 KST 날 전부이고, 시행 전 날들은 §3.8 의 회색 덩어리. (나) 그 아래 브라우저 모양 얇은 줄 — '눈금 따로 · 최고 n'. (다) 요일×시간 열지도 — `hourly.jsViews` 를 브라우저 시간대의 (요일 월~일, 시 0~23) 칸 7×24 에 더한다. 강도 = 0 이면 h0, 아니면 ⌈값 ÷ 최댓값 × 5⌉(h1~h5). 오른쪽에 요일 합(HTML), 아래에 시간 합 막대, 단계 견본('적음 … 많음(최고 n)').
- **⑤ 무엇을**: 많이 연 경로(`paths`, 한 막대 + % — 분모 `humanPages`, 부제 '사람 모양 페이지 줄'), 대시보드 진입 탭(`tabs`, 041 의 탭 이름표, 분모 `tabs` 합), 기기(`visitors.devices`, 겹친 두 막대). 접힌 칸 둘 — 'OS·브라우저 — 방문자 기준'(`visitors.os`·`browsers`), '기기·브라우저 — 페이지 줄 기준'(상위 목록 `devices`·`browsers`).
- **⑥ 문제**: 응답 표 — 2xx·3xx·4xx·5xx·대시보드 재접속 실패(`ws5xx`), 막대(요청 대비)·수·%, 빨강은 5xx 행에만. 표 아래 '탐색 경로 n줄'. 대시보드 연결 — 수 셋: 끝난 연결(`ws.count`, 부제 '연결 수 — 사람 수가 아니다')·연결한 방문자(`ws.pairs`, 날마다 셈)·재접속 실패(`ws.errors`). 지속 다섯 막대는 '지속 시간 — 머문 시간이 아니다' 접힘 안에. 최근 5xx 접힘(요약 '최근 5xx n건 — 대시보드 재접속 실패 제외').

### 3.5 답 문장 틀
덩어리 첫 줄 `p.answer` 에는 아래 틀만 쓴다. 글자는 textContent 로 넣고 `{…}` 자리는 `b` 요소(굵게)다. 갈래 — `24h` 시행 뒤 24시간 창, `기간` 7일·30일, `전` 시행 전(`windows` 가 `["24h"]`). 번호만 적은 틀은 세 갈래 공통이다.

- `①-24h`: `확인 {a}, 브라우저 모양 {b}(날마다 센 방문자) — 오늘·어제(KST)를 따로 세어 더한 수라 사람 수가 아니다.`
- `①-24h꼬리`: `시행 {D} 00:00 부터 센 값이다.`
- `①-기간`: `{기간} 동안 스크립트가 돈 방문자는 하루 평균 {a}명, 브라우저 모양까지 치면 {b}명 — 실제 사람은 이 사이다. 확인의 {c}%는 다시 온 사람이다.`
- `①-전`: `방문자는 처리방침 개정 시행 {D} 00:00 부터 센다. 지금은 줄 수만 — 사람 모양 페이지 {h}, 그중 스크립트가 돈 페이지 {j}.`
- `②`: `요청 {r}줄 가운데 사람 브라우저 모양은 {p}%다. 자동 요청은 {k1}({p1}%)·{k2}({p2}%) 순으로 많다. 사람 모양 페이지 가운데 스크립트가 돈 것은 {q}%다.`
- `③-24h·기간`: `확인의 {kr}%는 국내 통신사 망에서 왔다. 데이터센터·클라우드 망은 브라우저 모양의 {cl}%이고 그중 확인은 {cc}다. 들어온 길은 {c1} {x1}%·{c2} {x2}%·{c3} {x3}% 순이다.`
- `③-전`: `나라·망 종류와 들어온 길은 처리방침 개정 시행 {D} 00:00 부터 센다. 지금은 외부 출처·utm 만 페이지 줄로 보인다.`
- `④-24h·전`: `최근 24시간 중 화면이 가장 많이 뜬 때는 {H}시({j}회)다. 스크립트가 돈 페이지 보기 {J}회, 사람 모양 페이지 {P}회.`
- `④-기간`: `화면이 실제로 뜬 페이지 보기는 {h1}~{h2}시에 가장 몰린다. 가장 많은 칸은 {요일} {h}시({v}회). 날마다 확인 방문자는 {lo}~{hi}명이다.`
- `⑤`: `사람 모양 페이지는 {u1} 경로가 {x1}%로 가장 많고, 대시보드는 {t1} 탭으로 들어온 경우가 {y1}%다. 기기는 {d1} {z1}%({기준}).`
- `⑥`: `서버 오류(5xx)는 {e}건, 대시보드 재접속 실패는 {w}건이다. 4xx 는 {f}건, 탐색 경로 요청은 {pr}줄이다.`

- 수는 천 단위 쉼표, % 는 정수 반올림. 하루 평균 = 합 ÷ ((endTs − sinceTs) ÷ 86,400), 소수 1자리. 분모가 0 이거나 목록이 비어 못 만드는 조각(문장·쉼표로 나뉜 절)은 빼고 나머지만 쓴다 — 다 빠지면 '기록 없음'.
- `{D}` = 시행일 MM-DD. `{기간}` = 창 시작이 시행일로 잘렸으면 '개정 시행 뒤 센 n일', 아니면 '최근 n일'(n = (endTs − startTs) ÷ 86,400 올림). `①-24h꼬리` 는 `visitors.sinceTs` > `startTs` 일 때만 한 칸 띄고 붙인다.
- 자리: ① `{a}`·`{b}` = confirmed·shaped(24h 는 합, 기간은 하루 평균), `{c}` = returning ÷ confirmed, `{h}`·`{j}` = humanPages·jsViews. ② `{p}` = `classes.browser.requests` ÷ requests, `{q}` = jsViews ÷ humanPages, `{k1}`·`{k2}` = browser 밖 종류의 요청 상위 둘, `{p1}`·`{p2}` = 그 둘의 요청 ÷ requests. ④ `{J}`·`{P}` = jsViews·humanPages 합. ⑤ `{u1}`·`{t1}` = `paths`·`tabs` 첫 행(`{x1}`·`{y1}` 의 분모 humanPages·`tabs` 합). ⑥ `{e}`·`{w}`·`{f}`·`{pr}` = `status` 5xx·ws5xx·4xx·`totals.probes`. ③: 망 % 의 분모는 `networks` 합(확인은 confirmed 합, 모양은 shaped 합), 들어온 길은 confirmed 상위 셋·분모 `channels` confirmed 합. `networks` 에 `telecom_kr` 행이 없으면(KR 이 `(기타)` 라 서버가 `telecom` 에 합쳤다) 첫 문장을 뺀다. geo 가 ok 가 아니면 앞 두 문장 대신 '나라·망 종류는 자료를 받는 중이다.'(pending)·'나라·망 종류 자료를 받지 못했다({code}).'(error).
- ④-24h: `{H}` = jsViews 가 가장 많은 시(같으면 이른 시). 합이 0 이면 '최근 24시간 동안 스크립트가 돈 페이지 보기가 없다. 사람 모양 페이지 {P}회.' ④-기간: `{h1}` = 시간 합에서 이어진 세 시간 합이 가장 큰 시작 시(자정을 넘겨 잇는다, 같으면 이른 시), `{h2}` = `{h1}`+3(24 를 넘을 때만 24 를 뺀다 — 21 시작 '21~24시', 22 시작 '22~1시'). 가장 많은 칸 = 열지도 최댓값(같으면 월요일·이른 시). 날마다 범위 = 오늘(KST)을 뺀 `days` 의 confirmed 최소~최대.
- ⑤: `{d1}` — 시행 뒤 `visitors.devices` confirmed 상위·`{기준}` '확인 방문자 기준', 시행 전 상위 목록 `devices`·'페이지 줄 기준'.
- 평가 낱말은 규칙으로만 단다: ①(24h·기간) shaped > 0 이고 confirmed ≤ shaped × 0.1 이면 끝에 ' 브라우저 모양의 대부분은 봇이다.' / ③ cloud 확인 ≤ cloud 모양 × 0.1 이면 `{cc}다` 를 `{cc}뿐 — 대부분 봇이다` 로 / ⑥ 5xx 가 0 이면 첫 절을 '서버 오류(5xx)는 없었고', ws5xx > 0 이면 `{w}건` 뒤에 '(배포 때 몇 건은 정상)'. 그 밖의 평가·짐작 낱말은 쓰지 않는다.

- 행 이름은 아래 한국어 이름표다. 서버가 모르는 키를 보내면 원래 글자 그대로(글자로만) 둔다. 한 줄 뜻은 title(보조)이고, 원래 키는 행에 쓰지 않고 '이 칸 뜻' 과 title 에만 둔다(나라만 ISO 를 작게 함께) — 아래 이름표 일곱의 키는 모두 접속 절 '이 칸 뜻' dl 에 `<code>` 글자로 있다(휴대폰은 title 을 못 본다).

- 041 이 둔 접속 절 '이 절 읽는 법' 의 서버 기록 쪽을 고쳐 쓴다(첫 dt 둘 '읽는 값'·'판정' 은 041 꼴 그대로): 읽는 값에 서버 기록 60초·창 셋과 시행일, 판정에 '종합 판정에 들지 않는다', 뒤 항목에 서버 기록(caddy 기록을 api 가 메모리에서 센 요약, 저장 없음)·날마다 센 방문자·확인/모양·시각. summary 꼬리에 '· 서버 기록 60초'. Clarity 쪽은 041·043 몫이다.
- 글 제약: `admin.js` 에 SCRIPT_BANNED 부분 문자열(`.style`·`.src`·`.href` 등)·`://`·`explain`·`terms` 글자를 넣지 않는다(036·041 단언). 설명 dl 에는 링크·`://`·12자리 숫자·이메일 모양·32자 이상 16진을 넣지 않는다 — DB-IP 링크는 설명 밖 ③ 바닥에 둔다.

### 3.7 그림·색
- SVG 요소는 svg·g·rect·line·path·title, 속성은 036 허용 목록 그대로다(색·강도는 클래스). 그림 안에 글자를 두지 않는다 — 글자는 모두 HTML. 모든 SVG 에 role·aria-label(방문자 글자 없이), 막대·칸마다 title.
- 쓰는 그림: 겹친 두 막대(같은 눈금 — 바깥 rect 브라우저 모양, 안쪽 얇은 rect 확인), 하한–상한 띠(rect 둘), 시간 막대·날 막대, 열지도(rect + 강도 클래스), 지속 막대(036 세로 막대). 걸러 내기 줄은 HTML.
- 색(토큰 이름 — 값은 theme.css): 확인 `--color-accent-400`, 브라우저 모양 `--color-neutral-700`, 다시 온 `--color-accent-600`, 봇 종류 행 막대 `--color-neutral-600`(사람 브라우저 모양 행만 accent-400). 열지도 강도 h1~h5 = accent 700·600·500·400·200(밝을수록 많다 — 클래스 이름 `h0`~`h5`, 043 의 랜딩 도달 단계도 이 클래스를 쓴다), h0 과 시행 전 덩어리는 막대 바탕색(시행 전 덩어리는 범례 견본처럼 `--color-neutral-700` 테두리). ⑥ 응답 표·지속 막대는 `--color-neutral-600`(뜻 없는 수량 — accent 는 확인·다시 온 뜻이다).
- 상태색은 상태에만: 장애색 ✕ 는 5xx(수·행·막대 겹침), 주의색 ▲ 는 geo error·지난달 판·`capped`·오래됨. 색에만 기대지 않는다 — 확인/모양은 늘 'a / b'(a 굵게)로 적고 범례 글을 둔다.

### 3.8 빈 상태
- 시행 전: 7일·30일 버튼 disabled + 안내(§3.2). 짝 단위 칸(① 범위 숫자·띠·다시 온, ② 마지막 칸·단서 앞 둘, ③ 나라·망·들어온 길·앱 안 브라우저, ⑤ 방문자 기준 기기·OS·브라우저, ⑥ 연결한 방문자)은 '—' 또는 한 줄 '처리방침 개정 시행(MM-DD 00:00) 뒤부터 센다' — 나라·망 칸은 끝에 ' 그 전에는 DB-IP 자료를 받지도 않는다'. 줄 단위 칸은 값을 그린다. ④ 는 시간 막대만.
- 7일·30일 시작이 시행일로 잘림: 날 막대 왼쪽의 시행 전 날들을 회색 덩어리 하나(rect 하나 — 날마다 칸을 그리지 않는다)로 두고 HTML 이름표 '개정 전 n일 — 세지 않음 · MM-DD 부터 {7|30}일이 다 찬다'. n 이 8 미만이면 덩어리 위 이름표 없이 범례에만 '개정 전 n일 — 세지 않음'.
- geo(시행 뒤): pending '자료 받는 중 — 다음 갱신(60초)에 찬다', error ▲ '받지 못함({code}) — 6시간 뒤 다시', 지난달 판(`month` 가 지금 UTC 달보다 이른 판) ▲ '지난달 판 YYYY-MM 으로 셈'. 나라·망 칸과 단서 cloud 줄에 같은 글.
- `capped` ▲ '짝 기록이 1,000에 닿은 날이 있다 — 방문자 수가 실제보다 적다'. 시행 뒤 `visitors` 가 ok 가 아니면 036 §3.5 상태 글.
- 목록 0행 '기록 없음'. 접속 부분 전체가 ok 가 아니면 덩어리 여섯 모두 036 §3.5 상태 글이고, 창 줄은 실린 `windows`(없으면 24시간만)로 그린다.

### 3.9 좁은 폭
- 타일: 640px 이하 2열, 넓으면 한 줄(① 은 범위 숫자 + 타일 셋). 960px 이하에서 ① 범위 숫자 타일은 한 줄을 다 쓰고, 범위 숫자는 '~' 뒤에서만 줄을 바꾼다(옆 타일을 덮지 않는다).
