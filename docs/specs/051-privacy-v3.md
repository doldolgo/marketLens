## 1. 목적
관리자 화면에서 "화면의 어느 영역을 많이 보고 적게 보나" 를 보려고(052·053), KimpTrack 서버가 화면 분석에 동의한 방문자의 **화면 영역 이용 통계**(영역마다 화면에 보인 시간·1초 이상 보였는지·클릭 수 — 하루 합계로만)를 모은다. 새 처리라 처리방침과 동의 안내를 고치고, 동의 안내의 판을 올려 이미 동의한 방문자에게 다시 묻는다.

## 2. 범위
- 만드는 것: `web/public/privacy.html` 개정(v3), 이전 판 사본 `web/public/privacy-20261011.html`, sitemap `/privacy` lastmod, `server/app/core/config.py` 상수 `PRIVACY_V3_EFFECTIVE`, 동의 안내 판 `NOTICE_VERSION` 올림(`web/public/clarity.js`·privacy.html 스크립트·보이는 판 글자), **clarity.js 동의 띠의 글**(첫 문장·저장 규칙 문장·칸마다 알릴 사항 — 띠와 방침 동의 상자는 같은 글이어야 한다, test_clarity `test_strip_text_is_the_policy_consent_box_text`·test_privacy `SHARED_SENTENCES`), `server/tests/test_privacy.py`·`test_clarity.py` 단언.
- 하지 않는 것: 수집·저장·관리자 화면(052·053). 동의 세 칸의 구조와 판정 — 지금처럼 세 칸 모두 체크해야 `granted` 이고, 그때 Clarity 와 KimpTrack 영역 통계가 **함께** 돈다(영역 통계만 따로 켜는 칸은 두지 않는다 — 033 의 상태 기계를 바꾸지 않으려는 것).

- 사람 결정(2026-10-09): 자료 = 우리 서버가 직접 모은 영역별 통계, 동의한 방문자만, 모든 화면(랜딩·대시보드 탭 여섯·처리방침·검색어 페이지 둘).

## 3. 동작

### 3.1 시행일 D — 037 규칙 그대로
- 한 곳: `config.py` 상수 `PRIVACY_V3_EFFECTIVE = "YYYY-MM-DD"`(KST 날짜). 뜻은 '영역 통계를 받기 시작하는 날'. `PRIVACY_V2_EFFECTIVE` 는 그대로 둔다(038·039 게이트). 상수 옆 주석에 052 게이트와 test_privacy 대조를 적는다.
- D 와 같은 값: 페이지의 `<time datetime>` 넷(머리·변경 안내·12절 시행 문장·이력 첫 항목), sitemap `/privacy` lastmod, test_privacy `EFFECTIVE`, 상수. 하나만 고치면 테스트가 멈춘다.
- 정하는 규칙(037 §3.1 과 같다): D = PR 을 올리는 날(KST) + 9일, 머지 마감 = D − 8 의 18:00 KST — PR 제목 끝 `(머지 마감 MM-DD 18:00 KST)`, 본문 첫 줄 끝에도. 실행 세션은 실행한 날 + 9일을 임시 D 로 쓰고, PR 을 올리는 설계 세션이 그날 값으로 맞춘다. 마감을 넘기면 머지하지 않고 D 를 미루는 커밋을 먼저 넣는다.
- 덧붙인 조건: PR 은 **2026-10-11 이후**에 올린다 — 그래야 '이전 판' 이 하나(v2, 10-11 시행)다. 그 전에 실행이 끝나면 PR 만 기다린다.

### 3.2 동의 안내 판
- `NOTICE_VERSION`(clarity.js)·privacy.html 동의 스크립트 `VERSION`·방침의 보이는 판 글자를 **D** 로 함께 올린다. 예전 판의 `granted` 는 '정하지 않음' 이 되어 띠가 다시 묻는다(033 그대로 — 바뀐 내용을 보고 다시 고르게).
- 세 칸 판별 해시 `NOTICE_DIGESTS` 에 새 판을 더한다(예전 판 해시는 지우지 않는다 — 테스트가 판마다 글자를 묶는 방식은 033 그대로).
- 052 의 `attention.js` 도 같은 판 값을 갖는다 — 052 가 이 값을 복사하고 test_clarity 가 넷(clarity.js·privacy 스크립트·보이는 글자·attention.js)을 묶는다(attention.js 가 아직 없으면 셋).

### 3.3 privacy.html — 바뀌는 곳
말투·모양·외부 자원 0·CSP 는 지금 판 그대로. 시행 전후 언제 읽어도 거짓이 아니게 쓴다.
1. 머리 시행일 `<time datetime="D">`.
2. 변경 안내 상자(`#changes`) 내용 교체: "이 판은 D부터 시행합니다 — 그 전날까지는 이전 판(2026년 10월 11일 시행)을 따릅니다." / 바뀌는 것: 화면 분석에 동의한 방문자에게서 KimpTrack 서버가 **화면 영역 이용 통계**를 모은다(무엇을·어떻게 — 아래 2절 요약 한 줄) / "동의 안내가 바뀌어, 이미 동의했어도 한 번 더 묻습니다." / 링크 둘: 이전 판(`/privacy-20261011.html`), 대조(`#s12`).
3. 한눈에 보기의 화면 분석 줄: "Microsoft Clarity로 화면 이용을 분석하고, KimpTrack 서버도 화면 영역별 이용 통계를 하루 합계로 모읍니다 — 둘 다 동의한 경우에만, 기본은 꺼짐".
4. 동의 관리 절:
   - 질문 문단: Clarity 로 보내는 것에 더해 "KimpTrack 서버가 화면 영역별로 보인 시간·클릭 수를 하루 합계로 모아도 될까요?" 를 같은 질문 안에.
   - '수집·이용' 칸의 알릴 사항: 항목 끝에 "화면 이름·기기 종류(휴대폰·PC)·영역 이름별로 화면에 보인 시간·1초 이상 보였는지·클릭 수(KimpTrack 서버)", 목적에 "어느 영역을 많이·적게 보는지 알아 화면을 고치기", 보유 기간에 "KimpTrack 서버: 하루 합계로만 90일" 을 더한다.
   - '제공'·'국외 이전' 칸은 그대로 — 영역 통계는 Microsoft 에 가지 않고 국내(AWS 서울)에 둔다는 문장을 '수집·이용' 칸 끝에 한 줄.
   - 세 칸 모두 체크해야 둘 다 돈다는 문장을 고친다: "세 가지에 모두 동의한 경우에만 Clarity 와 KimpTrack 영역 통계가 돕니다."
   - 위 넷(질문 문단·'수집·이용' 칸 알릴 사항·국내 보관 한 줄·저장 규칙 문장)은 clarity.js 동의 띠(`HTML`)에도 같은 글로 바꾼다. 띠의 첫 문장 '랜딩과 대시보드의 화면 이용 기록…' 은 Clarity 몫 그대로 두고, 영역 통계 문장은 '모든 페이지(랜딩·대시보드·처리방침·검색어 페이지)' 라고 적는다 — 영역 통계는 띠가 없는 페이지에서도 저장된 동의로 돈다. `SHARED_SENTENCES` 에 바뀐 문장을 넣는다.
5. 1절 목적: "어느 화면 영역을 많이·적게 보는지 알아 화면을 고치기(화면 영역 이용 통계 — KimpTrack 서버, 동의한 방문자만)".
6. 2절 새 소제목 '화면 영역 이용 통계 — KimpTrack 서버' (Clarity 소제목 앞):
   - 항목: 화면 이름(랜딩·대시보드 탭·처리방침 등), 기기 종류(화면 폭 768px 미만 휴대폰·그 밖 PC), 영역 이름(예 '표'·'필터'·'자주 묻는 질문'), 영역마다 화면에 보인 시간·1초 이상 보였는지·클릭 수, 페이지를 본 횟수.
   - 방법: 브라우저가 화면을 떠나거나 숨길 때 한 번에 보내고, 서버는 받은 값을 그날(KST) 합계에 더하기만 한다. 방문자를 알아볼 값(IP·쿠키·기기 ID·주소·검색어·입력한 글자·마우스 위치)은 보내지도 저장하지도 않는다. 같은 IP 에서 너무 많이 보내는 것을 막으려고 IP 를 서버 메모리에서만 10분 동안 센다(서버를 다시 시작하면 사라진다). 이 요청은 서버 접속 기록에도 남기지 않는다.
   - 보유: 하루 합계 90일. 2절 표에 행 '화면 영역 이용 통계(동의한 경우만) | 하루 합계 90일'.
   - 처리 근거 문단: 영역 통계는 동의(개인정보 보호법 제15조 제1항 제1호). 합계라 한 사람분을 골라 지울 수 없다는 사실과, 철회하면 그 뒤로 보내지 않는다는 사실.
7. 3절 파기: "화면 영역 이용 통계는 날짜별 합계가 90일을 넘으면 서버가 지웁니다(저장소가 기한이 지난 키를 지운다)."
8. 7절 행태정보: 수집 방법에 "KimpTrack 서버로 — 브라우저 스크립트가 화면을 떠날 때 보냄(하루 합계로 90일)" 한 줄. 저장 장치 목록은 바꾸지 않는다(영역 통계는 쿠키·저장소를 쓰지 않는다).
9. 9절 안전성: "영역 통계는 영역 이름과 숫자만 보내고, 화면의 글자·입력값은 보내지 않습니다."
10. 12절: 시행 문장(이전 판 2026년 10월 11일), 이력 최신 위 "D — 화면 영역 이용 통계(KimpTrack 서버, 동의한 방문자만)·동의 안내 판 올림", 대조표(037 꼴 — 열 넷, 바뀐 문장마다 한 행).

### 3.4 이전 판 사본 `privacy-20261011.html`
037 §3.3 과 같은 꼴 — 지금 main 의 `privacy.html` 에서 `<script>` 를 지우고 동의 절은 알릴 사항만 정적 글로, 머리 아래 "이 문서는 2026년 10월 11일 시행 판의 사본입니다 — 지금 판과 시행일은 `/privacy`", title '개인정보 처리방침(2026년 10월 11일 판) — KimpTrack', canonical 대신 `noindex`, sitemap 에 넣지 않음. 지금 판 12절 이력의 2026년 10월 11일 항목에 '그 판 보기' 링크, 10월 1일 항목의 링크는 그대로.

### 3.5 엣지
- D 전 방문: 페이지는 v3 글이고 시행 문장이 'D부터' 라 거짓이 아니다. 052 서버는 D 00:00 KST 전 비콘을 저장하지 않는다.
- 판을 올린 순간부터 예전 동의자는 다시 묻는 띠를 본다 — D 전이어도 그렇다(새 판의 글을 보고 고른 동의만 쓴다).
- 052 가 D 까지 머지되지 않으면 방침이 앞선다(037 §3.5 와 같다).

## 4. 검증
- `test_privacy.py`: 상수 `PRIVACY_V3_EFFECTIVE` 가 날짜이고 `PRIVACY_V2_EFFECTIVE` 보다 늦다, `EFFECTIVE` = 상수, `<time>` 넷·sitemap 이 D, 변경 안내 문장('이전 판(2026년 10월 11일 시행)'·'한 번 더 묻습니다'·사본 링크), 본문 절마다 §3.3 의 새 낱말('화면 영역 이용 통계'·'하루 합계'·'90일'·'IP 를 … 10분'·'접속 기록에도 남기지 않'), 대조표 이전/이 판 칸 글자가 두 판 본문에 있다, 사본 단언(037 그대로 — 스크립트 없음·`<time>` = 파일 날짜·noindex).
