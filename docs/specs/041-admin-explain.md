# 041 — admin-explain

> 이 문서는 이 기능이 **지금 어떻게 동작해야 하는지**를 적는다. 동작이 바뀌면 이 문서를 직접 고치고, 같은 PR 에서 코드·테스트도 맞춘다(CLAUDE.md §4·§6). 사람이 끝까지 읽는 문서다 — 코드를 산문으로 옮기지 않는다.

## 1. 목적
운영자가 관리자 화면의 숫자마다 "어디서 온 값인지, 어떻게 셌는지, 무엇을 뜻하지 않는지" 를 그 자리에서 읽는다. 일곱 절에 접힌 설명을 달고, 영어 id 로만 보이던 실패 종류·경보·대시보드 탭을 한국어 이름으로 적으며, 잘못 읽히는 문구 다섯을 고친다. 화면 구조·피드·주기는 그대로다.

## 2. 범위
- 만드는 것: `web/admin/index.html` 의 정적 설명(절마다 '이 절 읽는 법' 하나, 덩어리 끝 '이 칸 뜻'), `admin.js` 의 이름표 표 셋·타일 부제·문구 고침, `admin.css` 의 설명 모양, `server/tests/test_admin.py` 정적 단언.
- 하지 않는 것:
  - 새 절·새 파일·새 피드·새 경로·새 외부 링크.
  - 칸 위에 뜨는 풍선(popover·'?' 단추) — 360 폭에서 옆 값을 가리고 JS 코드가 늘어난다.
  - JS 로 만드는 설명.
  - 개요 칸 여섯(`.vital` — 누르면 절로 가는 링크) 안에 무엇을 넣는 것. 링크 안에 누르는 요소를 둘 수 없고, 개요 설명은 절 설명이 맡는다.
  - 답 문장(덩어리 첫 줄에 데이터로 만든 답 — 042·043). 접속 절의 새 칸(042·043). 서버 동작.
- 바꾸는 기존 것: 036 §1·§3.4·§3.5·§3.9·§4(설명·이름표·문구), 034 §1·§3.2·§3.5 의 AWS 계정 종료 문장(동작 같음 — 문장만). 사용자 결정(2026-10-02): AWS 계정 종료일을 화면·문서의 근거로 쓰지 않는다 — 계정이 지워져도 운영을 이어 간다.
- 담당: 034·036 은 이 레포 주인 담당이라 고친다. 002·011·025·027 의 이름·규칙은 읽기만 한다.
- 접속 절 설명은 시작할 때 main 의 칸(035 의 24시간 요약·Clarity 받은 지표)으로 쓰고, 042·043 이 칸을 바꿀 때 같은 틀로 고쳐 쓴다. 038(접속 요약 v2)은 이 스펙 앞뒤 어느 때든 머지될 수 있고 몇 칸의 뜻을 바꾼다 — 그래서 §3.2 의 '038 이 앞뒤 어느 때 머지돼도 맞는 글' 규칙을 지켜, 어느 순서로 머지돼도 설명이 거짓이 되지 않게 한다.

## 3. 동작

### 3.1 설명 층 넷 — 자리와 모양
화면 지침의 설명 다섯 층 가운데 2~5 층을 만든다. 1 층(답 문장)은 042·043 이다.
- **절 설명** — `<details class="explain">`, 일곱 절에 하나씩.
  - 자리: 절 머리 줄(`.sec-head`) 바로 다음 요소. 개요는 머리 줄이 없어(띠가 머리다) 칸 여섯(`.vitals`) 바로 다음이고, 절의 마지막 요소다.
  - 기본은 접힘(`open` 없음). summary 는 '이 절 읽는 법' + 흐린 꼬리 한 줄(읽는 값과 주기 — 예 '· 수집기 10초마다'). 도구는 꼬리가 없다.
  - 펼치면 `dl` 하나. 첫 dt 둘은 늘 '읽는 값'(어디서·얼마마다·어떤 창)과 '판정'(개요의 종합 판정에 드는지, 든다면 무엇이 장애·주의인지)이고, 그 뒤가 §3.3 의 항목이다.
- **덩어리 끝 설명** — `<details class="terms">`, summary '이 칸 뜻', 기본 접힘.
  - 자리: §3.3 이 정한 카드(덩어리)의 마지막 요소. JS 가 통째로 다시 그리는 칸(`b-*`·`exchanges`·`timeline`·`access-tables`·`clarity-metrics` 처럼 `replaceChildren` 하는 요소)의 안이 아니라 그 형제 자리다. 그래서 빠른 묶음(10초)·느린 묶음(60초)이 다시 그려도 펼침이 남는다.
  - `dl` 하나. dt 는 화면에 보이는 칸 이름 그대로이고, 원래 id·키가 있으면 그 뒤에 작은 고정폭 글자로 적는다. dd 는 뜻·계산·한계를 한두 문장으로 적는다.
- 두 details 는 HTML 에만 있다. admin.js 는 그것을 만들지도, 열거나 닫지도 않는다. 펼침은 페이지를 다시 열면 접힌다(브라우저 저장소 없음 — 036 §3.8).
- **행 안 이름표**: 실패 종류·경보 꼬리·대시보드 탭을 행에 한국어 이름으로 적는다(§3.4). 원래 id 는 행에 적지 않는다. id 는 `title`(보조 — 휴대폰은 못 본다)과 설명 dl 에 둔다. 그래서 이름표 표의 키는 모두 index.html 의 설명 dl 어딘가에 글자로 있다.
- **타일 부제**: 값 아래 흐린 한 줄로 무엇을 센 수인지 적는다. 그 수가 사람 수로 읽히거나 봇·도구가 섞이는 타일이 대상이다 — 서버 기록 카드의 총 요청·페이지, Clarity 카드의 세션·봇 세션·사용자·세션당 페이지. 실시간 카드의 기존 부제('열린 대시보드 수 — 사람 수가 아니다')와 개요 칸 여섯의 아래 줄은 그대로다.
- 모양:
  - 설명 글은 본문보다 작고 흐리며 대비는 4.5:1 이상이다. 상태색(정상·주의·장애)은 쓰지 않고, 강조는 `<b>` 만 쓴다.
  - 641px 이상은 dt·dd 두 열, 640px 이하는 dt 아래 dd 다. 다 펼쳐도 360 폭에서 가로 넘침이 없다.
  - summary 는 키보드로 닿고, 초점 외곽선 2px(036 과 같다)·누르는 곳 36px 이상이다.

### 3.2 문구 규칙
- 프로젝트 문서·화면이 쓰는 낱말로 짧고 평이하게 쓴다. 번역투로 만든 낱말은 쓰지 않는다. dd 는 두 문장까지다.
- dd 가 답하는 것(필요한 것만): 무엇을 센·잰 값인가(식이 있으면 식) / 출처가 절 설명과 다르면 그 출처 / 잘못 읽기 쉬운 점·한계(사람 수가 아니다, 봇이 섞인다, 지금 값이 몇 분 늦다 등).
- 정상 범위는 스펙의 임계·색 기준·주기에서 나온 값에만 적는다. 예: 1시간 성공률 99% 초과(011 공개 탭 색), 메모리 가용률 20% 이상·디스크 70% 이하(036 색), 크레딧 잔고 data 173·serve 86 이상(027), canary 24시간 실행 288 안팎(5분 주기), 예산 85% 아래. 방문자·요청·마켓 수·금액처럼 늘 바뀌는 값에는 적지 않는다.
- 숫자: 화면 고정 주기(10초·60초)와 다른 스펙의 임계는 값으로 적는다. 서버가 `refreshSec` 로 알리는 주기 가운데 다른 스펙이 바꾸는 중인 것(Clarity — 040)은 숫자로 적지 않고 'Clarity 칸에 적힌 간격'(칸 본문의 '다음 조회 … — n 간격' 줄)으로 가리킨다.
- 모르는 것은 모른다고 적는다. 짐작을 사실처럼 적지 않는다.
- **038 이 앞뒤 어느 때 머지돼도 맞는 글**: 서버 기록 칸의 dd·부제는 038 이 바꾸는 사실에 기대지 않는다 — 5xx·시간대별 5xx·최근 5xx 에 대시보드 재접속(`/api/ws/spreads`) 502 가 드는지, 페이지에 304 가 드는지, 상위 표 여섯에 봇이 드는지, 기기 이름 목록, 비율 막대의 분모. 이 다섯은 042 가 038 의 뜻으로 고쳐 쓴다. 총 요청이 모든 줄이라는 것, 페이지에 봇이 섞인다는 것은 두 판에서 같아 적어도 된다.
- 낱말 표(042·043 도 따른다):
  - 방문자 셈은 '날마다 센 방문자'(줄여 '방문자(날마다 셈)')다. 24시간 창의 그 수는 '오늘·어제(KST)를 따로 세어 더한 수 — 사람 수가 아니다' 로 적는다.
  - '방문자-일'·'visitor-day' 는 쓰지 않는다. 응답 키(`confirmed`·`shaped` 등)는 dt 의 원래 id 로만 보인다.
  - 대시보드 연결 수는 '연결 수 — 사람 수가 아니다' 로 적는다.
- 설명 글 안에는 링크·이미지·스크립트·`style`·스킴 주소(`://`)·12자리 숫자·이메일 모양을 넣지 않는다. 036 §4 의 단언이 HTML 전체를 본다.
- admin.js 에 넣는 이름표·부제·title 글은 036 §4 의 금지 글자(`.href`·`.src`·`.style`·`innerHTML` 등)와 `fetch(`·`://` 를 품지 않는다. 스펙 번호·함수 이름은 화면 글에 적지 않는다.

### 3.3 절마다 항목 (dt 목록 — 글은 실행 세션이 §3.2 로 쓴다)
dd 의 사실은 이 스펙(§3.2 의 정상 범위·§3.4 이름표·§3.5)과, 이 PR 이 고치는 036 의 §3.2 피드 복사 줄·§3.4 화면 규칙(034·035 피드 계약을 복사해 둔 곳), 레포의 context 문서에서만 가져온다. 근거가 없으면 모른다고 적는다(§3.2).
- **개요** — 절 설명만:
  - 읽는 값: 빠른 네 경로 10초 + 경보·canary.
  - 판정: 일곱 재료(수집기·api·Redis·Influx·거래소·CloudWatch 경보·canary)만 보고, 위에서부터 알 수 없음·장애·주의·정상이다. 흐린 ○ 는 판정에 넣지 않은 재료다.
  - 사유 줄('상태 모름' 은 재료를 못 읽었다는 뜻), 칸 여섯(수집기·api·지금 접속·경보·canary·이번 달 비용).
  - 화면 공통: 칸 머리 'n분 전 값'·'오래됨'(서버 주기 × 3), 상태 배지 넷(연결 안 됨·권한 없음·불러오지 못함·첫 조회 중), 모양 여섯(● ▲ ✕ ○ ? …), 시각(이 브라우저 시간대 — Clarity 칸만 UTC), 차트 '값 없음'·'값 1개뿐'(경보의 '데이터 부족' 과 다르다), 마지막 갱신(탭이 숨으면 멈춘다).
- **수집** — 절: 읽는 값·판정(끊김 장애·지연 주의)·즉시 갱신(무엇을 다시 읽히나, 평소엔 누를 일이 없다). 이 칸 뜻은 둘이다.
  - '거래소 다섯' 카드 끝: 상태 셋(5초·60초 경계), 열린 실패 구간('n회' = 실패한 초, 60초 넘으면 Slack), 마지막 성공, 1시간 성공률(식 — 한 곳이 36초 끊기면 99.0%), 마켓, 마지막 오류(흐림 = 끝난 오류), 실패 종류 여덟(이름표와 id).
  - '실패 구간' 카드 끝: 막대 높이·색, 최소 폭, 아래 최근 다섯 줄.
- **인프라** — 절: 읽는 값(CloudWatch — 경보·canary 60초, 지표 5분)·판정(ALARM 장애, canary 실패 주의, 경보·canary 부르기 실패 주의, 박스 지표는 판정 밖)·연결 안 됨·권한 없음·카드 하나로 접힘. 이 칸 뜻은 셋이다.
  - '경보' 카드 끝: 꼬리 여덟(이름표와 조건 — §3.4), 상태 셋('데이터 부족' 의 뜻과 그것도 울림으로 다루는 경보), 사유, 바뀐 지, '정상 n개'.
  - 'canary' 카드 끝: 네 단계, 최근 실행(11분 안), 24시간 실행·오류, 실행 시간, 로그 줄.
  - '박스' 덩어리 끝: 박스 셋의 역할, 메모리 가용률, 디스크 사용률, CPU(색 없음 — collect 는 늘 높다), 크레딧 잔고, 스왑, 지금 값(마지막 5분 구간이라 몇 분 늦다), 머리 배지.
- **알림** — 절 설명만: 읽는 값(앱 두 역할이 보낸 Slack 알림 기록 + 경보 상태 변경, 최근 7일·200건)·판정(넣지 않는다)·머리 표시 셋(🔴·🟢·⚠️ 의 뜻)·10분 억제와 큐 상한(보내지 않은 알림은 기록에 없다)·전송 실패·없는 것(예산 알림·Amazon Q 가 올린 글·uptime 알림).
- **접속** — 절:
  - 읽는 값 셋: 실시간 10초, 서버 기록 60초, Clarity 는 Clarity 칸에 적힌 간격.
  - 판정: 넣지 않는다. 장애색은 5xx 에만 쓴다.
  - 창: 서버 기록은 24시간·이 브라우저 시간대, Clarity 는 부른 때 직전 하루·UTC.
  - 남기는 것: IP·UA 원문이 없고, api 메모리 요약이라 다시 시작하면 처음부터 센다. 빠지는 요청: 폴링·canary.
  - 서버 기록과 Clarity 의 차이: Clarity 는 동의한 방문자만이라 훨씬 적은 게 정상이다.
  - 대시보드 탭 여섯(이름표와 id).
  - 이 칸 뜻은 넷이다.
    - '실시간' 카드 끝: 지금 접속, 24시간 선(5분 최댓값 — 굵은 값은 24시간 최고).
    - '서버 기록' 카드 끝: 총 요청, 페이지, 5xx, 시간대별 막대, 상태 코드 넷, WebSocket 연결(끝난 연결만 — 지금 열린 연결은 없다)·지속 시간(머문 시간이 아니다), 읽지 못한 줄, 기록 시작.
    - 상위 표 여섯 묶음 다음: 경로, 탭, 외부 출처(사이트 주소만 — 누를 수 없다), utm_source, 기기, 브라우저.
    - 'Clarity' 카드 끝: 세션, 봇 세션, 사용자, 세션당 페이지, 받은 지표.

### 3.4 이름표 표 셋 (계약 복사 — 테스트 대상)
- 표는 admin.js 상수 셋이다. 서버 값으로 찾을 때는 036 의 `Object.hasOwn` 규칙을 따른다(`constructor` 같은 이름이 Object 의 것을 집지 않게). 표에 없는 값은 원래 글자 그대로 적는다 — 이름표 없이, 오류도 아니다.
- **실패 종류** — 011 §3.8 공개 수집 상태 탭의 유형 칩 라벨과 같은 이름:
  - `timeout` 타임아웃 · `network` 연결 실패 · `rate_limit` rate limit · `banned` 차단 · `unavailable` 거래소 오류 · `bad_request` 요청 오류 · `bad_response` 응답 오류 · `stale_stream` 스트림 정체.

- **경보 꼬리** — 027 §3.6. 이름은 `marketlens-<박스>-<꼬리>` 이고 canary·5xx 는 박스 없이 `marketlens-<꼬리>` 다. 접두를 뗀 이름이 꼬리와 같거나 `-<꼬리>` 로 끝나면 그 꼬리다. 이름표와 조건:

  - `status-system` 시스템 상태검사 — 60초 2점 연속 실패면 AWS 가 복구(recover).

  - `canary` canary — Lambda 실패가 5분 2점 연속(10분), 데이터 없음도 울린다.
  - `http-5xx` 사이트 5xx — 5분 합 10 이상(`/api/ws/spreads` 는 세지 않는다), 데이터 없음은 정상.

- **대시보드 탭** — 002:
