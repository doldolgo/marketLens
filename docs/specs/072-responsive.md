# 072 — responsive

상태: DONE | 의존: 002(셸·탭·KPI·푸터), 003·026(스프레드 표), 013·014·024(기록 탭), 048(갭 탭), 050(입출금 레이더). 쓰는 계약은 §3 에 옮겨 적었다

> 이 문서는 이 기능이 **지금 어떻게 동작해야 하는지**를 적는다. 동작이 바뀌면 이 문서를 직접 고치고, 같은 PR 에서 코드·테스트도 맞춘다(CLAUDE.md §4·§6). 사람이 끝까지 읽는 문서다 — 코드를 산문으로 옮기지 않는다.

## 1. 목적
대시보드(`/app/`)를 휴대폰·태블릿에서도 읽고 조작할 수 있게 한다. 넓은 화면(폭 1080px 이상, 높이 561px 이상)의 모습은 지금 그대로 두고, 그보다 좁거나 낮은 화면에서만 헤더·KPI·필터·표의 배치를 바꾼다. 데이터·URL 상태·화면 이용 통계 열쇠는 어느 폭에서나 같다. 접속 통계에 많이 잡히는 브라우저(iOS Safari·iOS Chrome·카카오톡 인앱·안드로이드 Chrome·데스크톱 Chrome·Edge·Safari)에서 같은 모습이 나오도록 엔진·터치 차이를 맞춘다(§3.9).

## 2. 범위
- 만드는 것: 화면 구간 판정(공유 훅 하나), 좁은 헤더(두 줄 + 메뉴), 폰 KPI, 폰 필터 접기, 폰 정렬 줄, 탭 다섯 개의 폰 행 모양, 문서 스크롤 배치.
- 하지 않는 것: 관리자 화면(`/admin/`) — 운영자가 넓은 화면에서 본다. 정적 페이지(랜딩·처리방침·검색어 페이지·404)는 이미 폭 719px 이하 배치·글자 크기 고정·어두운 화면 선언이 있어 hover 를 마우스 기기로 한정하는 것(§3.9) 말고는 손대지 않는다. 숨긴 수집 상태 탭. 새 라이브러리·CSS 파일. `docs/design/*` 원본(넓은 화면의 진실로 남는다) — hover 유틸을 마우스 기기로 한정한 것 하나만 원본에서 고쳐 복사했다(§3.9, 2026-10-23 사람 요청 "디자인을 전체적으로 문제 없게").
- 바꾸는 기존 것: 002 §3.5 셸 배치(좁은 헤더·폰 탭 이름·폰 KPI·문서 스크롤), 공용 표 틀(좁은 폭에서 왼쪽 열이 잘리던 결함), 기록 차트의 터치 세로 끌기(페이지 스크롤에 양보), 061 §7 요소 목록에 폰 열쇠 넷(§3.8).

## 3. 동작

### 3.1 화면 구간
판정은 `matchMedia` 로 하고 구간이 바뀔 때만 다시 그린다. 경계값은 공유 모듈 한 곳에 둔다.

| 구간 | 조건 |
|---|---|
| 폰 | 폭≤719 또는 터치+높이≤560 |
| 좁은헤더 | 폭≤1079 |
| 문서스크롤 | 폭≤719 또는 높이≤560 |
| 터치 | hover:none·pointer:coarse |

- **폰**: 표를 카드 행으로, 필터를 접기로, KPI 를 격자로, 탭 이름을 짧게. 719 는 정적 페이지들의 폰 경계와 같다. 가로로 눕힌 휴대폰(터치 기기 + 높이 560 이하)도 폰 배치다 — 넓은 배치로 두면 필터 줄 셋과 KPI 만으로 화면 높이(약 330~430)가 차고, 가로 스크롤 표 틀 때문에 표 머리가 화면 위에 붙지 않았다.
- **좁은 헤더**: 한 줄 헤더(로고·탭·링크·시계)가 1080px 아래에서 넘쳐 탭 글자가 한 자씩 꺾이고 시계·링크가 화면 밖으로 밀렸다. 이 구간은 두 줄 헤더를 쓴다.
- **문서 스크롤**: 휴대폰은 문서가 스크롤돼야 주소창이 접히고, 높이가 낮은 화면(가로 폰·낮은 데스크톱 창, 약 360~560)은 고정 머리만으로 화면이 찬다. 이 구간에서는 셸이 화면 높이에 묶이지 않고 문서가 스크롤된다(탭 본문 자체 스크롤 없음). 탭 줄은 화면 위에 붙어 따라온다(sticky). 그 밖에서는 지금처럼 셸이 화면 높이(지원하면 `100dvh`, 아니면 `100vh`)에 맞고 탭 본문만 스크롤된다.
- **터치**: 손가락이 주 입력인 기기(휴대폰·태블릿 — 폭과 무관). 배치는 바꾸지 않고 입력칸 글자 크기만 고른다(§3.9).

### 3.2 헤더
- 넓은 화면: 지금 그대로(한 줄).
- 좁은 헤더 구간 — 두 줄.
  1. 첫 줄: 로고 + 초록 점 + `실시간 수집 중`(폰은 점만) · 오른쪽에 시계 `HH:MM:SS KST`, 메뉴 단추(세 줄 아이콘, `aria-label="메뉴"`, `aria-expanded`).
  2. 둘째 줄: 탭 단추. 폰은 다섯 칸이 같은 폭으로 한 줄에 다 들어가게 **짧은 이름**을 쓴다 — `spread` 스프레드, `history` 기록, `gap` 현선갭, `pp` 선선갭, `flow` 입출금. 폰이 아니면 원래 이름이고 넘치면 가로로 스크롤된다(스크롤 막대는 숨긴다). 활성 표시는 넓은 화면과 같다(본문색 + accent 밑줄).
- 메뉴를 열면 첫 줄 아래 오른쪽에 `개인정보 처리방침` 링크(한 줄 높이 44px)가 뜬다(화면 분석 설정 링크는 2026-10-18 에 뺐다 — 033). 링크 주소·새 탭·`data-el`(privacy)은 넓은 화면과 같다. 메뉴 밖을 누르거나, Esc, 링크를 누르면 닫힌다.
- 문서 스크롤 구간에서 sticky 는 탭 줄이다(넓은 화면 구간이면 한 줄 헤더 전체). 첫 줄은 함께 스크롤돼 사라진다.

### 3.3 KPI·푸터
- 폰 KPI: 위 3칸 격자(`USDT/KRW 암묵환율`·`BTC 김프 · 순방향`·`BTC 김프 · 역방향`, 값 16px, 라벨은 넘치면 줄바꿈) + 아래 11px 한 줄(왼쪽 `수집 {수집 상태 값}`, 끊김·지연이 있으면 부제를 붙임 · 오른쪽 `{N}개 코인 · {M} 페어`). 값·색·계산은 002 §3.5 그대로다. 세로 구분선은 없다.
- 좁은 헤더 구간의 폰이 아닌 폭: 넓은 화면의 KPI 띠를 쓰되 줄바꿈을 허용한다(가로 스크롤 대신).
- 폰 푸터: 같은 세 문구를 세로로 쌓는다. 입출금 레이더 탭의 자체 푸터도 같다. 좁은 헤더 구간의 폰이 아닌 폭은 줄바꿈을 허용한다.

### 3.4 폰 필터 접기
폰에서는 탭마다 늘 보이는 조작만 한 줄에 두고, 나머지는 `필터` 단추로 펼친다. 펼침 상태는 메모리만(URL 밖)이고 기본은 접힘. 단추에는 기본값과 다른 필터 수를 작은 숫자로 붙인다(0 이면 없음). 필터 값·URL 키·`data-el` 은 넓은 화면과 같다.

| 탭 | 늘 보임 |
|---|---|
| 스프레드 | 검색·김프/역프 |
| 기록 | 김프/역프·검색 |
| 현선갭 | 검색·진입/정리 |
| 선선갭 | 검색 |
| 입출금 | 전부 |

- 스프레드 접힌 쪽: 기준 국내 거래소, 하이라이트 임계값, 임계 초과만, 입출금 열림, 네트워크 같음, 체결 규모 안내, 비교 해외 거래소. 숫자 세기: 국내 ≠ 모두, 임계값 ≠ 1.5, 세 토글 켜짐, 꺼진 해외 거래소 1곳 이상 — 각 1.
- 기록 접힌 쪽: 기간, 국내, 해외, 사건 정의 안내. 세기: 기간 ≠ 1주, 국내 ≠ 전체, 해외 ≠ 전체. 늘 보이는 줄 아래에 `{기간} · {N}건`(+ `조회 중…`)을 11px 로 둔다.
- 현선갭 접힌 쪽: 하이라이트 임계값, 임계 초과만, 갭 부호 안내. 세기: 임계값 ≠ 0.5, 임계 초과만 켜짐.
- 선선갭 접힌 쪽: 두 임계값, 임계 초과만, 안내. 세기: 가격갭 ≠ 0.3, 펀딩갭 ≠ 20, 임계 초과만 켜짐.
- 입출금: 창·방향 분절 한 줄, 검색 칸은 다음 줄 전체 폭, 피드 상태·오류는 그 아래.
- 분절 버튼 묶음은 어느 폭에서나 글자를 꺾지 않는다 — 넘치면 묶음 안에서 가로 스크롤된다(기록 탭 기간 9개).

### 3.5 폰 표 — 정렬 줄과 카드 행
- 폰에서는 열 머리 줄 대신 **정렬 줄**을 표 맨 위에 둔다: `정렬` + 열 이름 고르기(네이티브 select, 넓은 화면의 정렬 가능한 열 전부) + 방향 단추(`내림차순 ▾`/`오름차순 ▴`) + 오른쪽 표시 건수(`{표시} / {전체}`). 열을 고르는 것은 넓은 화면에서 그 열 머리를 누른 것과 같고(같은 열이면 방향 반전, 새 열이면 그 열의 첫 방향), 방향 단추는 지금 열 머리를 다시 누른 것과 같다. 정렬 줄은 문서 스크롤에서 탭 줄 바로 아래에 붙어 따라온다. 정렬 키·URL 은 넓은 화면과 같다.
- 정렬할 수 없는 표(입출금 두 표·기록 사건 로그)는 폰에서 머리 줄을 그리지 않는다.
- 행은 2~3줄 카드다. 줄마다 왼쪽은 이름·보조값, 오른쪽은 큰 값. hot·stale·실패값 `–`·색 규칙·행 클릭 동작은 넓은 화면과 같다.

| 탭 | 행 줄 |
|---|---|
| 스프레드 | 2 |
| 현선갭 | 2 |
| 선선갭 | 3 |
| 기록 순위 | 3 |
| 기록 로그 | 2 |
| 순유입 | 2 |
| 최근 전송 | 2 |

- 스프레드: 1줄 = 심볼·변동율·국내가격 / 슬리피지·김프(역프) 값. 2줄 = 해외 거래소 칩 → 국내 거래소 칩·네트워크 / 입출금 배지(망 다름이면 배지 하나). 해외가격(USD)은 폰에서 뺀다 — 국내가격·김프로 판단이 되고 한 줄 폭을 넘는다.
- 현선갭: 1줄 = 심볼·현물가 / 갭 값. 2줄 = 현물 칩 → 선물 칩 / 펀딩비·다음 펀딩까지.
- 선선갭: 1줄 = 심볼 / 가격갭. 2줄 = 두 칩 / 펀딩갭. 3줄 = `{low} 롱 / {high} 숏` / `해당 조합 펀딩갭`.
- 기록 순위: 1줄 = 티커·상태 배지 / `최대 {최대 스프레드}`. 2줄 = `{횟수}회 · 최대 {최대 지속} · 평균 {평균 지속}` / `평균 {평균 스프레드}`. 3줄 = 네트워크 · 최신. 선택한 티커 강조는 같다.
- 기록 로그: 1줄 = 거래소 배지·네트워크(넘치면 말줄임) / 최대 스프레드. 2줄 = `{시작} → {종료 또는 진행 중} · {지속}`(줄 전체).
- 순유입: 1줄 = 코인(누르면 검색) / 순유입 수량. 2줄 = `입금 {…} · 출금 {…}` / 원화 · 최근.
- 최근 전송: 1줄 = 방향 배지·코인·수량 / 원화. 2줄 = 시각 · 주소 → 상대(축약) / tx 링크 + `확정 전`.

### 3.6 폰이 아닌 좁은 폭의 표
열 구성은 넓은 화면 그대로, 표 틀 안에서 가로 스크롤된다. 표 틀은 화면이 표의 최소 폭보다 좁을 때 **왼쪽부터** 보인다(지금은 가운데 정렬 때문에 왼쪽 열이 잘리고 스크롤로도 닿지 않는다 — 넓은 화면에서도 창을 줄이면 생기던 결함). 기록 탭의 표·요약 두 칸 배치는 좁은 헤더 구간에서 한 칸으로 쌓인다.

### 3.7 기록 탭 차트
- 폰: 차트 높이 360px(넓은 화면 460), 카드 안 여백을 줄이고, 툴바 안내는 `두 손가락으로 확대 · 끌어서 이동 · 왼쪽 끝까지 끌면 과거 불러오기` 로 짧게.
- 모든 폭: 차트 위 터치의 세로 끌기는 차트가 잡지 않는다 — 문서 스크롤 구간에서 차트 위를 쓸어도 페이지가 스크롤된다. 가로 끌기·두 손가락 확대·마우스 동작은 그대로.

### 3.8 화면 이용 통계(052·061)
`data-area` 는 넓은 화면과 같은 이름을 같은 덩어리에 단다(header·tabs·kpi·filters·table·summary·list·chart·filters-2·table-2). 폰에서 새로 생긴 조작은 새 `data-el` 을 받는다 — 메뉴 단추 `menu`, 필터 단추 `filter-toggle`, 정렬 줄 `sort:col`(고르기)·`sort:dir`(방향). 메뉴는 링크처럼 영역 밖이다(메뉴 안 처리방침 링크는 넓은 헤더와 같은 열쇠). 061 계약대로 영역·열쇠는 화면 안에서 하나뿐이다 — 폰과 넓은 화면이 같은 영역·조작을 다르게 놓을 때도 영역 상자와 열쇠 단 요소는 소스에 한 번만 쓰고 자리·모양만 바꾼다. 공유 조각(필터 단추·정렬 줄)은 열쇠를 박지 않고 호출부에서 받는다. 새 열쇠는 061 §7 요소 목록·`server/tests/test_attention_elements.py`·관리자 이름표 `web/admin/screensnames.js` 에 함께 올린다.

### 3.9 브라우저·기기 차이
2026-10-23 접속 기록(caddy 10-02~10-23, 스크립트를 실행한 방문 218)에서 휴대폰은 iOS Safari(iOS 26·17)·iOS Chrome·카카오톡 인앱(iOS·안드로이드)·안드로이드 Chrome, 데스크톱은 Chrome·Edge·Safari·Firefox 였다. 그 엔진(WebKit·Blink)과 터치 기기에서 다음을 지킨다.
- 대시보드 문서는 정적 페이지와 같은 세 가지를 선언한다 — iOS 가 가로로 돌릴 때 글자를 키우지 않게(`text-size-adjust: 100%`), 어두운 화면(`color-scheme: dark` — 체크박스·select·스크롤 막대·버튼의 브라우저 기본 글자색까지 어둡게 그린다. 선언이 없을 때 기록 탭 순위 표의 `횟수` 숫자가 버튼 기본 글자색인 검정으로 흐리게 보였다), 휴대폰 주소창 색 `#161826`.
- 버튼으로 만든 행·칸은 글자색을 직접 정하거나 물려받게(`inherit`) 한다 — 버튼 기본 글자색은 iOS 에서 시스템 파랑이라, 넓은 화면 순위 표의 `횟수` 숫자가 아이패드·가로 폰에서 파랗게 보였다.
- hover 유틸(행·글자·테두리 밝힘)은 마우스처럼 올릴 수 있는 기기(`hover: hover`)에서만 켠다. 터치 기기는 누르거나 쓸어 넘긴 자리에 hover 가 남아 행·탭이 밝은 채로 머문다.
- 터치 기기의 입력칸(검색·숫자)은 16px — 폰이 아닌 배치(가로 폰·태블릿)에서도. iOS 는 16px 보다 작은 입력칸을 누르면 화면을 확대하고 그대로 둔다. 마우스 기기는 12px 그대로.
- 심볼 입력칸 다섯(스프레드·기록·현선갭·선선갭·입출금)은 휴대폰 자판이 대문자로 입력하게 하고, 자동 수정·맞춤법·자동 완성을 끈다 — 자동 수정은 Enter 때 심볼을 사전 낱말로 바꿀 수 있다.
- 기록 탭 사건 로그는 그 칸의 폭이 600px 보다 좁으면 열 표 대신 폰과 같은 2줄 카드(§3.5 기록 로그)로 그린다. 넓은 화면은 오른쪽 칸(3:2 의 2)이라 화면 폭 약 1,560px 아래에서 좁아져 `시작`·`종료`·`네트워크` 머리 글자가 한 자씩 꺾이고 행 글자가 겹쳤다. 화면 구간이 아니라 칸 폭으로 고른다. 좁은 칸의 카드 줄은 칸 제목과 같은 안쪽 여백을 쓴다.
- 기록 탭 순위 표의 최소 폭은 660px(아홉 열이 640px 까지 겹치지 않는다 — 2026-10-23 실측)이다. 좁은 헤더 구간에서 표·요약이 한 칸으로 쌓일 때 그 칸이 660px 보다 좁으면 폰과 같은 정렬 줄 + 3줄 카드(§3.5 기록 순위)로 그리고, 그 밖에서는 열 표가 가로로 스크롤되지 않는다 — 예전 최소 폭 800px 은 태블릿 세로에서 마지막 열(`최신`)을 표 틀 안 가로 스크롤 뒤에 숨겼고, 넓은 배치에서 오른쪽 칸을 밀어냈다. 넓은 배치(두 칸)는 카드로 바꾸지 않는다 — 표가 최소 폭으로 왼쪽 칸을 잡고 오른쪽 칸(요약·사건 로그)이 남은 폭을 쓴다. 정렬 줄은 문서 스크롤 구간에서만 탭 줄 아래에 붙는다(탭 본문이 스스로 스크롤되는 배치에서 붙이면 위에 빈 줄이 생긴다).
- 정적 페이지(랜딩·검색어 페이지 둘·처리방침)의 hover 도 같은 이유로 마우스 기기에서만 켠다. 얼려 둔 처리방침 옛 판(`privacy-YYYYMMDD*.html`)은 그대로 둔다.
- 로고 줄(마크·이름·점·`실시간 수집 중`)은 세로 가운데로 맞춘다 — 기준선 맞춤이면 점·상태 글이 로고 위쪽에 떠 있었다. 폰 KPI 라벨은 낱말 단위로만 꺾는다(320px 에서 `암묵환율` 의 마지막 글자가 혼자 떨어졌다).
