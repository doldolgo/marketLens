## 3. 동작

### 3.1 '?' 말풍선
- 모든 페이지의 `?`(카드 머리·큰 수 타일·화면 페이지 판 머리·스크립트가 만드는 표 칸 머리 — 082 §3.3)는 마우스 올림·누름(클릭·터치)·키보드(Tab 으로 가서 Enter·Space)로 말풍선을 연다. 말풍선 하나만 뜬다 — 다른 `?` 를 열면 앞의 것은 닫힌다.
- 닫기: 같은 `?` 를 다시 누름·말풍선 밖 누름·Esc·페이지 스크롤·창 크기 바꿈. 말풍선 안 누름·스크롤은 닫지 않는다. 누름으로 연 것은 닫을 때까지 남고, 마우스 올림으로 연 것은 마우스가 `?` 와 말풍선 둘 다 벗어나면 닫힌다 — `?` 에서 말풍선으로 옮겨 가는 동안(사이 틈 포함)은 남아 안을 스크롤할 수 있다. Esc 는 말풍선만 닫는다(열린 상세 판은 그대로).
- 큰 수 타일(트래픽 — 누르면 아래 추이의 지표가 바뀌는 단추) 안의 `?` 를 눌러도 타일은 눌리지 않는다.
- 말풍선 = §3.2 의 칸 — 칸마다 굵은 칸 이름(강조색 작은 글자) + 글, `낱말 뜻` 칸은 낱말(굵게) — 뜻 목록. 글에 없는 칸은 빠진다. `?` 아래에 두되, 아래에 다 안 들어가고 위에 들어가면 위, 둘 다 모자라면 남은 자리가 넓은 쪽에 그 높이만큼 둔다 — 넘는 글은 말풍선 안에서 스크롤한다. 좌우는 화면 안으로 민다. 폭 400px(좁은 화면은 화면 폭 − 16px), 높이 한도 600px, 글자는 본문 13px.
- 글은 HTML 의 `title` 에 두고(칸 이름 붙은 줄, §3.2), 페이지가 뜰 때 브라우저 기본 툴팁이 겹치지 않게 다른 속성으로 옮긴다. 스크립트가 못 돌면 기본 툴팁이 그 줄 그대로 보인다.
- 접근성: `?` 는 `role=button`·`tabindex=0`·`aria-label="설명"`·`aria-expanded`, 말풍선은 `role=tooltip` 이고 열린 동안 `?` 의 `aria-describedby`.

### 3.2 설명 글 규칙
- 모든 `?` 글(HTML `title` 과 스크립트가 만드는 표 칸 머리 글)은 칸 이름을 줄 머리에 붙인 칸 넷이다. 순서는 아래 그대로, 칸마다 한 줄(낱말 뜻은 낱말마다 한 줄):
  - `보여 주는 것:` (꼭) — 이 카드·타일·판이 무엇을 보여 주는지. 사람 수인지 아닌지, 무엇의 합·평균·비율인지.
  - `낱말 뜻:` (카드 안에 처음 보는 사람이 모를 낱말이 있으면) — 다음 줄부터 `· 낱말 — 뜻`. 낱말은 카드 제목·단위 줄·칩·탭·열 이름·범례에 화면이 쓰는 글자 그대로.
  - `자료 출처:` (꼭) — 숫자가 어디서 오는지(caddy 접속 기록·CloudWatch·AWS 예산·수집기 상태·Clarity·화면 이용 통계·화면 이동 기록 등), 무엇을 셌는지, 기간·다시 읽는 주기, 한계(빠지는 것·섞이는 것·비는 까닭).
  - `읽는 법:` (꼭) — 그림 모양·색·선·기준선을 어떻게 보는지, 정상과 나쁨의 기준, 흔한 오해.
- 줄마다 180자 이하, `?` 하나의 글 900자 이하. 처음 보는 사람이 읽는 쉬운 우리말로 쓰고 번역투로 지어낸 말을 쓰지 않는다 — 화면 이름(제목·칩)이 어려우면 낱말 뜻 칸에서 풀어 준다. '처리방침' 낱말은 쓰지 않는다(060 — '정적 페이지'·'동의' 로).
- 같은 값을 다른 페이지·카드에서 보이면 자료 출처 칸은 같은 문장이다(개요 지금 접속·트래픽 지금 접속·서버 WS 접속, 개요 수집 원천·서버 수집 상태, 개요·서버 비용, 개요·서버 경보). 보여 주는 것은 그 카드가 그리는 모양(지금 값·흐름)에 맞춘다.
- 칸 이름이 하나도 없는 글(이 스펙 첫 판의 두 줄 꼴)은 첫 줄 = 보여 주는 것, 둘째 줄 = 읽는 법으로 보인다(지금 그런 `?` 는 없다 — 다른 브랜치에서 옛 꼴로 더한 글이 깨지지 않게).

### 3.3 상세 판의 뜻 줄
- 카드의 ⤢·제목으로 연 상세 판은 머리 아래 안내 줄(`sheet-note`)의 맨 앞에 그 카드 `?` 의 보여 주는 것 칸 글을 둔다. 판 자신의 안내(일부만 읽음 등)가 있으면 그 뒤에 ` — ` 로 잇는다. 카드 `?` 가 없는 판(화면 페이지 판, IP 상세)은 판 자신의 안내만.

### 3.4 '누가' 상세 판
- 판 머리 단위 `기기 · OS · 브라우저 · 요청 종류`. 그림 대신 네 묶음을 위아래로 둔다. 묶음마다: 제목 + 흐린 분모 글(`브라우저로 온 방문자 n명 기준` / 요청 종류는 `모든 요청 n건 기준`) + 한 줄 설명 + 항목 행(이름 · 막대(묶음 안 비율) · 수 · %). 항목은 수 내림차순, 0 은 뺀다.
- 묶음 설명: 기기 = '방문자가 쓴 기기 — 화면 크기가 아니라 브라우저 정보로 가른다', OS = '방문자의 운영체제', 브라우저 = '방문자의 브라우저 — 카카오톡·네이버 같은 앱 안 브라우저는 따로', 요청 종류 = '서버에 온 모든 요청을 보낸 쪽의 종류 — 일반 브라우저만 방문자로 센다'.
- 요청 종류 항목마다 흐린 설명 — 이름과 글은 082 §3.1(일반 브라우저·검색 로봇·AI 로봇·링크 미리보기·자동화 도구·그 밖 봇·스캐너·운영자 접속·브라우저 정보 없음).
- 아래 표는 그대로(묶음·이름·수·묶음 안 비율, 찾기·정렬·CSV) — 정렬 기본은 묶음 순서(기기·OS·브라우저·요청 종류) 다음 수 내림차순.
- 방문자 값이 없을 때(처리방침 시행 전 등) 기기·브라우저는 브라우저로 연 페이지로 센다는 066 규칙 그대로 — 그때 분모 글은 `브라우저로 연 페이지 n건 기준`.

### 3.5 '화면' 페이지 쓰는 법
- 고르기 줄 위에 접는 안내 `이 페이지 쓰는 법`(`<details>`). 페이지를 열 때마다 펼쳐 둔다 — 접은 상태는 기억하지 않는다(관리자 화면은 브라우저 저장소를 쓰지 않는다, 064).
- 내용(목록 다섯): ① 이 페이지는 동의한 방문자가 보낸 화면 이용 통계(우리 서버, Clarity 아님)를 실제 페이지 위에 겹쳐 그린다 — 동의한 사람만이라 수가 작다. ② 위 칩에서 화면(랜딩·대시보드 탭·정적 페이지들)과 기기(PC·휴대폰)를 고른다. ③ 보기 — 요소(단추·링크마다)·영역(덩어리마다)·깊이(어디까지 내려왔나). 지표 — 클릭·마우스 올림(PC)·보인 시간. ④ 진할수록 많다. 빗금은 거의 안 닿은 곳, '표본 적음' 이면 숫자를 믿지 않는다. ⑤ 오른쪽 표의 행을 누르면 그 요소로 화면이 움직이고, ⤢ 로 전체 표·CSV.

### 3.6 Clarity 안내 줄
- Clarity 페이지 머리 아래 한 줄(모양 없음 — 경고가 아니다). Clarity 요약(040 — 받은 시각 `fetchedAt` 앞 24시간의 `traffic.sessions`, 6시간마다·이 페이지를 열 때만 다시 받는다)과 화면 이용 통계 피드(052 `days=1`, 오늘 KST 의 `rows[].pv` 합)로:
  - Clarity 세션 0 이고 통계 페이지 보기 > 0 → `Clarity 가 {받은 시각 KST} 에 받은 최근 24시간 세션은 0 이다 — 그 뒤의 방문은 다음 받기(6시간마다, 이 페이지를 열 때)에 들어간다. 같은 동의로 도는 화면 이용 통계는 오늘 페이지 보기 n회(시각 없는 날짜별 합이라 Clarity 의 24시간과 바로 견주지 못한다). 지난 기록은 Clarity 열기에서 본다.`
  - 둘 다 0 → `Clarity 가 {받은 시각} 에 받은 최근 24시간 세션 0 · 오늘 화면 이용 통계 0 — 동의한 방문이 없어 비는 게 정상이다. 지난 기록은 Clarity 열기에서 본다.`
  - Clarity 세션 > 0 → 줄 숨김. 어느 피드든 ok 가 아니면 숨김.
- 어긋났다고 단정하지 않는다: 통계는 시각이 없는 날짜별 합이라 Clarity 의 '받은 시각 앞 24시간' 과 겹치는 몫을 알 수 없다. 2026-10-16 운영 — 이 줄의 첫 판이 '오늘 2회인데 Clarity 0 → 토큰 확인' 으로 경고했지만, 받은 두 번(10-14 04:02·10-16 09:56)의 24시간에는 동의한 방문이 실제로 없었다(동의 방문은 10-09 46회·10-10 3회, 그리고 10-16 에 2회 — 날짜별 합이라 시각은 모른다).

### 3.7 트래픽 그림의 WS 칸
- 개요 트래픽 카드와 트래픽 상세 판의 셋째 칸·계열 이름 `WS 접속` → `대시보드 동시 접속`, 카드 단위 `시간별 · 브라우저로 연 페이지 · 5xx · 대시보드 동시 접속`.
- 두 값은 단위가 다르다 — 브라우저로 연 페이지는 **한 시간에 열린 페이지 수**(랜딩·처리방침 포함, 위장 봇 포함), 대시보드 동시 접속은 **그 순간 열려 있는 대시보드 탭 수의 5분 최댓값**(027 게이지 — `/ws/spreads` 연결, 랜딩만 본 방문자는 0). 그래서 동시 접속이 페이지 수보다 작은 것이 정상이다. 이 문장은 트래픽 카드 `?` 의 읽는 법 칸에 쓴다.

## 4. 검증
- node(066 방식 가짜 DOM): 글 → 칸 나누기(칸 넷·낱말 줄·칸 이름 앞의 줄·칸 이름 없는 두 줄); `?` 누름 → 말풍선 열림·칸마다 칸 이름·글·낱말 목록·`aria-expanded`; 같은 `?` 다시 누름·밖 누름·페이지 스크롤·Esc 로 닫힘, 말풍선 안 누름·스크롤로는 안 닫힘; 마우스로 연 것이 말풍선으로 옮겨 가면 남고 둘 밖으로 나가면 닫힘; 타일 안 `?` 누름이 타일의 지표를 바꾸지 않음; 한 줄 글은 보여 주는 것 칸만; 글자는 글로만(`<img onerror>` 가 요소가 되지 않음); 자리(아래·위·둘 다 모자랄 때 넓은 쪽 높이·600 한도·좌우 화면 안).
- 정적: 모든 페이지의 `?` 글이 §3.2 칸 규칙(칸 이름·순서·꼭 있는 칸 셋·낱말 줄 꼴·줄 180자·글 900자), 페이지 안 `?` 수가 066 의 카드 수 이상(빠진 카드 없음). 표 칸 머리 `?` 글의 칸 규칙은 082 시험이 본다.
- 상세 판: 카드 `?` 가 있는 판의 안내 줄이 그 보여 주는 것 칸 글로 시작.
- 누가: 묶음 넷의 분모(방문자 / 모든 요청)·막대 폭(묶음 안 비율)·0 항목 빠짐·요청 종류 설명 여덟·방문자 값 없을 때 분모 글.
- Clarity 진단: 세 경우(0·n / 0·0 / n) 와 피드 오류에서 숨김.
- 트래픽 그림 셋째 칸 이름 `대시보드 동시 접속`.
- 브라우저(가짜 피드 `admin-fake-feeds.py`): 여섯 페이지에서 `?` 누름·Esc·휴대폰 폭 390px 에서 말풍선이 화면 안·긴 글은 말풍선 안 스크롤, 화면 페이지 안내 접고 펴기, 콘솔·CSP 오류 0.
