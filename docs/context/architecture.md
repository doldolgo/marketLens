# architecture.md — 구조

> 이 문서는 현재의 핵심 설계 결정과 구현 경계를 쓴다. 기능별 구현 상태는 `status.md` 가 말한다.

## 핵심 설계 결정
- **실시간 시세의 기준은 `live_store`(LiveStore)다.** 실시간 조회 API 는 메모리만 읽고(스프레드 표 푸시는 api 가 Redis 구독으로 — 017), `/history/*` 와 랜딩 요약 `/landing`(022 — 1분 봉 1시간·사건 7일) 만 InfluxDB 를 조회한다. HTTP 조회 경로에 S3 호출은 없다. Redis 를 HTTP 가 만지는 곳은 `GET /spreads`(키 `spreads:latest` 읽기·`spreads:want` 쓰기, 018)와 `GET /landing`(`spreads:latest` 읽기만, 022) 둘이고(029 의 관리자 상태 `GET /admin/status` 는 Redis·Influx 에 ping 만, 034 의 `/admin/alerts` 는 `alerts:log` 읽기, 035·040 의 `/admin/clarity` 는 `admin:clarity`·`admin:clarity:pages` 읽기·쓰기, 052 의 `/admin/attention` 은 `attn:d:*` 읽기 — 052 의 `POST /attention` 은 Redis 를 부르지 않고 api 메모리에 더한다) 그 밖은 WebSocket 푸시의 구독뿐이다.
- **거래소 시세는 WebSocket 상시 연결로만 받는다.** 업비트·빗썸은 호가·현재가 스트림(001), 바이낸스는 depth20·miniTicker 스트림(012), 바이빗은 orderbook.200 스냅샷+델타·publicTrade 스트림(019), 비트겟은 books15 스냅샷·trade 스트림(020), OKX 는 books5 스냅샷·trades 스트림(045). perp 는 바이낸스 depth5@500ms(`/public`)+!markPrice@arr@1s(`/market`) 스트림(046)이고, **바이빗·비트겟 perp 만 예외로 REST 전체 티커를 매초 1회 받는다**(046 — 심볼별 WebSocket 티커가 초당 약 8,400 프레임이라 수집기 CPU 를 두 배로 만들었고, 갭 표는 1초 틱이라 1초 지연이 손해가 아니다, 2026-10-08 결정). REST 는 그 밖에 "지금 어떤 코인이 있는가"(마켓·심볼 목록, **매초**)와 입출금 상태(60초), perp 목록·펀딩 주기(10초·60초)에 쓴다 — 목록이 바뀐 초에 구독을 더하고 지운다. 여섯 거래소 모두 SSE 는 제공하지 않는다 — 선택지는 WebSocket 뿐이다.
- **저장은 세 계층을 순서대로 흐른다(009).** LiveStore 는 최신 시세와 **최신 틱 1장**을 들고, 새 틱이 만들어지는 순간 직전 틱이 Redis 로 인계된다. Redis 는 Influx 로 아직 옮기지 못한 틱만 들고(원문이 아니라 Influx 가 저장할 모양 그대로), 60초마다 전량이 Influx 로 옮겨진 뒤 비워진다.
- **원문은 S3 에 남긴다(010).** 거래소가 준 WebSocket 프레임·REST 응답 본문을 가공하지 않은 텍스트 그대로 원문 싱크에 넘기고, 거래소별로 **분마다 객체 1개**를 S3 `raw/` 에 쌓는다. 시세 프레임은 심볼·종류마다, 매초 오는 마켓·심볼 목록 응답은 거래소마다 그 분의 마지막 1건만 남기고(용량 — 하루 0.3~0.5GB), 입출금·핸드셰이크 거부 본문 같은 나머지 응답은 전량 남긴다. 쓰는 필드가 바뀌어도 재수집 없이 분 단위로 재생하기 위한 저장소다.
- **시세 커넥터는 공통 인터페이스를 구현하고 코드를 공유하지 않는다.** 거래소별 메시지 형식·quirk 는 각 커넥터 안에서만 흡수한다. 새 거래소 추가는 커넥터 하나 추가다.
- **도메인 계산은 가능한 한 순수 함수로 작성한다.** 네트워크·DB 같은 I/O 의존성은 인자로 주입하고 변경 가능한 전역 상태를 사용하지 않는다. 틱 생성과 표 계산은 `await` 없이 끝난다 — 한 계산 안에서 교체 전후 호가가 섞이지 않는 유일한 근거다.
- **입출금 상태는 `open(true) / closed(false) / unknown(null)` 세 상태를 구분한다.** `unknown` 을 `open` 으로 처리하지 않는다.
- **프로세스 역할은 `ROLE`(collector | api)다(016).** collector 는 uvicorn worker 1개 — `live_store` 가 프로세스 메모리라서, 다중 worker 를 쓰려면 프로세스들이 공유하는 외부 저장소로 먼저 이전해야 한다. api 는 메모리 저장소를 갖지 않고 Influx 만 읽으며(`/history/premium`·`streaks`·`streaks/bulk`·`candles`), 접속자가 있는 동안 Redis 채널 `spreads` 를 구독해 `/ws/spreads` 접속자에게 표를 민다(017). `GET /spreads` 는 두 역할 모두 Redis `spreads:latest` 를 돌려준다(018) — 스프레드 탭이 보는 컨테이너는 api 하나다. 랜딩 요약 `GET /landing`(022)도 두 역할 모두에 있고 배포에선 nginx 가 api 로만 보낸다.

## 성능 원칙
2026-09-28 성능 개선에서 구현한 규칙이다. 새 기능과 고치는 기능은 모두 따르고, 벗어나야 하면 그 스펙에 이유를 적는다.
- **매초·메시지마다 도는 경로에서는 행마다 객체를 만들지 않고, 거래소·시장 단위 값은 한 번만 구한다.** 표는 시장(거래소, 코인) 재료를 처음 쓰일 때 한 번 만들고 정렬 없이 순서대로 행을 만든다. 틱은 조합을 한 번 훑고 망 판정은 회차 메모를 표와 나눠 쓴다. 분 닫힘·flusher 는 점 객체 없이 줄을 바로 만든다(001·003·006·009·014).
- **바뀐 것만 다시 만든다.** spark 는 값이 바뀐 조합만 새 목록·조각, 사건 판정은 문턱 아래이고 열린 사건이 없는 행을 건너뛰고, 매초 목록 응답은 본문이 직전과 같으면(해외는 시각 필드 제외) 파싱하지 않고, 해외 시세 메시지는 집계 `last_message_at` 만 올린다(001·009·012·013·019·020).
- **같은 표·응답을 여러 번 직렬화·압축하지 않고 한 번 만든 바이트를 재사용한다.** 표 JSON 은 spark 조각을 끼워 한 번, 허브는 delta·snapshot 을 표 1장당 한 번 압축해 접속자 전원에게 같은 바이트, `GET /spreads` 의 gzip 은 표 텍스트당 한 번, `/history/events`·`candles` 는 공유 캐시가 원본·gzip 바이트를 들고 같은 키 조회 하나를 같이 기다린다(005·013·014·017·018).
- **수신 경로에서 같은 프레임을 두 번 파싱하지 않는다.** 원문 싱크는 커넥터가 받은 문자열을 참조로만 붙이고, 줄 조립·JSON 검사는 창을 닫을 때 스레드에서 살아남은 원문에만 한다(010).
- **요청 경로의 큰 JSON 은 이벤트루프에서 인코딩하지 않는다.** `/history/*` 는 조회·빌드·인코딩을 스레드 작업 하나로 끝내 루프에는 bytes 만 오고, 무거운 세 조회(premium·streaks·bulk)는 기간 상한과 동시 1개 게이트(돌고 있으면 429·`Retry-After: 1`)를 두고 원값을 점 목록 없이 흘려 읽는다. 루프에서 인코딩하는 큰 JSON 은 틱 안의 표 1장뿐이다 — 틱과 같은 동기 구간이 계약이라서다(005·013·014·017).
- **HTTP·인계 gzip 레벨은 6이다.** 전역 미들웨어·미리 압축하는 응답·허브 프레임·틱 인계가 모두 같다 — 9 는 압축 CPU 가 2.5배인데 크기는 1~5% 작을 뿐이고 수집 박스는 코어가 1개다(001·009·017·018).
- **상한은 '조합 수 × 시간'으로 정하고, 조합 수가 늘면 다시 정한다.** Redis `ticks` MAXLEN 10,800(3시간, ≈0.44GB — Redis 600MB 안), 인계 큐 600(10분), 봉 미전송 30,000줄(≈20분), 사건 미전송 1,000(복원이 닫은 점은 따로)(009·013·014·021).
- **프로세스는 기동을 마친 직후 GC 를 정리한다** — `gc.collect()` → `gc.freeze()` → 세대 임계 (2000, 10, 10). 기동 객체를 전체 수집에서 빼고 수집 빈도를 줄인다. 1만대 임계는 순환 쓰레기가 치워지지 않아 쓰지 않는다(001·016).
- **숨은 화면은 조회하지 않고 다시 그리지 않는다.** 기록 탭은 처음 볼 때 받는 청크이고 기록 탭과 브라우저 탭이 보이는 동안만 60초 재조회한다. 계속 숨은 탭은 셸 리렌더에서 건너뛰고, 스프레드 표 행은 memo·`content-visibility` 로 보이는 글자가 바뀐 행만 그린다(002·003·013·014).
- **수식 자체보다 둘레를 줄인다.** 순수 산술은 틱의 1.4%·표의 5.9% 라 식 변형·증분 틱·numpy 는 이득이 없다(비트만 바뀌거나 느려진다). 줄일 곳은 객체 생성·직렬화·파싱·중복 계산이고, 줄인 경로는 결과 바이트가 같음을 테스트로 지킨다(표·틱·원문 객체·응답 인코딩 — 001·003·005·010·017).

## 런타임 구성
- **server/**: Python 3.12, FastAPI, httpx, websockets, redis(asyncio), influxdb-client, boto3, pyjwt, pydantic v2, pydantic-settings. 로컬 포트 8000. 상시 태스크(collector 역할 — api 는 017 구독 태스크 1개(접속자가 있을 때만) + 접속마다 보내기 태스크 + 052 화면 영역 통계 10초 묶음 쓰기 태스크 1개(끌 때 한 번 더 보낸다) + `SLACK_WEBHOOK_URL` 이 있으면 025 알림 태스크 + `STATSD_ADDR` 가 있으면 027 게이지 태스크 + DB-IP 받기 데몬 스레드 1개(039 — 게이트 뒤 접속 요약이 판을 필요로 할 때만 뜨고 끝나면 사라진다)): 업비트·빗썸 스트림 각 1, 바이낸스·바이빗·비트겟 샤드 각 3 + 재조정 루프(60초), 마켓 우주 갱신 루프(매초 — 목록 5개 병렬, 본문이 직전과 같으면(해외는 시각 필드 제외) 커넥터가 파싱 생략, 실패는 직전 목록 유지·거래소·원인당 60초 1줄 로그), 틱 루프(1초), Redis 인계 큐, flusher(60초), 원문 닫기 회차(1초, 업로드는 데몬 워커 스레드 1개), 입출금 조회(60초), `collect_fail` 쓰기 큐 태스크, `premium_event` 쓰기 태스크(점이 생기면 즉시·없어도 60초 회차 — 60초 갱신 회차마다 열린 사건 사본을 Redis 에도, 종료 때 사본 저장·미전송 쓰기 1회), `candle` 쓰기·롤업 태스크(분이 닫히면 즉시·없어도 60초 회차 — 1m 을 5,000줄씩 쓴 뒤 같은 회차에 5m→1h→4h→1d), 017 표 게시 보내기 태스크(표는 접속자와 무관하게 매 틱 — `spreads:want` 는 읽지 않는다)·구독 허브(로컬 단일 프로세스는 자기 게시를 자기 구독 — 접속자가 있을 때만, 0명 30초면 구독을 닫는다), 관리자 피드 AWS 읽기 전용 데몬 스레드 1개(034 — 관리자 페이지가 `/admin/aws`·`/admin/alerts` 를 부를 때만 생긴다). 두 역할 모두 `SLACK_WEBHOOK_URL` 이 있으면 025 알림 기록 태스크가 보낸 알림마다 잠깐(2초 안) 뜬다(034). 두 역할 모두 기동을 마친 직후(요청을 받기 직전) GC 를 정리한다 — `gc.collect()` → `gc.freeze()` → 세대 임계 (2000, 10, 10)(001 §3.1, 2026-09-28 결정: 기본값이면 전체 수집이 거의 매초 루프를 멈추고, 1만대면 순환 쓰레기가 안 치워진다).
- **web/**: React 19, TypeScript, Vite. 런타임 의존성은 react·react-dom·lightweight-charts(기록 탭 캔버스 차트) 셋이다. 기록 탭 코드(차트 라이브러리 포함)는 첫 화면 번들에서 빠진 별도 청크라 처음 볼 때 받는다(002). 대시보드는 `/app/` 아래에 산다(Vite `base: '/app/'`) — `/` 는 React 밖의 정적 `public/landing.html` 이 nginx 로 서빙된다(022 — 스크립트가 요약 API `/api/landing` 을 페이지가 보이는 동안 10초마다 부른다. WebSocket·`/api/spreads` 는 부르지 않는다). `/privacy` 는 번들 밖 정적 방침(`public/privacy.html` — 외부 자원 없음, nginx 가 CSP 를 붙인다, 032). 랜딩·대시보드는 `public/clarity.js` 가 동의 창(세 칸)을 띄우고, 동의(`kt.analytics=granted`·`kt.analytics.v` 가 지금 판)·GPC 아님·호스트·ID 가 맞을 때만 Microsoft Clarity 태그를 부른다(033) — 관리자·처리방침 페이지는 부르지 않는다. 화면 영역 이용 통계(052)는 `public/attention.js` 가 랜딩·대시보드·처리방침·검색어 페이지 둘에서 같은 동의 판정일 때만 `data-area` 영역의 보인 시간·seen·클릭을 세어 `/api/attention` 으로 보낸다. 로컬 포트는 5173 이고, 배포 컨테이너의 nginx 는 80번 포트를 사용한다. 호스트 포트는 `WEB_PORT` 로 정한다.
- **저장소**: InfluxDB 2.7 OSS(org·bucket `marketlens`, Flux) — 김프 이력. Redis 7 — 틱 버퍼(AOF, Influx 로 옮기기 전까지만). S3(`marketlens-spreads-snapshot`, ap-northeast-2, 접두사 `raw/`) — 거래소 원문 아카이브. 모델은 `db.md`. 테스트에서는 셋 다 띄우지 않는다(fake·fakeredis). S3 자격증명은 SDK 기본 탐색(로컬 `~/.aws`, EC2 IAM 역할). 배포에서 Redis·Influx 는 data 박스에 있고 server·api 가 사설 IP(루트 `.env` 의 `DATA_HOST`)로 붙는다(021).

- 스트림이 끊기면 행은 남고 그 거래소의 `last_message_at` 이 멈춘다. `/spreads` 의 `age`·`status` 는 행이 아니라 **거래소 스트림의 마지막 수신 시각** 기준이다(조용한 코인의 호가는 안 바뀌어도 현재값이다). 단 행 자체(`updated_at`)가 **300초** 이상 안 바뀌면 `age` 는 그 행의 실제 경과 초라 stale 로 보인다(거래 정지·심볼 장애 — 스트림은 살아 있는데 그 코인 프레임만 안 오는 상태).
- 입출금 상태 API 는 틱 루프가 60초 주기로만 조회해 캐시하고, 행이 새 메시지로 교체돼도 그 3필드는 물려받는다. 키가 없으면 `null`(모름). 망 판정은 core 공용 함수 하나로 `/spreads` 행과 틱이 같이 한다(024) — 틱의 입출금 4상태는 006 판정값이고 망 이름 2개(국내·해외 표시명)를 함께 싣는다. 빗썸은 키가 필요 없다.
- `GET /health` 와 틱 루프는 기능 폴더가 아니라 앱 진입점 소관이다. `/health` 는 025 이후 마지막 틱이 30초 안에 있었는지를 답한다(200 ok / 503). 밖에서는 `/api/health`(collector)만 열고, api·Redis·Influx 는 canary 가 본다(027). 관리자 페이지(029, :8081)는 두 역할의 `/health` 와 api 의 `/admin/status`(WS 접속 수·Redis·Influx·버전)를 함께 보고, 034·035 피드 넷으로 경보·지표·canary·예산·알림 기록·접속 요약·Clarity 를 더한다(036). 상세는 `/health/collect`(011).
- USDT 시세는 별도 호출 없이 국내 거래소의 `KRW-USDT` 호가 메시지에서 추출한다. 최우선 매도호가가 rate_ask(USDT 살 때), 최우선 매수호가가 rate_bid. 거래소별 ask/bid. 은행 환율은 어디에도 쓰지 않는다(product.md 용어).
- `POST /refresh` 는 시세를 묻지 않는다 — 마켓 우주 갱신·재구독·입출금 재조회를 즉시 시키는 진단용 트리거다.
- 재기동 시 시세는 스트림 스냅샷으로 수 초 안에 복구되고(스트림은 복원보다 먼저 연다), 이력 24시간(011)과 spark 30분(009)은 Influx 에서, 진행 중 사건(013)은 Redis 사본에서(없으면 Influx) 되읽는다. Redis 에 남아 있던 틱은 다음 flusher 회차에 옮겨진다.

## 데이터 흐름 (FE)
- 스프레드 표는 WebSocket `/ws/spreads` 연결 1개(017), 나머지는 `fetch` 폴링. 상태관리·라우터·스타일 라이브러리 없음.
- API base: `VITE_API_BASE` (미설정 시 `/api`). dev 는 vite proxy `/api → http://localhost:8000` (prefix strip — 허용 목록과 무관하게 모든 `/api/*`), 배포는 nginx 허용 목록(028)만 넘긴다.
- 폴링 실패 시 직전 데이터 유지.
- 번들 밖 `public/attention.js`(052)는 React 와 무관하게 `data-area` 를 단 요소를 IntersectionObserver(문턱 0)·애니메이션 프레임당 한 번 `getBoundingClientRect`·MutationObserver(1초에 한 번 찾기)로 보고, 셸은 사용자가 탭을 바꾼 뒤(첫 그리기 제외) `window` 에 `kt:tab`(`detail` = 탭 id)만 낸다 — 셸은 통계를 모른다.
- 셸의 공유 피드가 탭 공통 데이터를 들고, 1.5초 tick 은 셸이 돌린다. `/ws/spreads` 구독(snapshot 통째 교체·delta 키 제자리 병합, 10초 무응답 재연결·백오프 — 대기는 백오프의 0.5~1.5배, 폴링 fallback 없음)은 spreads 기능(017)이, `/health/collect` 5초 폴링은 health 기능(011)이 제공한다. 기록 탭은 처음 볼 때 받는 별도 번들 청크이고, 탭이 보이는 동안만 `/history/events` 60초 재조회(013 — 조회 창 끝은 60초 경계)와 `/history/candles` 청크 캐시(014 — 봉 종류 → 계층, 쌍마다 360창 청크, LRU 120청크, 최신 청크만 60초 재조회·같으면 다시 그리지 않음, 계층 안 접기)를 쓴다. 계속 숨은 탭은 셸 리렌더에서 다시 그리지 않는다.

## 계약 규칙 (BE ↔ FE)
- BE 내부는 snake_case 를 사용한다. HTTP JSON 키와 복합어 쿼리 파라미터는 모든 엔드포인트에서 camelCase 를 사용한다. 정확한 스키마는 각 기능의 모델과 타입이 정의한다.
- `/spreads` 최상위 `warnings: list[str]` — USDT 시세 60초 미갱신 경고. 없으면 빈 배열(키는 항상 존재). (스펙 008)
- 응답 압축: GZip 미들웨어를 앱 전역에 켠다 — `/history/streaks/bulk` 같은 수 MB JSON 때문. 레벨은 6(core 설정 상수 — 9 는 압축 CPU 가 2.5배인데 크기는 1~5% 작을 뿐이고 수집 박스는 코어가 1개다, 001 §3.1 2026-09-28 결정). `GET /spreads`(018)·`/history/events`(013)·`/history/candles`(014) 는 같은 레벨로 미리 압축해 둔 바이트를 gzip 을 받는 요청에 `Content-Encoding: gzip`·`Vary: Accept-Encoding` 과 함께 직접 준다 — 미들웨어는 이미 인코딩된 응답을 건너뛴다. 정적 파일은 nginx 가 빌드 때 만든 `.gz` 를 준다(007). `/history/*` 의 JSON 인코딩은 스레드에서 끝나 루프에는 바이트만 온다(005 §3.4).
- FE 가 소비하는 응답 스키마를 변경할 때는 같은 변경에서 BE 모델과 FE 타입을 함께 수정한다.
- 비즈니스 에러는 `{"error": {"code": str, "message": str, "detail": any}}` 형식이다. 인증 실패와 FastAPI 요청 검증 실패(422)는 `{"detail": ...}` 형식을 사용한다. 처리 안 된 예외도 같은 형식의 500(`internal_error`, 내용 없음)이다(025).
- 공개 `/api` 는 허용 목록이다 — 웹·감시가 새 API 를 부르면 그 스펙이 nginx 허용 목록(과 `tests/test_deploy.py` 의 `PUBLIC_API`)에 한 줄을 더한다. 목록 밖은 nginx 가 앱과 같은 404 JSON 으로 답한다(028).
- 공개 페이지는 `admin.kimptrack.com` 안에서만 틀에 들어간다(053) — 공개 nginx 의 랜딩·대시보드·처리방침·검색어 페이지 둘에 CSP `frame-ancestors 'self' https://admin.kimptrack.com`(`X-Frame-Options` 없음), 관리자 화면 CSP 는 `frame-src https://kimptrack.com` 하나를 더 연다. 틀로 띄운 페이지는 `kt-overlay=1` 일 때 세지 않고(attention.js 덮어 보기·clarity.js 건너뜀) 그 문서 요청은 038 운영자 흔적이다.
- 관리자 경로는 공개 server 에 두지 않는다 — 관리자 server 는 web nginx 의 :8081 이고 8081 은 게시하지 않는다(029). 공개 server 에 `server_name` 으로 가르거나 caddy 에 admin 사이트를 두면 Host·SNI 위조로 로그인을 건너뛴다. 들어오는 길은 Cloudflare Tunnel 하나다 — serve 의 cloudflared 가 Access 로그인을 통과한 요청만 :8081 로 넘기고, 로그인은 앱 밖(Cloudflare Access)에 있다(030).
- 기록 항목·목적·보관·받는 곳(외부 스크립트·글꼴 포함)을 바꾸는 변경은 같은 PR 에서 `web/public/privacy.html` 을 고친다(032). 이전 판은 `privacy-<시행일>.html` 로 남긴다. 항목·목적·보유 기간·받는 곳이 늘거나 새로 생기는 개정은 시행일 7×24시간 전에 게시한다 — 이때는 같은 PR 대신 방침 PR(시행일 = 올린 날 + 9일, 머지 마감 = 시행일 − 8 의 18:00 KST)을 먼저 머지하고, 동작 PR 은 그 시행일의 날짜 게이트(`PRIVACY_V2_EFFECTIVE`)로 연다(037·038·039). 처리를 줄이거나 멈추는 변경과 사실 바로잡기는 같은 PR 에서 고치고 그날 시행한다.
- `/health` 의 503 은 상태 응답(`{"status","version","lastTickAt"}`)이라 `{"error":…}` 형식이 아니다 — uptime 서비스가 상태코드만 보고 판정한다(025).
- 관리자 피드(034·035)는 부분별 `state`(ok·unconfigured·denied·error·pending)를 담은 200 상태 응답이고, 오류 문장·ARN·계정 ID 를 싣지 않는다 — 외부 호출은 요청이 있을 때만, 실패는 code 만 WARNING.

## core 가 제공하는 계약 (기능·스펙이 공유하는 Protocol)
- 원문 싱크 `record(exchange, source, received_at_ms, payload, key=None)` — 동기·무예외(010 구현, 수신 경로가 호출). 받은 문자열을 참조로만 붙이고 줄 조립·JSON 검사는 창을 닫을 때 한다. `key` 는 시세 프레임이면 `"<종류>:<원본 심볼>"`(`orderbook:KRW-BTC`·`depth20:BTCUSDT`), 매초 오는 마켓 목록 응답은 `markets:all`(업비트·빗썸)·`symbols:all`(바이낸스), 그 밖(입출금 REST 본문·핸드셰이크 거부·비시세 프레임·디코드 실패)은 None — 010 이 `key` 있는 줄을 분당 마지막 1건으로 솎는 데 쓴다.
- 틱 인계 `handoff(tick)` — 동기·무예외(009 구현, 틱 루프가 호출).
- 판정 결과 전달 — 틱 루프가 이력 추적기에 거래소별 성공/실패를 넘긴다(011 구현). perp 원천은 046 §3.8 — 현물 거래소 전부 뒤에 같은 추적기로.
- 사건 감지 `observe(tick)` — 틱 루프가 매초 현재 틱을 넘긴다(013 구현, 동기·예외 없음).
- 입출금 조회기 `refresh_if_due(client, force=False)` / `apply` / `failed` / `warnings` / `availability`(006 구현, 틱 루프가 호출 — `force` 는 `/refresh` 트리거가 쓴다).
- 해외 USDT 현물 심볼 집합 `id` / `refresh(client) -> int` / `bases() -> set[str]` / `set_universe(bases)`(012·019·020 커넥터가 각각 구현, 마켓 우주가 **목록**으로 받아 합집합을 만들고 확정될 때마다 각 커넥터에 `set_universe` 로 우주 전체를 넘긴다 — 자기 맵에 없는 base 는 커넥터가 무시한다). 커넥터를 꽂지 않는 테스트에는 빈 집합을 주는 기본 구현.

core 는 features 를 import 하지 않는다 — 구조적 타입(Protocol)으로만 알고 배선은 `main.py` lifespan 이 한다.

## 기능 폴더 기본 구조
기능에 필요한 파일만 둔다. BE 전용 기능은 web 폴더가 없고, API 를 호출하지 않는 mock 화면은 `api.ts`·`types.ts` 가 없어도 된다.

```
server/app/features/<name>/
  router.py     HTTP API가 있으면 APIRouter를 선언한다.
  service.py    기능 흐름을 조립한다. 계산은 가능한 한 순수 함수로 두고 I/O 의존성은 인자로 받는다.
  models.py     요청·응답 모델이 있으면 둔다.
  tests/        기능 테스트. 외부 네트워크는 fake로 대체한다.
web/src/features/<name>/
  Tab.tsx       해당 기능의 화면.
  api.ts        실제 API를 호출할 때 fetch 함수와 표시 전용 가공을 둔다.
  types.ts      실제 API 응답을 사용할 때 BE 응답과 맞는 타입을 둔다.
```

## 배포 토폴로지
EC2 3대(021), 같은 VPC·서브넷, 박스끼리는 사설 IP 로만 통신한다. compose 파일은 하나이고 서비스 7개(server=collector·api·web·caddy·influxdb·redis·cloudflared)에 profile 이 하나씩 있어 박스마다 자기 profile 만 띄운다 — cloudflared 의 `tunnel` 은 serve 박스 부속이라 배포가 토큰 파일이 있을 때만 따로 띄운다(030): `docker compose --profile <collect|data|serve> --env-file .env --env-file server/.env up -d --build`. `depends_on` 은 없다(의존 대상이 다른 박스).
- **collect**(c7g.medium) — `server`. 거래소 WebSocket·틱 루프·Redis 인계·flusher·S3 원문·입출금 조회. 호스트 8000(serve 보안그룹만), 탄력 IP(업비트 허용 IP), `marketlens-s3-snapshot` 은 이 박스에만(세 박스 모두 에이전트 정책, data·serve 는 `marketlens-cwagent` — 027), 역할에 관리자 읽기 인라인 정책 `marketlens-admin-read`(034).
- **data**(t4g.small, 스왑 1GB) — `redis`·`influxdb`. 호스트 6379·8086(collect·serve 보안그룹만). Influx 메모리 상한 — 쿼리 1개 256MB × 동시 2 = 512MB·쓰기 캐시 256MB·`GOMEMLIMIT` 700MiB·컨테이너 `mem_limit` 1300m(`memswap_limit` 같은 값 — 스왑 없이 재시작), Redis `maxmemory` 600mb `noeviction`(둘 합 1.9GiB, 021 §3.1).
- **serve**(t4g.micro, 스왑 1GB(027), 공개 주소 `https://kimptrack.com`) — `api`·`web`·`caddy`·`cloudflared`(030). 호스트 80(`WEB_PORT`)·443 은 caddy 가 쥔다(023) — `kimptrack.com` 은 Let's Encrypt 로 TLS 종단해 web(nginx :80) 으로, `www` 는 http·https 모두 apex 로 301(022), 그 밖의 호스트(탄력 IP `3.34.104.16` 직접)는 평문으로 web 에 넘기되 `X-Robots-Tag: noindex`. caddy 는 `caddy/Caddyfile` 디렉터리 바인드·배포 뒤 reload·도메인 블록 접속 로그 → 호스트 `logs/caddy/`(027, nginx 접속 로그는 끔) — api 가 `logs/caddy` 를 읽기 전용으로 읽는다(035) — 게이트 뒤 매달 download.db-ip.com 에서 DB-IP Lite 두 파일을 받아 메모리에만 둔다(039). nginx 의 공개 `/api` 는 허용 목록 여섯만 넘긴다(028) — `/api/health`·`/api/health/collect`·`/api/history/events` 는 `COLLECT_HOST:8000`(수집기)으로, `/api/history/candles`·`/api/landing`·`/api/ws/spreads`(WebSocket 업그레이드)는 같은 박스의 api 로(전부 정확 일치·접두 제거), 나머지 `/api` 는 404 JSON. `= /privacy` 는 방침 파일(no-cache·CSP — `/privacy.html`·`/app/privacy.html` 은 301, 032). 같은 nginx 에 web nginx 관리자 server :8081(게시 안 함) — 028 이전의 전체 `/api` 분기·교차 사이트 403·접속 기록 → 호스트 `logs/admin/`(029). cloudflared(profile tunnel, 망 admin) → web 관리자 server :8081 — 밖으로만 나가는 연결(030, `admin.kimptrack.com`·Cloudflare Access, 토큰 파일 `secrets/cloudflared-token` 이 있을 때만, 설정은 대시보드 — `docs/runbooks/admin-access.md`). collect 의 `server` 는 `UVICORN_ROOT_PATH=/api` 라 API 문서가 `/api` 아래 스키마를 부른다(029).
박스 간 주소는 루트 `.env` 의 `DATA_HOST`·`COLLECT_HOST` 두 키다. 기본값이 서비스 이름이라 로컬은 `COMPOSE_PROFILES=collect,data,serve` 로 예전처럼 6개가 한 망에 뜬다. PR CI 는 server lint·format·pytest 와 web lint·build 를 실행한다. main push 는 워크플로가 data → collect → serve 순서로 SSH 배포한다(한 박스가 실패하면 뒤는 돌지 않는다). 상세는 스펙 007(deploy)·021(infra-split), 전환 절차는 `docs/runbooks/ec2-split.md`.
일곱 컨테이너 모두 compose 가 로그를 `json-file` 50MB × 3 으로 묶는다 — 회전 없는 로그가 디스크를 채우면 Influx 가 쓰기를 거부하고, 그 거부는 공간을 되찾아도 재시작 전까지 풀리지 않는다.
배포 workflow 의 성공은 EC2 명령 실행 성공만 뜻한다. 외부 URL 확인과 실패 시 자동 롤백은 아직 없다.
