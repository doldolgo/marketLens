서버 접속 기록

kimptrack.com으로 온 요청마다 한 줄을 남깁니다: 시각, IP 앞부분(IPv4는 마지막 마디, IPv6는 뒤 80비트를 지움), 접속 포트, 프로토콜·메서드·호스트, 경로와 쿼리(스프레드·갭·선선갭 화면의 검색어는 지움 — 기록 탭의 코인 칸 sym과 utm_*는 남음), 상태 코드·크기·처리 시간(대시보드 실시간 연결은 연결을 연 시간), 이전 페이지의 사이트 주소(도메인까지), 브라우저·기기 정보(User-Agent). 헤더·쿠키는 남기지 않고, 화면이 몇 초마다 부르는 조회와 감시용 요청은 기록하지 않습니다. www.kimptrack.com은 kimptrack.com으로 옮겨 주기만 하고 기록하지 않습니다. AWS 서울 리전의 서버 파일과 로그 저장소(Amazon CloudWatch Logs)에 둡니다. 로그 저장소에서는 서버가 기록을 보낸 때부터 90일을 셉니다.

(가) 운영자가 보는 관리자 화면을 위해 같은 서버가 이 파일을 읽어 최근 30일까지의 요약을 만듭니다. 요약에는 요청 수와 응답 상태, 경로·이전 페이지의 사이트·utm_source 값·대시보드 탭, 요청을 보낸 쪽의 종류(사람 브라우저·검색엔진·자동화 도구 등)와 기기·브라우저 종류, 대시보드 실시간 연결의 수와 시간, 최근 오류 요청 몇 줄이 들어가며, IP·브라우저 정보 원문은 넣지 않고 기기·브라우저는 종류 이름으로만 셉니다. 요약은 서버 메모리에서만 만들고 따로 저장하지 않아, 서버를 다시 시작하면 사라집니다.

(나) IP 앞부분으로 나라와 망 종류(국내 통신사·데이터센터 등)를 추정합니다. 서버가 공개 자료 DB-IP Lite(나라와 망 번호 ASN)를 받아 메모리에 올려 두고 찾으며, 방문자 정보는 밖으로 보내지 않습니다. 찾은 망 번호·조직 이름은 남기지 않고 망 종류만 셉니다.

(다) 같은 방문을 하루에 한 번만 세려고, IP 앞부분과 브라우저 정보를 원래 값으로 되돌릴 수 없는 값으로 바꿔 메모리에서만 씁니다. 바꾸는 방식은 서버를 다시 시작할 때마다, 그리고 날마다 달라집니다. 그 값에는 그날 페이지를 연 시각과 시간대, 들어온 길(검색·소셜·직접 등), 기기·운영체제·브라우저 종류(앱 안 브라우저면 어느 앱인지), (나)의 나라·망 종류(IPv6면 IPv6라는 표시만)를 붙입니다. 또 페이지의 스크립트를 받았는지(화면 분석 동의와 상관없이 페이지가 부르는 파일의 요청으로 판단), 대시보드에 실시간 연결을 했는지, 다시 온 방문인지(브라우저가 전에 받아 둔 사본으로 판단), 보안 허점을 찾는 요청이나 운영자가 연 흔적이 있었는지를 붙입니다. 이 값은 서버 메모리에 최근 30일까지만 둡니다.

(라) 이 판의 시행일 전에 남은 기록은 이전 판대로 24시간 요약에만 쓰고, 24시간을 넘는 (가)의 요약과 (나)·(다)에는 쓰지 않습니다.

화면 이용 기록 — Microsoft Clarity

랜딩과 대시보드에서 화면 분석의 세 가지에 모두 동의한 방문자에게만 돕니다(기본은 꺼짐 — 위 “화면 분석 동의 관리”). 받는 것: 페이지 주소(검색어는 뺌), 이전 페이지 주소(브라우저가 알려 주는 그대로 — 서버 기록과 달리 줄이지 않음), 누른 링크의 주소, 클릭·스크롤·마우스 움직임·화면 크기, 화면 내용(입력칸은 늘 가림), 보고 있는 탭과 기록 탭에서 고른 코인 이름·탭을 바꾼 일, 기기·브라우저·운영체제, IP 주소(Microsoft가 받아 대략의 위치를 추정), 쿠키 _clck·_clsk와 sessionStorage _cltk(7절). 받는 곳은 Microsoft Corporation(미국)이며, Microsoft는 이 정보를 Microsoft Advertising 제공 등 자기 목적에도 씁니다(Microsoft 개인정보처리방침에 따름). 한 사람분만 골라 지울 수는 없고 프로젝트를 통째로 지워야 합니다. KimpTrack은 동의한 방문자에 대해서도 Clarity에 광고용 쿠키를 저장하지 말라는 신호를 보냅니다 — 이 신호는 Microsoft가 받은 정보를 자기 목적에 쓰는 것까지 막지는 않습니다.

대시보드(/app/)를 열면 방문자의 브라우저가 Google Fonts(Google LLC, 미국)에서 글꼴을 직접 받습니다. 이때 IP·User-Agent·요청 주소·이전 페이지 도메인이 Google로 가고 쿠키는 가지 않으며, Google이 요청 기록을 남깁니다. 운영자만 보는 관리자 화면의 API 문서는 jsDelivr·fastapi.tiangolo.com·Google Fonts에서 화면 파일을 받습니다. 랜딩과 이 페이지는 외부 글꼴을 부르지 않습니다.

방문자 정보가 가지 않는 곳

운영 알림(Slack·AWS 경보·가동 감시)에는 방문자 정보가 가지 않습니다 — 알림에는 거래소 수집 상태와 오류 내용, 오류가 난 요청의 경로(쿼리 없음)만 실립니다. 거래소 원문 보관(Amazon S3)과 시세 저장소(InfluxDB·Redis)에도 방문자 정보는 없습니다.

화면 이용 기록(Microsoft Clarity)은 정보주체의 동의를 받아 처리합니다 — 수집·이용(개인정보 보호법 제15조 제1항 제1호), Microsoft에 제공(제17조 제1항 제1호), 미국으로 이전(제28조의8 제1항 제1호)을 칸을 나눠 각각 받고, 세 가지에 모두 동의한 방문자에게서만 모읍니다. 동의는 언제든 철회할 수 있습니다. KimpTrack은 나이를 확인하지 않으며, 동의 안내에 “만 14세 미만은 동의하지 마세요”라고 적습니다. 서버·관리자 접속 기록은 서비스를 제공하고 보안을 지키며 이용 통계를 내기 위한 정당한 이익(같은 항 제6호)으로, 그 목적에 필요한 범위에서만 처리합니다. 권리 행사 요청에 답하는 것은 법령상 의무(같은 항 제2호)이고, 그 밖의 문의 답변은 같은 항 제6호에 따릅니다.

3. 개인정보의 파기

KimpTrack은 보유 기간이 지난 기록을 아래 방식으로 지웁니다. 서버 접속 기록은 하루(또는 일정한 크기)마다 새 파일로 나뉘고, 보유 기간이 지난 파일은 다음에 파일을 나눌 때 자동으로 파일째 지워집니다 — 방문이 없는 동안에는 파일을 나누지 않아 지우는 때가 늦어질 수 있습니다. 관리자 접속 기록은 매일 새 파일로 나뉘고, 90개(90일)를 넘는 파일은 그때 자동으로 지워집니다. 로그 저장소(CloudWatch Logs)는 보낸 때부터 90일이 지난 기록을 AWS가 지웁니다 — 기간이 끝난 뒤 지우기까지 며칠 걸릴 수 있습니다. 문의 메일은 기간이 끝나면 운영자가 메일함에서 지우고 휴지통까지 비웁니다. Clarity 기록은 Microsoft가 보관하며, 2절의 기간이 지나면 Microsoft가 지웁니다(지우는 시점은 Microsoft 기준). 화면 분석 동의를 철회해도 이미 보낸 기록은 그 기간 동안 남습니다 — 바로 지우기를 원하면 8절대로 요청할 수 있고, 그러면 운영자가 Clarity 프로젝트의 기록을 통째로 지웁니다(지우는 시점은 Microsoft 기준). Microsoft가 자기 목적에 쓰는 정보는 이것으로 지워지지 않으며 Microsoft에 직접 요청할 수 있습니다(개인정보 문의). 법령에 따라 따로 보존하는 기록은 없습니다.
