이 절 읽는 법· 10초마다 · 경보·canary 60초
읽는 값
수집기·api 헬스, api 상태(연결 수·Redis·Influx), 거래소 수집 상태를 10초마다 읽고 CloudWatch 경보·canary 를 60초마다 읽는다. 이 탭이 보이는 동안만 부른다.
판정
일곱 재료(수집기·api·Redis·Influx, 거래소, CloudWatch 경보·canary)만 보고 위에서부터 알 수 없음(헬스 호출 실패) → 장애(수집기·api 상태가 ok 아님, Redis·Influx down, ALARM 경보, 거래소 끊김) → 주의(거래소 지연, canary 실패, 수집기가 경보·canary 를 읽지 못함) → 정상 이다. 띠의 판정 재료 일곱 가운데 흐린 ○ 는 판정에 넣지 않은 재료(연결 안 됨, 권한 없음, 이 화면이 그 값을 부르지 못함)이고, 지표·알림·접속·비용은 처음부터 판정 밖이다.
사유 줄
판정을 만든 까닭을 셋까지 적는다 — ALARM 경보는 둘까지 이름, 셋 이상이면 수. '상태 모름' 은 그 재료를 읽지 못했다는 뜻이고 판정은 바꾸지 않는다.
수집기
수집기 헬스와 마지막 틱이 지난 시간. 첫 틱 전은 starting, 30초 넘게 틱이 없으면 stale 이고 둘 다 장애다.
api
api 헬스 — Redis 에 남는 수집기 심장박동으로 같은 판정을 하고, Redis 에 못 닿으면 redis_down 이다. 아래 줄은 api 가 본 Redis·Influx 연결이고, 헬스가 정상이어도 하나가 down 이면 '저장소 끊김' 이다.
지금 접속
api 가 지금 들고 있는 대시보드 연결 수. 연결 수 — 사람 수가 아니다(탭마다 하나라 탭 둘이면 2, 숨긴 탭도 센다).
경보
CloudWatch 경보 가운데 ALARM 인 수 / 전체 수와 데이터 부족 수. 어느 경보인지는 인프라 절에서 본다.
canary
밖에서 사이트를 5분마다 점검하는 Lambda 의 최근 실행(11분 안에 끝난 것) — 통과·실패와 걸린 시간. 실패는 주의이고, 두 번(10분) 이어 실패하면 canary 경보가 울린다.
이번 달 비용
월 예산 가운데 한도 대비 실제가 가장 큰 것의 실제 사용액과 비율. 85% 이상이거나 AWS 예측이 한도를 넘으면 주의색, 100% 이상이면 장애색이지만 판정에는 넣지 않는다.
n분 전 값 · 오래됨
칸 머리의 경과는 그 값을 서버가 만든 뒤 지난 시간이다. 서버 갱신 주기의 세 배를 넘으면 '오래됨' 으로 칠한다.
상태 배지
연결 안 됨 = 그 기능이 이 서버에 켜져 있지 않다(자격·파일·토큰 없음), 권한 없음 = IAM 정책이나 조직 SCP 가 막았다, 불러오지 못함 = 부르다 실패했다, 첫 조회 중 = 서버가 아직 첫 값을 만드는 중이다. 배지 옆 작은 고정폭 글자는 서버가 준 짧은 사유다.
모양
● 정상 · ▲ 주의 · ✕ 장애 · ○ 판정 밖 · ? 알 수 없음 · … 기다림. 색만 보지 않도록 모양과 글자를 함께 붙인다.
시각
화면의 시각은 모두 이 브라우저의 시간대다. Clarity 가 준 값만 UTC 기준으로 센 값이다.
값 없음 · 값 1개뿐
차트에 값 있는 점이 0개·1개라 선을 긋지 못했다는 뜻이다. 경보 상태의 '데이터 부족' 과는 다르다.
마지막 갱신
머리의 시각은 이 화면이 마지막으로 값을 받아 온 때다. 탭이 숨으면 부르지 않아 멈춘다.

읽는 값
수집기의 수집 상태(거래소 다섯의 상태·최근 24시간 실패 구간)를 10초마다 읽는다. 수집기 메모리의 값이고, 수집기를 다시 시작하면 24시간 이력은 Influx 에서 되읽는다.
판정
거래소 하나라도 끊김이면 장애, 지연이면 주의로 개요 판정에 든다. 실패 구간·성공률은 판정에 넣지 않는다.
즉시 갱신
수집기에 마켓 목록·구독·입출금 상태를 지금 다시 읽힌다. 시세는 원래 실시간 스트림이라 평소엔 누를 일이 없는 진단용이고, 토큰은 입력칸에만 있고 저장하지 않는다.

이 칸 뜻
상태
마지막 성공 뒤 5초 미만이면 수집 중, 60초 미만이면 지연, 그 밖은 끊김이다. 수집기가 뜬 뒤 한 번도 성공하지 못했어도 끊김이다.
마지막 성공
수집기가 그 거래소를 마지막으로 정상 판정한 때. 1초마다 판정하고, 스트림이 연결돼 있고 30초 안에 시세가 왔으면 정상이다.
열린 실패 구간
지금 이어지는 실패 — 실패 종류 · n회(실패로 판정된 초의 수) · 이어진 시간이고, 60초를 넘으면 Slack 알림이 나간다. 연속 성공 3번이면 닫히고, 실패 종류가 바뀌면 그때 닫고 새 구간을 열어 n회·시간을 처음부터 센다(수가 줄어도 복구가 아니다).
1시간 성공률
(1 − 최근 1시간과 겹친 실패 구간의 초 ÷ 3,600) × 100 을 소수 1자리로 적는다 — 한 곳이 36초 끊기면 99.0% 다. 99% 를 넘으면 정상 범위이고, 요약 줄의 '전체 1시간' 은 다섯 곳의 평균이다.
마켓
그 거래소에서 지금 수집기 메모리에 든 마켓 수. 요약 줄의 '마켓' 은 다섯 곳의 합이다.
마지막 오류
24시간 안 가장 최근 실패 구간의 마지막 실패 — 시각 · 실패 종류 · HTTP 상태 · 오류 글 앞부분(전체는 마우스를 올리면). 오류 글은 거래소가 준 응답 본문이 있으면 그 글, 없으면 수집기가 적은 글이고, 흐린 글이면 그 구간은 이미 끝났다.
수집기 시작
수집기 프로세스가 마지막으로 뜬 시각. 배포하지 않았는데 바뀌었으면 수집기가 다시 시작된 것이다.
타임아웃 timeout
연결이나 호출이 제한 시간 안에 답하지 않았다.
연결 실패 network
연결을 맺지 못했거나 연결이 끊겼다(DNS·연결 거부 등).
rate limit rate_limit
거래소의 호출 한도를 넘었다(429 등).
차단 banned
거래소가 우리 IP 를 막았다(업비트 418 등).
거래소 오류 unavailable
거래소가 5xx 로 답했다(장애·점검).
요청 오류 bad_request
거래소가 우리 요청(구독 등)을 거부했다.
응답 오류 bad_response
받은 응답을 읽지 못했다 — JSON 이 아니거나 모양이 예상과 다르다.
스트림 정체 stale_stream
연결은 살아 있는데 30초 넘게 시세가 오지 않았다.

이 절 읽는 법· CloudWatch 경보·canary 60초 · 지표 5분
읽는 값
수집기가 AWS 서울의 CloudWatch 를 읽어 준 값이다 — 경보·canary 는 60초, 박스 지표는 5분마다 서버가 새로 읽고 화면은 60초마다 부른다. 지표는 지난 24시간을 5분 구간으로 나눈 점이다.
판정
경보 하나라도 ALARM 이면 장애, canary 최근 실행 실패와 수집기가 CloudWatch 의 경보·canary 를 읽지 못한 것(읽기 오류)은 주의로 개요 판정에 든다. 이 화면이 피드를 부르지 못한 것(호출 실패)과 박스 지표는 판정 밖이다 — 메모리·디스크·크레딧이 경보 기준을 넘으면 그 경보가 ALARM 이 되어 판정에 든다.
연결 안 됨
수집기가 AWS 자격을 얻지 못했다(AWS 밖 호스트·로컬 포함). 이 절·비용 절, 개요의 경보·canary·비용 칸, 접속 절의 24시간 선, 알림 절의 경보 이력(경보 행)이 비고 판정에서 빠진다.
권한 없음
IAM 정책이나 조직 SCP 가 그 읽기를 막았다. 그 부분만 비고, 값은 AWS 콘솔에서 본다.
카드 하나로 접힘
경보·지표·canary 세 부분이 같은 이유(연결 안 됨·권한 없음·같은 호출 실패)로 비면 절을 카드 하나로 접는다. 그때는 아래 카드와 그 '이 칸 뜻' 도 함께 숨는다.

EC2 시스템 상태검사가 60초 2점 연속 실패하면 울리고, AWS 가 그 박스를 복구(recover)한다.
CPU 크레딧 잔고 credit-balance
잔고가 최대 적립의 30%(data 173·serve 86) 밑으로 5분 3점 연속이면 울린다.
잉여 크레딧 과금 credit-surplus
잉여 크레딧 과금이 5분 1점이라도 0 을 넘으면 울린다 — unlimited 과금이 시작됐다는 뜻이다.
메모리 memory
메모리 가용률 10% 미만이 5분 이어지면 울린다(collect 는 5분 1점). 지표가 들어오지 않아도 울린다.
디스크 disk
디스크 사용률이 5분 1점이라도 80% 를 넘으면 울린다. 지표가 들어오지 않아도 울린다.
canary canary
canary Lambda 실패가 5분 2점 연속(10분)이면 울린다. 실행이 멈춰 점이 없어도 울린다.
사이트 5xx http-5xx
사이트의 5xx 응답이 5분 합 10 이상이면 울린다(/api/ws/spreads 는 세지 않는다). 점이 없으면 정상이다.
상태
ALARM = 조건을 넘었다, OK = 정상, 데이터 부족 = 평가할 지표 점이 들어오지 않았다. 메모리·디스크·canary 경보는 점이 없으면 데이터 부족이 아니라 ALARM 이 된다.
사유
AWS 가 적은 마지막 상태 변경의 까닭(앞 160자, 전체는 마우스를 올리면).
바뀐 지
그 상태가 된 뒤 지난 시간.

이 칸 뜻
네 단계
Lambda 가 5분마다 사이트를 밖에서 차례로 점검한다 — 첫 화면, /api/health, 최근 15분 1분 봉, 대시보드 WebSocket 표. 하나라도 실패하면 그 실행은 실패다.
최근 실행
최근 11분 안에 끝난 실행 가운데 가장 늦은 것의 통과·실패, 지난 시간, 걸린 시간. 끝난 실행이 없으면 그렇게 적고, 일정이 멈췄으면 10분쯤 뒤 canary 경보가 울린다.
24시간 실행·오류
CloudWatch 의 Lambda 실행 수·오류 수를 24시간 더한 값. 5분마다 돌아 실행 288 안팎·오류 0 이 정상이다.
실행 시간
실행 한 번이 걸린 시간의 5분 최댓값. 굵은 값은 24시간 최고이고, 작은 '마지막 5분 구간' 값은 몇 분 늦다.
로그 줄
최근 실행이 남긴 단계별 결과 — 'N단계 통과 (ms)' 또는 실패 글, 10줄까지.
박스 · 24시간
이 칸 뜻
박스 셋
collect(c7g — 수집기), data(t4g — Influx·Redis), serve(t4g — caddy·web·api). 메모리 경보가 있는 박스만 나오고, 이름에 마우스를 올리면 인스턴스 ID 가 보인다.
메모리 가용률
CloudWatch 에이전트가 잰 가용 메모리 비율의 5분 최솟값. 20% 이상이 정상이고 20% 미만 주의·10% 미만 장애다(점선 = 경보 기준 10%).
디스크 사용률
루트 디스크 사용률의 5분 최댓값. 70% 이하가 정상이고 70% 초과 주의·80% 초과 장애다(점선 = 경보 기준 80%).
CPU 사용률
EC2 CPU 사용률의 5분 평균. 색을 칠하지 않는다 — collect 는 수집기가 늘 높게 쓴다.
CPU 크레딧 잔고
t4g 박스(data·serve)가 기준보다 CPU 를 더 쓸 때 꺼내 쓰는 적립의 5분 최솟값. data 173·serve 86 이상이 정상이고 그 밑이면 장애색이다(점선 = 경보 기준).
스왑 사용률
값이 오는 박스만 5분 최댓값을 선으로 그린다(경보 없음). serve 는 스왑이 있지만 에이전트가 모으지 않아 '스왑 지표 없음' 이다.
지금 값
굵은 값은 마지막 5분 구간의 값이라 몇 분 늦다. 옆 작은 글은 24시간 최저(메모리·크레딧) 또는 최고(디스크·CPU·스왑)다.

    사람은 몇 명 왔나

    이 칸 뜻
    날마다 센 방문자 visitors
    하루(KST)마다 (가린 IP, 브라우저 정보) 짝을 따로 세어 더한 수 — 같은 사람이 이틀 오면 2 이고, 쿠키·브라우저 저장 없이 처리방침 개정 시행일부터 센다. 7일·30일의 큰 숫자는 그 합을 센 날수로 나눈 하루 평균이다.
    확인 confirmed
    그날 화면 스크립트(/clarity.js 또는 대시보드 연결)가 돈 흔적이 있는 방문자 — 하한이다. 광고 차단기를 쓰거나 스크립트를 끈 사람은 빠진다.
    브라우저 모양 shaped
    브라우저 이름을 달고 페이지를 연 방문자 — 상한이다. 스크립트를 돌리지 않는 위장 봇이 섞인다.
    다시 온 returning
    확인 방문자 가운데 그날 첫 페이지가 / 또는 /privacy 의 304(브라우저에 받아 둔 사본이 있음)였던 수. 랜딩이 바뀐 배포 날과 대시보드만 본 사람은 빠진다.
    스크립트가 돈 페이지 jsViews
    사람 브라우저 모양 요청이 /clarity.js 를 받은 줄 수 = 화면이 실제로 뜬 페이지 보기 수. 한 방문자가 여러 번 보면 여러 번이다.
    사람 모양 페이지 humanPages
    사람 브라우저 모양으로 화면 주소를 연 줄 수. 위장 봇이 섞인다.
    2 · 누가

    사람인가 봇인가

    이 칸 뜻
    걸러 내기 줄
    모든 요청에서 확인 방문자까지 좁혀 가는 다섯 칸이고, 칸 아래 % 는 앞 칸 대비 남은 비율이다. 마지막 칸만 방문자(날마다 셈)라 '1명이 평균 n쪽' 은 스크립트가 돈 페이지 ÷ 확인이다.
    종류 여덟 classes
    요청이 밝힌 User-Agent 로 가른 종류 — 사람 브라우저 모양 browser · 검색엔진 search · AI 수집기 ai · 링크 미리보기 preview · 자동화 도구 tool · 스캐너 scanner · 운영자 흔적 operator · 이름 없음 unknown. 막대는 모든 요청 대비 비율이고 값은 '요청 · 페이지' 다.
    탐색 경로 probes
    없는 관리 페이지(wp-·.env·/admin 등)를 찔러 보는 요청 줄. 브라우저 이름을 달아도 스캐너로 센다.
    운영자 흔적 operator
    출처가 localhost·사설 IP·IP 글자 그대로·Clarity 대시보드인 요청이고, 그날 그 짝은 방문자에서 뺐다. 운영자 IP 를 적어 두지 않아 보통 브라우저로 연 운영자 방문은 거르지 못한다.
    위장 봇 단서
    브라우저 이름을 달았지만 사람으로 보기 어려운 세 갈래 — 스크립트가 한 번도 돌지 않은 브라우저 모양(모양 − 확인), 데이터센터·클라우드 망의 브라우저 모양, 운영자 흔적 요청. 종류를 따로 만들지 않고 이 수로 드러낸다.
    3 · 어디서

    어느 나라·망에서, 어떤 길로 왔나

    IP Geolocation by DB-IP

    이 칸 뜻
    나라 geo.countries
    IP 앞부분(/24)을 DB-IP Lite 자료로 서버 메모리 안에서 추정한다 — 방문자 정보는 밖으로 보내지 않고, 자료의 정확도 지수는 81 이다. 방문자가 적은 나라는 (기타)로 묶는다.
    망 종류 geo.networks
    IP 가 속한 망 — 국내 통신사 telecom_kr · 해외 통신사 telecom · 데이터센터·클라우드 cloud · 기업·학교·기관 other · 자료에 없음 unknown. 한국이 (기타)로 묶인 창에서는 국내 통신사가 '통신사' 한 칸에 든다.
    들어온 길 channels
    그날 첫 페이지의 출처로 정한다 — 직접 direct · 검색 search · 앱 안 브라우저 inapp · 소셜·커뮤니티 social · AI 답변 ai · 다른 사이트 링크 referral · 캠페인(utm) campaign · 사이트 안 이동 internal · 첫 페이지 기록 없음 unknown. 출처가 없으면 직접이다.
    앱 안 브라우저 inApp
    카카오톡 kakaotalk · 네이버 앱 naver · 인스타그램 instagram · 페이스북 facebook · 라인 line · 다음 앱 daum · 밴드 band · 그 밖 앱 other. 앱 안 브라우저는 출처를 보내지 않는 일이 많다.
    외부 출처와 utm referrers·utmSources
    다른 사이트 링크의 주소(스킴·호스트만)와 페이지 주소의 utm_source 값을 페이지 줄로 센다 — 막대·% 는 사람 모양 페이지 대비다. 글자로만 보이고 누를 수 없다.
    IPv6 geo.ipv6
    IPv6 방문자는 나라·망 종류를 찾지 않고 수만 센다.

    어느 날, 어느 시간대에 오나

    이 칸 뜻
    시간 막대 hourly
    막대 하나가 이 브라우저 시간대의 한 시간이고, 회색은 사람 모양 페이지·그 안의 진한 막대는 스크립트가 돈 페이지·빨강은 5xx 다. 대시보드 재접속 실패 수는 막대에 마우스를 올려야 보인다.
    날 막대 visitors.days
    한국 시각(KST) 하루마다 확인 방문자이고 진한 아랫부분은 다시 온 사람, 아래 얇은 줄은 브라우저 모양(눈금 따로)이다. 회색 덩어리는 처리방침 개정 시행 전이라 세지 않은 날이다.
    요일×시간
    칸 하나가 이 브라우저 시간대의 요일 하나·한 시간이고, 값은 스크립트가 돈 페이지 보기를 창 안에서 더한 수다(밝을수록 많다). 한국 밖 브라우저면 날 막대(KST)와 날 경계가 다르다.

    무엇을 여나

    이 칸 뜻
    많이 연 경로 paths
    사람 모양 페이지 줄의 주소(쿼리를 뗀 것). 막대·% 는 사람 모양 페이지 대비다.
    대시보드 진입 탭 tabs
    실시간 스프레드 spread · 기록/통계 history · 선물–현물 갭 gap · 선선갭 pp · 수집 상태 health · 입출금 레이더 flow. tab 이 없는 /app/ 은 spread, 목록 밖은 (기타)이고 들어온 뒤 바꾼 탭은 없다 — % 는 탭 합 대비다.
    기기와 OS·브라우저 devices·os·browsers
    User-Agent 글자로 가른 기기(휴대폰·태블릿·데스크톱)·OS·브라우저. 방문자 기준(확인 / 모양)과 페이지 줄 기준(사람 모양 페이지 대비)을 따로 접어 둔다.
    6 · 문제

    오류·연결에 문제는 없었나

    최근 5xx
    시각경로상태
    이 칸 뜻
    5xx status
    서버 오류로 답한 요청(대시보드 재접속 실패 제외) — 장애색은 이것에만 쓴다. 어느 경로였는지는 '최근 5xx' 에서 본다.
    대시보드 재접속 실패 ws5xx
    대시보드 WebSocket(/api/ws/spreads)에 5xx 로 답한 요청 — 배포 때 몇 건은 정상이다. 시간 막대에서는 막대에 마우스를 올려야 보인다.
    4xx와 탐색 4xx·probes
    4xx 는 없는 주소·잘못된 요청이고 대부분 탐색 경로 요청이다. 탐색 경로 줄은 종류와 무관하게 센다.
    대시보드 연결 ws
    끝난 연결은 창 안에서 끝난 대시보드 연결 수(사람 수가 아니다), 연결한 방문자는 그 연결을 연 방문자(날마다 셈)다. 지속 시간은 연결이 열려 있던 시간이지 머문 시간이 아니다(숨긴 탭도 열려 있다).
    Clarity 요약

    최근 1일 · UTC 기준 — Clarity 가 준 값

    받은 지표
    이 칸 뜻
    세션 sessions
    Clarity 가 센 세션 수. 화면 분석에 동의한 방문자만 든다.
    봇 세션 botSessions
    Clarity 가 봇으로 가려낸 세션 수. 세션 수에 들어 있는지는 확인하지 못했다.
    사용자 users
    Clarity 가 가른 서로 다른 사용자 수(동의한 방문자만). 가르는 규칙은 Clarity 의 것이라 사람 수와 같다고 보지 않는다.
    세션당 페이지 pagesPerSession
    Clarity 가 준 PagesPerSessionPercentage 값을 소수 2자리로 적었다. 이름에 Percentage 가 붙어 있어 평균인지 비율인지는 세션이 있는 응답을 보기 전이라 모른다.
    받은 지표
    Clarity 가 준 지표 이름·행 키를 고치지 않고 적은 것(지표마다 20행). 주소 값은 쿼리를 뗐다.
    다음 조회
    Clarity 는 하루에 부를 수 있는 횟수가 정해져 있어 적힌 간격으로만 부르고, 실패하면 마지막으로 받은 값을 그대로 둔다.

    수집기가 AWS Budgets 의 비용 예산 전부를 6시간마다 새로 읽고, 화면은 60초마다 부른다.

    이 칸 뜻
    막대

    점선
    한도 × 이번 달(UTC 달)이 지난 비율 — 한도를 고르게 썼다면 지금 있을 자리다. 막대가 점선을 넘으면 한도보다 빠르게 쓰고 있다.
    세로선
    한도의 85%·100% 자리 — 예산 알림이 나가는 기준이다.
    예측
    AWS 가 낸 이번 달 말 예상 사용액. AWS 가 하루 몇 번만 갱신하고, 한도를 넘으면 주의색이다.
    월 단위가 아닌 예산
    분기·연 예산은 막대 없이 이름·실제·한도만 적고, 개요 칸·절 요약은 월 예산만 본다.
